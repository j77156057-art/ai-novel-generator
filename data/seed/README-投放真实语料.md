# 真实语料投放区

把真人小说的 `.txt` 放进这个目录（或用 `NOVEL_DIR` 指向别处），然后跑入库脚本即可。

> **仓库里不带语料**：正文与参考书都受版权保护，语料只在本机投放，不随仓库分发。

## 为什么需要它

RAG（混合检索）每次生成都会把检索到的语料原文塞进提示词，作为"文风参考"。
原来库里只有一段 322 字的 demo 文本（随仓库不带，见上文），而那段文本本身
就带 AI 腔（段尾升华 + 旁白预告），模型在学它—— 所以 prompt 层面再怎么改
都压不住 AI 味。换成人人小说才能治本。

## 放什么

- **UTF-8 编码的 `.txt`**，UTF-8 之外的编码会解析失败
- 有分章标记最好（`第X章` / `第X节` / 纯文本也能切，但没有章节信息时
  知识图谱的「首现章 / 末现章」会退化到单一章号）
- **题材分布建议**：悬疑、科幻、都市各1 本最好。单一题材会让检索结果的
  场景/人物套路趋同，生成的新段落会带上该题材的全部陈词滥调
- 单本 5万字以上效果更稳；一两章的短篇起不到文风基底的量级

## 怎么入库

```bash
cd backend
python load_corpus.py
```

脚本会：上传全部 txt → 重建知识图谱 → 打印每本的分片数与总字数。
入库后可清掉demo 语料（见下）。

## 清掉 demo 语料

demo 文本本身带 AI 腔，留着会污染检索。入库确认没问题后：

```bash
python load_corpus.py --drop-demo
```

## 注意

- 语料只用于**文风参考检索**，不会被复述进生成正文（`prompts.py` 里的语料块
  明确要求"只借鉴文风与句式，不要照搬情节和句子"）
- 但如果语料本身是金句堆的文本，模型仍会无意识学到它的痕迹 —— 所以**选书
  比选数量重要**
