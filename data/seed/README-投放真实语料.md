# 本地语料投放区（可选）

仓库本身不带任何第三方作品文本，默认只有 `data/seed/sample_novel.txt` 那段 322 字的 demo。
如果你手上有**自己拥有合法使用权**的 `.txt` 小说，可以放到这个目录，再用入库脚本加载。
这是本地调试/自测的一种可选做法，不是产品流程里的一步。

## 为什么会有这一层

RAG（混合检索）在生成时会把检索到的语料原文塞进提示词，作为"文风参考"。
demo 文本本身带 AI 腔（段尾升华 + 旁白预告），模型会学它——所以 prompt 层面再怎么改
都压不住 AI 味。想验证「换成别的语料会怎样」时，才需要往这里放东西。

## 放什么

- **UTF-8 编码的 `.txt`**，UTF-8 之外的编码会解析失败
- 有分章标记最好（`第X章` / `第X节`；纯文本也能切，但没有章节信息时
  知识图谱的「首现章 / 末现章」会退化到单一章号）
- 题材上尽量分散，避免单一题材让检索结果的场景/人物套路趋同
- 单本 5 万字以上效果更稳；一两章的短篇起不到文风基底的量级

## 怎么入库（本地可选）

```bash
cd backend
python load_corpus.py
```

脚本会：上传全部 txt → 重建知识图谱 → 打印每本的分片数与总字数。
入库后可清掉 demo 语料（见下）。

## 清掉 demo 语料

demo 文本本身带 AI 腔，留着会污染检索。入库确认没问题后：

```bash
python load_corpus.py --drop-demo
```

## 注意

- 语料只用于**文风参考检索**，不会被复述进生成正文（`prompts.py` 里的语料块
  明确要求"只借鉴文风与句式，不要照搬情节和句子"）
- 但如果语料本身是金句堆的文本，模型仍会无意识学到它的痕迹 —— 所以**选书
  比选数量重要**
- 不要把自己没有使用权的作品提交进仓库；这个目录里的内容默认只留在本地
