## 这个系统 / What this is

长篇网文写作的难点不在「调一次 LLM」,而在**几百段之后还能不能守住同一本书的写法、不忘伏笔、不自相矛盾、前情还不把 token 撑爆**。这个系统把这些问题拆成可机检的部件:

- **文体是可蒸馏、可复用的资产** —— 一本书的写法蒸馏成一份档案,任何项目都能用;
- **前情是有界的** —— 层级摘要树保证「段 1..N 全被覆盖,没有洞」;
- **漂移是可拦截的** —— 知识图谱在生成前把角色/伏笔/进度提醒给模型;
- **助手里手不能乱写** —— agent 只提卡,任何落库都要人批。

## ✨ 能力 / Capabilities

### 📖 文体与叙事档案:一本书的写法,蒸馏一次,全局复用

- **17 维叙事档案** —— 人物描写手法 / 对白风格 / 段落编排 / 场景构建 / 情绪表达 / 节奏控制 /
  世界观呈现 / 剧情编排模式 / 角色声音词典 / 伏笔与悬念设计 / 文笔量化审计 / 节拍序列 /
  高频场景模板 / 潜台词模式 / 战斗描写 / **心理描写手法** / 语序编排。
- **21 个可机检文体特征** —— 句长均值 / 句长 CV / 句长 p90 / 短句占比 / 长句占比 / 段长 CV /
  段均句数 / 对白字占比 / 对白段占比 / 纯台词段占比 / 逗号密度 / 句号密度 / 感叹号密度 /
  问号密度 / 省略号密度 / 比喻密度 / 情绪直陈密度 / 段尾升华率 / 四字格密度 / 短串占比 /
  虚词密度。档案里每一个数都能复算。
- **三档蒸馏**(完整 / 平衡 / 快速),落在**全局共享、幂等**的库里 —— 不按项目重复蒸馏。
- **注入取法是设计过的**:只在**成熟期**章节里挑、均匀取**不同的章**、每章取最早追加的那条。
  早期章节文风没稳定,拿开篇代表全书是错的。
- **进度按六个阶段走**(准备 / 采样 / 提炼 / 声音 / 二次提炼 / 汇总),不是一根假进度条:
  运行中封顶 99%,收尾才 100%;参考语料的图谱在**保存语料时**后台建,不再卡住蒸馏的开头。

### 🧠 有界前情:层级摘要树 + 覆盖不变量

- 三层结构:**段 → 卷 → 主线**,`compose_prior` 按预算裁剪。
- 它**永远报告 `uncovered`**(应恒为 `[]`):前情块必须连续覆盖段 `1..N` 且无洞。
- **覆盖声明写在文本里**,不只存在报告里 —— 外部核对器只读 prompt 文本就能算出有没有洞,
  不必相信模块自报的结果。

### 🔎 检索与知识图谱防漂移

- **混合检索**:纯 Python BM25 × 向量 embedding,**RRF** 融合。
- **知识图谱 v3**:实体 / 事件 / 关系 / 关系演化 / 伏笔 / 角色状态 / 知识条目 / 时间线因果链。
  段落提交后由后台 worker **用模型抽取**(异步批抽,零阻塞),落进 9 张 v3 表,
  再经【世界观事实】块回流进下一段的提示词。
  抽取伏笔时会把**账上已有的伏笔名**一起给模型并要求**同名复用** ——
  否则每抽一轮同一件事就多一个说法,账本无界长(实测 9 段正文攒出 117 个名字;
  同样 6 段重抽一遍,旧做法又长 21 个名字,新做法只长 3 个)。
  **抽取统计如实分账**:模型吐出几条 / 同名复用几条 / 批内重复几条 / 新增几条 /
  近似变体几条,分开记(近似变体 = 新名与账上某条老名字高度相似,阈值 0.50,
  是量出来的;只计数+留痕,不改账本)。
- **生成前提醒**(reminders)把「这个角色是谁」「这条伏笔还没收」「剧情走到哪」喂给模型,
  再叠加**用户自己写的 plot-bible**(故事权威),两边在**同一处合并**后使用两次:
  静态 system 层 + 靠近末尾的 user 提醒。

### 🎭 角色对话:让书里的人按自己的记忆开口

- **每段证据带来源标注** ——「他亲历」「他在场听到」还是「**只是被提到**」由服务端判:
  文里写到他**不等于**他在场(第三档就是为这条加的),认不出他开口就往保守那档判
  (宁可漏判不要误判:误判会让角色知道不该知道的秘密)。
- **只知道他知道到此刻为止的事** —— 与续写共用同一条 fail-closed 边界,章节边界之外的内容不进入提示词。
- **没有依据就直说不知道** —— 检索不到支撑时不允许编,回答里带不上的东西就明说。
- **角色档案来自蒸馏结果** —— 生平时间线 + 说话方式 + 他依据的原文,三块拼成这个角色的 system 层。
- **清单里个个是人** —— 项目角色取自归一化后的实体表(不是抽取器的原始产物,
  后者会把「水下」「边缘」也当成角色);别名折叠显示,不单独占一格。
- **答自己的性格用第一人称** —— 证据块说清「这是书里的片段,不是你的传记」,
  并列出**他亲口说过的话**;模型据此用自己的话回答,不写「XX么」这种人物小传
  (实测:同一个问题,修前 175 字第三人称还顺带评价了别人,修后 73 字第一人称)。
- **换角色就换一段对话** —— 问答按角色分组,界面上永远只显示你正在跟谁说话的那一段。
- **后台任务被杀也不会一直「在跑」** —— 服务重启后,没跑完的批抽作业会被收成「已中断」
  (可一键重捞),不会留下一堆永远转圈的 running 行。
- **他只知道到「故事进行到第几章」为止** —— 检索与生平时间线都按那个边界裁,
  没设边界的书**整本挡掉**(fail closed);证据取不到时**不让他编** ——
  实测:同一个问题,边界第 300 章时他引用第 290~295 章的原话,
  边界第 1 章时他直说「说不上来」(而不是用训练里的世界知识糊弄你)。

### 🧪 提示词细化:把「像一点」变成可核对的数字

- **基线给区间而不是单点** —— 与 `band_check()` 同源(p10~p90);比例型/稀疏型指标**只给均值**
  (长尾分布上给区间等于没给)。
- **要求带例句** —— 例句过**两道闸**:脱敏(专名表拦截)+ PMI 候选兜底(表外漏网),
  候选集按书缓存进专名表;实测 28 条例句**零泄漏**。
- **提示词标签化** —— 每一块注入都带标签,模型知道哪块是约束、哪块是材料。
- **提示词里的噪声也治** —— 把真实提示词导出成文本**按块量**,再决定改哪块:
  实体 context 压成**一句完整的话**(窗口从正文中间截开 ⇒ 原本 20 条里只有 1 条
  以句末标点收尾,修完带 context 的 17 条**全是完整句**;重复片段只留一处)、
  KG 抽来的**对话碎片伏笔**不进约束块(19 → 5 条;**用户在剧情圣经里写的伏笔一个字不动**)、
  空关系**整条不列**(字面量 `None` 归零)。判据一律「宁可放过,不可误杀」。

### 🩺 文风档案检查:说清楚为什么挡,并能当场改

- **按语法角色判,不是「字串出现过就算」** —— 档案的规则正文如果写了禁用清单里的转折词,
  提示词检查会判「档案自相矛盾」并**挡住生成**。纯子串命中会把
  「场景常先以人物当**下一刻**的细微反应切入」这类名词性用法误判成转折连词
  (实测蒸馏库 4 份档案 2 份命中、验收库 2/2 项目命中,真档案几乎必然被挡),
  所以判据必须分语法角色:连词用法挡住,名词性用法降为提醒(不挡生成,但照样报出来)。
- **冲突能当场修** —— 项目工作台里点「检查文风档案」,列出冲突所在的维度与规则原文,
  两个动作直接改:「去掉这个词」/「删掉这条规则」。改的是**本项目在用的档案**,
  **不动全局蒸馏库**(那是共享的);改动留痕(改前的原文记在档案里,可回退),
  改完由后端重跑一次检查,当场自证。
- **证据引文一个字不动** —— 规则尾部的「（证据：语料原句）」渲染前会被剥掉,
  只出现在证据里的词模型根本看不见 ⇒ 修档案不碰它(否则是把语料原句改坏)。

### 🧬 语料体检:认出盗版站拼进来的别的书

- **一句话** —— 盗版站的「单本下载」经常把**好几本书拼进一个 txt**。
  体检会认出「哪几章来自另一本书」,并给出证据(独占词 + 原文样本 + 字数),
  人点头才剔。**默认只报不删**:删的是整章正文,判据万一错了丢的是真内容。
- **判据不是「像不像本文风」** —— 第一版用风格离群(与全书中心的相似度),
  在一部现代都市网文上标出 60 段,**逐段核验全是误报**:那些段只是文风跳脱,
  用的是本书的人。真正的判据是**人物聚集度 + 排他性**:
  混进来的书有一群**只在这一小片里活动的人**(人名在全书别处不出现、总在相邻几章),
  本书的人物则铺满全书。
- **实测** —— 18 本真实网文(7900 万字)全扫:命中 1 本(3 段 / 21.8 万字 / 5.44%),
  其余 17 本**零误报**;剔除后外书人名 1,136 → 0 次,本书人名 14,242 → 14,242 次
  (一字不少)。**外书的章是夹在本书的章之间的**,所以按「命中的连续章」切段删,
  不按首尾跨度整段删(否则会连带删掉 16.8 万字本书正文)。
- **接在哪儿** —— 投放时的**待确认卡**上直接写出「混进了几段别的书、独占词是哪些、
  占了多大比例」,并给一个**默认不勾**的「剔除这几段」勾选框;
  入库后语料页的「入库体检」块给出同样结论并说明是否已剔除;
  审核面板(`foreign_book_blocks` 规则)也看得见。剔除是投放时的一个显式开关,
  默认关闭 —— 检测照做,删不删由人点。

### 📇 角色档案:让「这个角色是谁」真的进到提示词里

- **证据回填** —— 字段级事实核验:从「有他出场的行」里定位 n-gram 命中,给老档案补上合规证据
  (实测 32/32 命中),不用放宽门禁。
- **生平时间线** —— 完整句 / 引号配对 / 名字不在引号里,还原「他经历过什么」。
- **限长 400 字/角色**,原文摘录插在「说话」块之后(放最后会被限长截掉)。

### 🎭 角色个性:自己定这个人该怎么表现,AI 帮着补

- **四栏手写** —— 他怎么说话 / 他会怎么做 / 他不会做什么 / 决定他现在状态的事。
  写在**生成之前**就能改,写完直接进生成提示词(没有个性描述时,提示词逐字节不变)。
- **AI 只补不改** —— 点「AI 帮我完善」,模型**只输出补充**,给的是建议不是结果:
  采纳与否由人点;采纳时**追加在你写的后面**,不覆盖你的原文,重复的那几条自动去掉。
- **三种来源,人写的永远优先** —— 合成剧情圣经时给的是想象版,从已写正文里反推的是实测版,
  你手写的标成「你写的」:后两者都不会覆盖你写的,界面上也标得出来。
- **真跑对过** —— 顾星河(手写「句子短、从不解释」)、伊芙琳(短答、只陈结果)、
  陆沉舟(先问再推测、用词偏档案记录)同场说话:全段 70 句台词 **0 个感叹号**,
  顾星河台词均长 5.1 字、最长 10 字(只给结论,不解释)。

### 🎴 角色卡:武器、功法、能力与说话方式

- **四组字段** —— 身份 / 能力 / 声纹 / 关系。能力栏**同时写上限**:
  「做不到什么」比「能做什么」更能防止模型把角色写飘。
- **声纹是可执行锚点,不是形容词** —— 句长档位(闭集 极短/短/中/长)、
  句末习惯(闭集 6 选 1)、自称、语气底色、口头禅。
  「沉稳寡言」这种形容词**没用**:实测写了 persona 的项目角色反而更像
  (平均两两距离 0.230 vs 0.399),五个角色的台词均长全挤在 7~8 字。
- **成批生成互相避让** —— 生成一批新角色时把已有声纹喂给模型让它避开;
  生成后再检测「相同锚点 ≥ 3 项」判撞,撞了带冲突回灌重写。
  实测整批六对角色**全部 0 项相同**,句长四档全铺开(我/老身/下官/六)。
  「都自称『我』」**不算撞**。
- **台词归属宁缺勿错** —— 一行里出现 ≥2 个角色名 ⇒ **整行不要**
  (旁白与别人的话不能算给他)。

### 🌍 世界设定:这个世界长什么样,开书前就写定

- **三样东西** —— 一句话世界 / 硬规则(世界不可违背的约束)/ 已知势力与地点。
  没有它,模型每段自己现编一套世界观,城名、规则、势力各写各的,跨段必然漂移。
- **设定与走向分两条通道** —— 剧情走向(梗概、后续走向)在分章模式下会被剔掉,
  免得第一段就奔结局;**世界设定不含走向,始终保留**,每一段都带着它写。
- **不按句子切,按职责分流** —— 「小说大概内容」是世界设定与走向混在一起的自由文本,
  在提示词里逐句切既脆弱又会静默丢内容。改成**合成剧情圣经时分流一次**:
  模型另外产出一份世界设定,往后走向走走向通道、设定走设定通道。
- **AI 只给建议** —— 点「AI 帮我补全」,模型写一份**不落库**的建议,满意再「填入」,
  自己改完点保存。
- **实测:设定确实被听见,规则确实压得住** —— 同一场景同一模型,只差一个背景块:
  设定里的要素出现率 **0/3 → 3/3**(没有背景时模型是每次现编一个世界);
  背景里故意写错的信息(「货币是金币」),有禁止规则时 **0/8** 次漏进正文,
  去掉那条规则就 **4/8** 次漏进去(有阳性对照,不是模型本来就不写)。
  跑的是 opencode Go 订阅通道的 `deepseek-v4.1-flash`,
  只说明「指令被听见」这层,不代表成稿质量。
- **没写这一块时,提示词逐字节不变** —— 老项目不受影响。

### ⚔️ 修炼体系与量级:境界怎么分、谁压谁

- **体系三型,正交于档位** —— 体系类型是**纵向精细度**(细分型 / 序列型 / 粗放型),
  档位是**横向群像分层**。「路人甲只记档位、不逐个建档」这条规矩靠档位落地。
- **粗放型不能假设等差** —— 凡人→修行者→圣人→神明,后一阶可能差距**更小**;
  序数不可比,只能用量级比(`realm_rank` 对粗放型返回 `None`)。
- **量级是相对标尺,不是 DPS** —— 五档(凡人/伤人/毁物/毁城/灭世)+ 一句具体的
  「出手规模」+「他压得住什么、压不住什么」。判据是**能造成什么后果**。
- **只给同场的人,且成对比较** —— 提示词里只出现在场角色,并直接说清谁压谁。
  没有量级数据 ⇒ 提示词**逐字节不变**。
- **真机 A/B 有效** —— 同一世界观同一场景,只差一个量级块:
  高量级动作(沉进/化成/倒卷/退开/往上提)A 组 **0 次** → B 组 **7 次**;
  B 组自发写出「她能烧我一里,我就退一里。可她站的地方,只有一里」。
- **体系类型可以先定下来** —— 生成时选「细分型 / 序列型 / 粗放型」(或交给 AI 定);
  选定了,AI 给的类型对不上会**带着原因**让它重做。
  类型以前一直是**模型自己说的**:实测要「粗放型」时它给了一套细分阶梯并自判「细分型」。
- **结果有闸门,失败说清原因** —— **解析成功 ≠ 内容对**:同名境界(层级被摊平了)、
  名字带表头前缀(「列：见隙」)、境界多到 90 个、类型不符 —— 命中任一条就**带原因重试**一次;
  还不合格就如实说「认不出是一套体系」,并把**模型回的内容**摆出来给人看。
- **AI 只建议,不落库** —— 体系、档位、量级都由人点采纳。

### 💭 心理描写:不是提示词缺要求,是蒸馏教了「不写心理」

- **取证** —— 生成文本里直陈心理 **1.03** 处/千字,参考书 **3.06**;更精确地说,
  生成把心理换成了**身体反应**(身体反应 3.10 vs 参考书 0.46,多 6.7 倍)。
- **根因在蒸馏** —— 蒸出的「人物描写手法」规则是「用动作暗示心理,**不直接写**内心独白」,
  它有原文证据、过了证据闸门,于是被当成「作者的手法」注入。
  但真书作者**两种都写**(直陈 : 身体 ≈ 6.7 : 1)⇒ **蒸馏把一半当成了全部**。
- **治根** —— 蒸馏新增第 17 维「心理描写手法」,要求**并存的两面**并给出占比;
- **治表** —— 提示词给可执行指引(5 种心理模式 + 4 种场景模式,每条带真书范例),
  频次「每 2~3 段一处」(实测 1.79 → 8.18;参考书 3.06,偏高部分靠字数约束兜住)。
- **边界写清** —— 「禁止情绪直陈」禁的是**形容词贴标签**(「眼神里露出悲凉」),
  **不禁**具体的心理活动(他在盘算什么、想起了谁)。这两条必须一起给,否则模型
  会把禁令理解成「不许写内心」。

### 🛡 三条写作路径与可见性边界

| 路径 | 参考书怎么用 | 边界 |
|---|---|---|
| **只学写法**(原创) | 整本可作**写法材料**(只取写法,不取专名) | 用户显式设的原文边界永远优先 |
| **接着这本书写**(续写) | 只有边界以内的章节 | **fail closed**:没设边界 ⇒ 整本挡掉(防剧透) |
| **角色聊天** | 角色声音词典 + **检索他出场的原文片段** | 只用**他出场**的片段;每段标注「他亲历 / 他在场听到」;章节边界同样 fail-closed(他只知道到那一章为止) |

界面上是**三个板块**,不是一个可选输入框 —— 三套可见性规则,猜错了就是剧透或白白挡住素材。
「读到第 N 章」的边界直接写在参考语料下面。

> **角色聊天确实会读参考书原文**,只是读法与续写不同:
> 续写把边界内的章节当**写作材料**(整体学它的写法),
> 角色聊天只取**他本人出场**的片段,并且逐段标注来源 ——
> 所以他能演出「这事我是听说的」,而不是把别人当着他面说的话当成自己的记忆。
> 真跑发现:不这么做的话,问他一件他不知道的事,他会**编得像模像样**。

### ✍️ 写作工序链

`生成 → 段长闸门 → 场景契约审计 → 去重 → AI 味重写 → 文风改写 → 形态校正 → 摘要/KG → 落库`

- **段长闸门**:长度不再是提示里的一句「软希望」。量的是**汉字**,不够就**回灌让模型扩写**
  (有界),仍不到下限就照写但**如实标注未达标**。
  (开了候选池时,闸门在**池内**跑 —— 即打分之前 —— 所以它不会再换掉被择优认可的稿子。)
  **同步、界面(流式)、重生成三条路径用的是同一把尺**;
  流式路径为此改成了「先生成、过闸门、再分块吐出」——
  代价是**首字延迟从秒级变成整段生成的时长**,换来的是界面落库的段长与接口一致。
- **形态校正**:把「一行一句台词」掰成「叙述 + 台词同段」。**机械版**默认开 ——
  零模型调用、100% 可复现、**一个字都不新增**(唯一的例外:并接处把句号改成冒号,
  以对齐参考书的混合段形态);**模型改写版**默认关(实测不可靠)。
  机械版走**最大匹配**(纯叙述段 ↔ 裸台词段,含向后并),实测 9 段真实正文
  纯台词段占比 **71.5% → 42.2%**;**引导语补写**(再给裸台词段补一句动作/神态,
  **默认开、按需触发**)能再拉到 **20.9%~21.5%**(多轮真跑)—— 进了参考书的分布带。
  引导语多一道**说话人一致**判据:模型自报说话人,服务端拿它跟**本段归属语**、
  **引导语自己的主语**比对,判得死才拒。
- **候选池**(Best-of-N / 阈值式拒绝采样,默认关):同一提示采多份,**每份走完整条链之后**
  再用**同一把尺**量**成品**,落库**第一份合格的** ⇒ 「池选中 == 落库」。
- **局部补写**(beat,默认关):在连续对白段开头并进一句动作叙述,逐段验收。

#### 🔬 对白形态的两个开关(候选池默认关;引导语补写**默认开**)

**候选池**与**引导语补写**都只在 `backend/.env` 里配 —— **刻意不做进界面**:
开关旁边没法写清它要花多少钱。

| 开关 | 默认 | 代价(真跑量过) |
|---|---|---|
| 候选池 | 关(`STYLE_CANDIDATE_POOL=1`;`3`=开) | 采样与走链**交替**:采一份、走一条链、量一次成品,合格就停。真跑(生产通道,N=3):第一份就合格 **126.7 秒 / 2 次模型调用**;三份都不合格 **318.6 秒 / 48 次 / 3 条链** ⇒ 最坏 ≈ 17 倍。段长闸门在池内跑,每份候选都付一次。 |
| 引导语补写 | **开**(`STYLE_LEAD_IN=true`) | **按需触发**后每段 **5.6 次**模型调用(补到均值要 11.7 次),约十几秒;它**会新增文字**,所以判据比机械合并严(七道,含「说话人一致」)。 |

**为什么引导语默认开**:机械合并只改段落边界,实测只把「纯台词段占比」从
71.5% 拉到 **42.2%**,而参考书是 **22.7%** —— 关掉它,**开箱即用的产物形态永远在带外**。
真跑(真实正文 + **生产通道** + 生产代码):7 段里触发的 **5 段全部进带**
(形态 `0.468→0.290`、`0.450→0.300`、`0.456→0.294`、`0.407→0.296`、`0.365→0.288`,
带上沿 0.335),采纳率 **100%**,整批 41 次调用 / **33 秒**。

「按需」是三个条件,每一个都有实测依据:

1. **只在裸台词多于带上沿 `p90` 时才付钱** —— 低于下沿 `p10` 时补写只会把比值压得更低、离带更远;
2. **补到上沿就停**,不追均值 —— 目标是「进带」,不是「打到平均」;
3. **余量 2 处 + 还差就再来一轮** —— 采纳率是**模型与通道共同决定的**
   (实测 67%~100%),写死一个余量只能赌某个模型;所以补一轮、量一次,不够再补一轮。

⇒ 代价 **11.7 → 5.6 次/段(-52%)**（按全部段平均；真正触发的段约 7.8 次）。

**候选池仍然默认关**,而且默认关是对的:它多花的是**一整条链**(一次真跑 17 倍耗时),
而收益是「开了池时,落库的那份一定是尺子判过的」——
默认路径本来就有形态校正与引导语补写兜底,不需要为它付这个钱。
**要开就开在真需要它的地方**:默认写手之外的模型(实测 Flash 经机械校正后
4/4 候选已进带,收益只剩「离分布中心更近」)。

### 🤖 助理 agent:只提卡,不落库

这是本项目的**硬边界**:agent 的工具箱里,所有会改数据的能力都是**提案**,不是写入。

- **28 个工具,全部 `read_only=True`** —— 注册时**硬拒**非只读工具与黑名单前缀名
  (`write_` / `commit_` / `update_` / `delete_` / `patch_` / `rollback_` / `apply_proposal`)。
  要改数据只有一条路:`propose_action` / `propose_text_edit` / `propose_text_fix`
  —— 三个都**只构造待确认卡**,不落库、不执行。
- **提案 → 批准 → 落库 / 回滚**;每次落库留**版本快照**,可 diff、可恢复。
- **提示词运行时覆写是真的接进生成路径的**:批准后,覆写文本会被追加进系统/用户提示词
  (风格块之后 / 续写纪律之后 / 并进续写指令段),三条生成路径 + 预检页 + 提示词体检读的是同一份。
  没设覆写时,提示词与接线前**逐字节相同**(用黄金哈希钉住)。覆写**只能加不能减** ——
  默认块里的角色锁定与伏笔纪律删不掉。
- **11 步工作流**:语料就位 → 清洗抽检 → 文风蒸馏 → 档案审查 → 提示词体检 → 写正文 →
  正文审查 → 修复待批 → 派生重建 → 解锁放行 → 收敛。
- **确定性诊断规则**(零模型调用):句长偏离、对白形态偏离、标点事故、外来拉丁字母、
  角色名冲突、伏笔堆积、死角色复现…… 每条 issue 带**可复核的证据**(原文 + 定位)。
  agent 看到 issue 后用 `from_issue` 起草改写,**证据由服务端带进提案**,模型不抄。
- **需要模型判的那类**(如正文内的事实矛盾)走**同一个 issue 契约** —— 证据照样由服务端给,
  agent 的改写草稿照样要过提案闸门。

### 🔌 多渠道模型与角色隔离

- `ProviderRegistry` **两轨**:Writer 与 Assistant 各自独立的模型配置,并发隔离。
- **timeout 真正生效** —— 每个渠道分支都把 `timeout` 传到底层调用(基类默认 120 秒)。
- 写手模型、辅助模型、嵌入模型各自可配;空 key ⇒ 本地确定性兜底。

## 🧭 架构 / Architecture

```mermaid
flowchart TD
    Corpus[语料 Corpus · txt] -->|UTF-8 解析 + 自动分章| Chunks[叙事切分 Chunks]
    Chunks -->|BM25 + 向量 embedding| Store[(PG + pgvector · SQLite)]
    Chunks -->|规则抽取 角色/坑/关系| KG[(知识图谱 KG)]
    Corpus -->|文风蒸馏 三档| Lib[(全局蒸馏库 StyleDistill)]
    KG -->|生成前提醒 reminders| Gen[分段生成环 Generation Loop]
    Store -->|RRF 融合召回 + 原文边界| Gen
    Lib -->|档案 + 规则 + 写法样例| Gen
    Gen -->|段级总结| Tree[层级摘要树 Summary Tree]
    Tree -->|有界前情 compose_prior + 覆盖证明| Gen
    Gen -->|Writer 续写| LLM1[Writer Model]
    Gen -->|诊断 / 提卡| AG[助理 Agent · 28 工具]
    AG -->|提案 Proposal| Gate[提案闸门 人批]
    Gate -->|批准| Gen
    Gate -->|版本快照| Ver[(Versions · diff · restore)]
```

**生成数据流**:`KG reminders` + 用户 **plot-bible** → 合并约束(唯一权威口径,用两次:
静态 system 层 + 近因 user 提醒)→ `summary_tree.compose_prior` 组装**有界前情**
(主线 / 近情 / 卷)→ RAG 上下文(含原文边界裁剪)→ LLM 写 → 段级摘要 → 写进 `generations`
并卷进摘要树(L1 → 按需 L2/L3)→ 下一段读树。

## 🔬 工程保证 / Engineering guarantees

这个项目把**证据**当交付物。下面每一条都能被第三方复算、重跑或查证:

- **可复算的量** —— 档案里的每个数都能用同一套尺子重算;口径变更会作废旧档案并重新拟合,
  而不是让两套数并存。
- **覆盖不变量自带证明** —— 覆盖声明写进前情文本本身,外部核对器只读 prompt 就能算出有没有洞,
  不必相信模块自报的 `uncovered`。
- **边界有测试钉着** —— `tests/test_assistant_readonly.py`(助理只读)、
  `tests/test_reference_boundary.py`(原文边界)、`tests/test_action_proposals.py`(提案闸门)、
  `tests/test_workflow_steps.py`(工作流)。
- **对抗性验证** —— `tests/qa4_verify_deep_attacks.py`(深度攻击)、
  `tests/qa4_verify_proposal_write_path.py`(提案写路径)、
  `tests/qa6_assistant_browser_smoke.py`(真实浏览器端到端)。
- **四轴验收能真跑** —— 离线跑(无模型,验闭环与记忆系统)与**真模型跑**(30 段,
  验文风与漂移的机器侧证据)用**同一把尺、同一份种子设定**;阈值取自真实语料的分位数,
  不是拍的。真模型跑还会产出盲评材料(题面/密封映射/记录表)与二项检验判定脚本,
  让人评那一段也能算成判定。
  **盲评包先过自检才发**:两侧同等脱敏(专名换等长占位符)、取样口径对称、
  题材/年代一致、脱敏痕迹对称、**题面级专名复查**(脱敏后再把题面读一遍,
  把还是专名的词挑出来补遮)—— 任一条不成立,工具就把这个包标成
  「不是盲评包」,**判定脚本拒绝出统计结论**(退出码 2)。
  2026-10-30 那次真跑抓到并修掉三个**单测与 CI 全绿也抓不到**的缺陷
  (每第 10 段生成必崩 / 路线规划端点参数不匹配 / 心理维度渲染未定义名)——
  这类洞只有真跑能逼出来,验收跑因此是定期要重跑的,不是一次性证据。
  真跑也量出了**文风上的硬伤**:比喻密度中位 0.30/百字,而**同题材**人类网文
  的 p90 是 0.256(19/30 段超标)。但要说清这次测的是**谁的腔**:
  那一跑的项目**没投参考语料、也没蒸馏档案** ⇒ 形态校正/文风改写/照搬闸门
  三道工序全程没启用 ⇒ 量到的是「**没有档案时模型默认腔**」。
  系统本来就有可执行的比喻上限带(会随档案进提示词),下一步是
  **投语料 + 蒸馏档案后再跑一遍**,看风格迁移到底压不压得住。
  (基线换过一次:第一版基线取的是**古风武侠**,跟产出跨代 ——
  换成现代题材后阈值全变,「句长偏齐」那个结论也被推翻了。
  详见 `docs/real-model-acceptance.md` §3.2.1。)
- **构建闸门** —— 前端要 `vue-tsc --noEmit` + `vite build` 都过;后端有真实 `uvicorn` HTTP 冒烟。
- **空白机自检** —— 仓库**已发布的那棵树**(`git archive HEAD` 导到干净目录)真跑过一遍:
  新建 venv → `pip install -r backend/requirements.txt` → `pytest tests/` 全绿 →
  照 README 复制 `.env` → 空 SQLite 起 uvicorn → `/openapi.json` 与 `/api/novels`
  真打 HTTP 200 → 前端 `npm ci && npm run build` 产出 dist
  (零 key、零配置、零手工干预)。这类复验抓出过三个真实缺陷(测试环境被全仓扫描、
  脚本式断言假绿、全局队列跨测试串味),均已修复;过程记在 `ENGINEERING.md`「发布前体检」。
- **CI** —— `.github/workflows/ci.yml`:每次 push / PR 跑**后端全量 pytest** 与
  **前端测试 + 构建**(`npm test` + `npm run build`,后者自带 `vue-tsc` 类型检查)。
  跑的就是 README「跑测试」那一节写的命令 —— 不给 CI 另写一套更严格的检查。
  **在 Linux 上绿,不只是本机绿** —— 流水线能在 Linux 上抓出本机看不见的缺陷
  (测试子进程删掉父进程的 SQLite 文件:Windows 删不掉打开中的文件,本机因此全绿)。
- **规模** —— 后端 **1,903** 项测试(`pytest tests`),前端 10 个纯逻辑测试文件(50 项)
  + 3 个组件级测试文件(27 项,vitest + jsdom),**当前全绿**。
- **文档里的数字被机器守着** —— `tests/test_readme_test_count.py`:
  README 写的用例数必须等于 `pytest` **实际收集到的**条数,且 README 里几处写法
  必须彼此一致 ⇒ 改了测试忘了改 README,这条测试就红。
- **工程纪律** —— 见 `ENGINEERING.md`:每条规矩都对应一次真实踩坑,不是口号。

## ⚖️ 边界与已知限制 / Boundaries

下面几条是**有意为之的取舍**,不是没做完的坑 —— 说清楚比藏着好:

- **提示词覆写只增不减** —— 三个追加槽能加说明,改不了代码里的维度级行为
  (那在 `PROFILE_RULES` 里);覆写也删不掉默认块里的角色锁定与伏笔纪律。
- **角色约束清单走规则抽取,世界观事实走模型批抽** —— 生成前的「角色约束 / 未填伏笔」
  清单走确定性规则抽取(v2.6 同步图);知识图谱 v3 的 **LLM 抽取**另走异步批抽
  (落 9 张表),经【世界观事实】块回流进提示词 —— 两条路并存,各司其职。
- **候选池的末端判定只判形态,不判字数** —— 判定看纯台词段占比是否落在参考书分布带内;
  长度由段长闸门负责(池内每份候选都过一遍),而落库前的文风改写会压缩 15%~25%,
  拿守恒下限去裁决链后的文本会系统性误杀;字数只如实报在 `length_ratio` 里。
  候选都不合格时仍会落库**离目标最近**的那份并标注偏离(拒绝采样的下限兜底:
  预算不确定,但保证最低质量)。
- **机械形态校正改不动本质** —— 机械版只改段落边界(不新增一个字),
  实测把「纯台词段占比」从 71.5% 拉到 42.2%(参考书 22.7%)——
  **只动边界这条路到不了目标**,剩下的差距要靠「引导语补写」
  (调模型给裸台词段补一句动作/神态,**会新增文字**,默认开、按需触发)。
  补写后实测 **20.9%~21.5%**,进了参考书的分布带。
  引导语的「指错说话人」由一道**说话人一致**判据守着:模型自报说话人,
  服务端拿它跟**本段归属语**(引号外点名的人)和**引导语自己的主语**比对,
  判得死才拒,判不准只留痕。实测 121 次候选**零冲突** ——
  也就是说这个缺陷在本批真实数据上没复现;判据是**守门**,不是「修好了」。
- **未回收伏笔块有预算上限** —— 根因在抽取层而不是渲染层:抽取时若看不到账上已有的名字,
  每抽一轮同一件事就多一个说法(实测真实账本 117 条 / 9 段正文,切片一条不落全渲染 = 2,639 字)。
  现在抽取会把**已有伏笔名单**给模型并要求**同名复用**,提示词里**只列名字**
  (回收章 97 条里 82 条是假的:0 或照抄示例的 50),
  上限 60 条当安全阀、**触发了就如实写出省略了几条**。
- **本仓库不含版权正文** —— 参考书原文与模型跑出来的验收产物被 git 忽略,
  语料只在本机投放(见 `data/seed/README-投放真实语料.md`)。
- **盲评包要「同题材的人类语料」才作数** —— 工具会自己检查:两侧是否同年代、
  版式与脱敏痕迹是否对称、**题面里还残留没遮掉的专名**、**每一题两侧是不是同题材**;
  不合格的包直接标成「不是盲评包」,**判定脚本不出统计结论**。
  七道闸门里最容易被忽略的是**题材**:实测(2026-10-31)18 题包的人类侧满篇
  「厉鬼/复苏/规则」、我们侧是都市市井,**年代闸门全绿也没抓到**(同代不同题材),
  评者读一两题就能分辨 ⇒ 现在用**模型读正文判题材**(闭集 9 类,判不出来=不算一致),
  并且**每一题两侧同题材、题与题之间题材乱着来**。
  换成跨代语料(比如古风武侠)一律作数不得 —— 那量的是年代差,不是文风差。
  多本混采时**轮转取书**(随机抽可能 5 题来自同一本 ⇒ 认出一本就等于认出大半)。
  版权正文只在本机投放,**不进仓库**;盗版站水印要**按整行**剥
  (行内正则会吃掉正文里的「最新章节」,实测削掉 7% 正文)。
- **「混进来的书」只认占比小的混入** —— 判据要求外书占全书章数 ≤ 25%
  (超过就不是「一本书里混了几章」,而是「这本书本身就是拼的」);
  混入少于 5 章的也放过去。取这组阈值是因为放宽会让候选膨胀、
  排他性验证不通过,**真阳性反而检不出来**(实测 25% ⇒ 3 段;40% ⇒ 0 段)。
  同一组阈值也意味着:**检不检出取决于混入的局部密度** ——
  把那 16 章单独截出来(20 万字、人物名出现在 16 章里)反而不报。
- **剔掉混书 ≠ 全面变好(实测过,是取舍)** —— 三臂对照(30 段 × 3 臂,只变语料):
  剔除混书后**相邻段复读明显下降**(p<0.001),但**句子更整齐了**
  (按人类基线是退步,p=0.016),**比喻密度毫无差别**(p=1.00)。
  机制也查清楚了:混书内容会经「写法参考」进提示词 —— 混臂三条样例里有一条
  (占 1/3)就是外书正文;但产物里外书人名 0 次 ⇒ **学到的是文风,不是情节**。
  ⇒ 所以界面上给的是**体检结论 + 一个默认不勾的开关**,不替人做主。
- **默认不带浏览器 UA** —— provider 的请求头只带 Authorization 与 Content-Type。
  指向走 Cloudflare 的 OpenAI 兼容端点(例如某些订阅通道)会被拦成 **403**,
  错误是「Forbidden」而不是原因。自定义请求头还没做,这是已知边界。
