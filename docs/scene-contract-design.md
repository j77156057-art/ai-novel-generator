# Scene Contract 与局部文风修复

## 目标

解决真实生成中「对白段过密、问句过密、连续堆叠新谜面」的问题，同时保持跨题材通用性。约束必须随当前场景变化，不能把所有小说压成一个固定对白比例。

## 方案

### Scene contract

生成前由已有上下文确定性组装当前段契约，包含：

- 本节目标与当前场景类型
- 上节场景摘要
- 当前可见角色
- 本节必须推进的一个状态变化
- 本节不提前揭示的内容
- 对白/问句/新悬念的软预算

契约只进入 user prompt，不写入正文，不使用题材专名词表。

### 三项审计

对生成正文计算：

- `dialogue_density`：引号内字符占比
- `question_density`：问号每千字数量
- `mystery_stack`：命中揭示/疑问词的段落数，是词面代理指标，不是真实新谜面数量。

预算来自当前检索片段，按生成长度归一揭示词计数；少于两个有效样本时不判违规。当前尚未实现按场景类型及阶段分组的参考分布，不能声称已完成同场景校准。悬疑代理指标只能提示，不能据此判定人物/事件事实错误。

实验开关 `SCENE_CONTRACT_ENABLED=1` 才启用契约、L2 关系裁剪和局部修复；未开启时保留旧生成行为。未获真实质量证据前不默认启用。

### 局部修复

审计发现问题时，不重写全文。把违规段落、问题类型、必须保留事实和不可改变的结尾交给修复模型：

- 只修改指定段落
- 保留角色、事实、事件顺序
- 不增加新人物、新地点、新谜面
- 修复后拼回原文

修复失败或返回长度异常时保留初稿。

### L2 裁剪

续写只注入当前上下文命中的、且已有 L2 档案的角色；角色聊天只注入被扮演角色。每个角色只渲染与当前角色关系相关的关系项，续写最多 3 个角色，角色聊天最多 1 个。

## 验收

- 单测覆盖契约、三个审计指标、局部段落定位、L2 裁剪。
- 真实 M3 做 5 次旧链路与新链路对比，记录正文、指标、修复次数和人工质量结论。
- 不先调整全局风格 prompt；只有新链路在 5 次真实 A/B 中稳定改善后，才决定是否改风格提示。
