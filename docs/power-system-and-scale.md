# 修炼体系、量级标尺与「谁压谁」（2026-10-29）

## 一、用户诉求

> 「如果涉及到武侠的，或者是修仙的，还有其他乱七八糟的修炼体系的，
> 那么这个要不要做去角色卡，那么主角目前的境界，以后的境界，
> 还有中途的修炼等级，还有其他各式各样配角和路人甲的等级，
> 放进去以后**为了他们的境界会提示成什么样**，提升的慢还是快，
> 慢的话会不会被其他人嘲笑，快的话会不会被赞扬，
> 角色有什么修炼天赋，比如说什么体质，或者灵根，
> 或者是修炼**遇到了叉**，掉了境界，或者**为了活命，燃烧了寿命**，
> 或者是去了什么**洞府**得到了提升这种**动态的路线**，怎么规划」

> 「世界观里有神明……这种高纬度生物，举手投足可以破坏一个城市甚至一个星球
> 那种角色的感觉，但生成出来的就和**路边混混斗殴**一样，
> 角色统一干扁的发言，千篇一律的短字，打架毫无张力，
> boss 拿着个刀打，男女主能被个门挡住，看起来就是普通的街头干架」

> 「顺便给境界卡加一个档位吧……类似修仙的那种什么什么境界，第几重，
> 什么初期，中期，大圆满，**这种算第一类**，
> 然后是相对没这么清晰的，类似诡秘之主那种没有细分那么清楚的，**算第二档**，
> 再然后是那种境界基本没划定的，类似从凡人再到什么修行者，再到什么圣人，
> 再到什么神明这一类的，境界划分模糊，**可能每一个阶段差距很大，
> 也可能每一个档位差距很小**」

## 二、取证：问题出在哪

### 2.1 现有通路只有「有序词表」，没有「量级」

项目里已有 `plot_bible["realm_order"]`（有序阶梯词表）+ sentinel 的**境界倒退**检测
（`app/kg/sentinel.py`）。量了发布版冒烟库三个项目：

**能做**：判断「写低了没有」（有跌落事件才判；不同量纲一律不判）。

**缺的**（= 用户要的）：

| 缺的 | 现在为什么不行 |
|---|---|
| 体系可配 | `REALM_SYSTEMS` 是**硬编码的 3 套**（修仙档位/品阶/星级）；用户自己的体系只能塞进 `realm_order`，而那只有「有序词表」，没小境界、没档位、没含义 |
| 小境界 | `realm_order` 是**一维**的，`炼气三层` 只能塞成独立词条 ⇒ 「三层→四层」不算升级 |
| 档位（分层群像） | 没有分层机制，路人只能一个个建档（实测 38 个 character 实体） |
| 修炼等级/天赋/瓶颈/掉境原因 | 完全没有 |
| 谁压谁 | 没有 |

### 2.2 ⚠️ 关键发现：「身份描述」不等于「量级」

量了三个项目的**真实提示词**（角色约束块 = 模型真正看到的东西）：

| 项目 | 角色约束块长度 | 「这一击能有多大」类信号词 |
|---|---|---|
| 1 | 81 字 | **0 次** |
| 2 | 35 字 | **0 次** |
| 5 | 1930 字 | **0 次** |

project 5 的 1930 字里写满了「失落神女」「窃取太阳权柄的旧神阵营首领」
「弑神之战」——**全是身份描述词，没有一个字说明他出手是什么规模**。

⇒ 模型只能按它**最熟悉的物理尺度**去写（刀/门板/石阶）。
于是「旧神的一击」写成了「黑刃骤然穿过木门」。

肉眼看真实打斗段落（雾海之影 151 段）也印证：沉日者与顾星河的全程交锋
都是「黑刃穿过木门」「短刃抵住门板」——**神明之战变成门板之争**。

## 三、设计

### 3.1 三个正交维度（最容易搞混的地方）

| 维度 | 是什么 | 例子 |
|---|---|---|
| **体系类型** | **纵向**：这套体系**怎么分**（边界有多硬） | 细分型 / 序列型 / 粗放型 |
| **档位（band）** | **横向**：群像怎么分层（路人按层归类） | 入门 / 小成 / 登堂 |
| **量级（scale）** | **绝对**：他出手能造成什么后果 | 凡人级 / 毁城级 / 灭世级 |

⚠️ 「第一类/第二类/第三类」说的是**体系类型**（纵向），不是档位。

### 3.2 三类体系（用户给的三档）

| 类型 | 边界 | 典型 | 序数能不能比高低 |
|---|---|---|---|
| **细分型** | **硬**：明确列出，常有初期/中期/大圆满、第几重 | 炼气→筑基→金丹，每境九层 | ✅ 能 |
| **序列型** | **较硬**：明确列出但**不细分** | 诡秘 22 条序列 | ✅ 能 |
| **粗放型** | **软**：只有大阶段，阶段差距**可能很大也可能很小** | 凡人→修行者→圣人→神明 | ❌ **不能** |

⇒ **粗放型不能假设等差**：模型看到「圣人」会默认压过「修行者」很多，
但设定里可能不是。⇒ 粗放型**只能用「量级」比强弱**，不能用境界序数。

真机实测（粗放型那次模型自己讲清楚了）：

> 「四阶不是四层楼，而是四种『与世界立约』的方式。
> **阶段只决定权限类型，不决定战力倍数。**
> 同阶上下限可以极大，跨阶也可能被克制、被暗算、被条款锁死。」

### 3.3 量级标尺：解决「神明之战像街头斗殴」

五档固定（跨体系通用，不预设武侠还是修仙）：
`凡人级 / 伤人级 / 毁物级 / 毁城级 / 灭世级`

每档配一句**尺度锚点**（进提示词给模型当物理参照），
每个角色再给一句**具体的「出手规模」**（如「抬手能让半座雾港沉进海里」）。

#### A/B 对照（真实模型，同世界观同场景，只差一个量级块）

| | 高量级动作 |
|---|---|
| A（现状） | **0 次** |
| B（带量级对照） | **7 次**（沉进/化成/倒卷/退开/往上提…） |

B 组原文：

> 沉日者站在阶下。他没踩台阶——**那几级台阶自己沉进雾里**，像纸被水泡软。
> 更远处**海水倒卷**，哗啦一声撞碎灯塔最底下的两层石阶。
> 他没抬手，只往前迈了一步。**脚底石阶化成水，又凝回来**。

且 B 组自发写出**量级差进了对话**：

> 「你掌里那一点，能烧空我一里雾。再远呢？」
> 「她能烧我一里，我就退一里。可她站的地方，只有一里。」

#### 提示词里的样子

```
【量级对照（本场）】
· 沉日者＝灭城级：抬手能让半座雾港沉进海里
· 顾星河＝毁物级：能压住一盏不灭的火
· 白烬＝凡人级：被黑刃擦到就会散成灰
⇒ 顾星河远强于白烬；若顾星河出手，白烬挡不住
（写打斗时，出手的规模按各自量级来：不要让低量级的角色挡下高量级的一击，
  也不要把高量级的交锋写成贴身短刃。）
```

**只给本段在场的人**（其余角色的量级对这场戏没用，只占地方），
**成对比较**（模型最需要的不是「每个人多强」，而是「这两个打起来谁赢」）。

### 3.4 分层群像：路人只记档位

实测 38 个 character 实体，逐个记境界成本高，
而**绝大多数角色的境界在正文里根本不会被提及**。
⇒ 只给「档位层」（如「筑基期散修」「入门弟子」），
主角与主要配角才逐个精确记境界。

### 3.5 路线规划：AI 只建议

用户问的「修炼路线」（卡在哪、掉境界、燃烧寿命、洞府机缘）由 AI 规划，
但**只返回建议，人点采纳才写进档案**（与 persona / 角色卡同一条纪律）。

### 3.6 「处境」推导：纯规则，不问模型

用户问的「提升慢会怎样、快会怎样」——
只给**倾向**（谁压谁、卡在哪、付过什么代价），不给具体台词：

```
强于路人（凡人级）；卡在瓶颈，旁人容易议论或催逼；已经付出过代价，身体会先垮
```

## 四、真机跑出来的坑（都是真实模型才暴露的）

### 4.1 模型常回 **Markdown 表格**，不是 JSON

实测表头：`境/江湖切口/本质/常人耗时/江湖位置`、`关/关名/练什么/过关标志`、
`程次/名目/核心火候/验法`、`阶段/契约对象/力量来源/强项/死穴/内部跨度`。

⇒ 解析要**兼容表格**，而且：
- 列名别名是**无穷的**（名目/关口/名号/程次/品级…）⇒ 按**位置推断**兜底；
- 说明列常是**好几列**（契约对象/力量来源/强项/死穴）⇒ 要**拼起来**；
- 档位列可能被填成**境界名**（阶段名）⇒ 认出来就不当档位用。

### 4.2 模型把「江湖位置/阶段」填进档位

⇒ 档位不成「档」了（每境一个不同的长句）。
⇒ **代码侧兜底**：档位过多或太长 ⇒ 按境界顺序**归纳**成少数几档
（`入门/小成/登堂/一方/顶尖`），位置描述并进「说明」。

### 4.3 粗放型**必须靠内容推断**

模型回 Markdown 时**常常不带「类型」字段** ⇒ 默认成「序列型」是错的。
⇒ 推断规则：有「内部跨度」列 / 境界名全是「凡人·修行者·圣人·神明」这类
/ 正文出现「不细分·边界模糊·不一定均匀」⇒ 粗放型。

### 4.4 ⚠️ **量纲看体系，不看档位**（概念混淆）

之前用「档位」当量纲标签：
    量纲 = f"realm:{档位}"
⇒ 同一体系里「低（初入）」与「高（登堂）」被判成**不同量纲** ⇒ 不可比
⇒ **「谁压谁」永远出不来**（实测三种体系类型比较全返回 None）。

⇒ **档位是横向分层**（同体系里多个境界可以落在同一档：炼气与筑基可能都算「初入」），
**量纲 = 体系**（跨体系才不可比）。

### 4.5 思考型模型偶尔不吐 JSON

同一个 prompt，这次返回 4 个角色的合法 JSON，下次返回一句寒暄
（「Hi! It looks like your message came through empty」）。
⇒ 解析不出内容**必须重试**（`PARSE_RETRY=2`），不能当成「功能不可用」。

## 五、验收项

1. 体系可配：体系 → 境界 → 小境界，每层带说明与档位；
2. 三类体系（细分/序列/粗放）语义正确：
   细分型有小境界、序列/粗放型没有；
   细分型与序列型**序数可比**、粗放型**不可比**；
3. 量级五档固定、档位名认不出来就丢掉（横向比较要用同一把尺）；
4. 分层群像：档位层里用了体系里没有的档位 ⇒ 那层丢掉；
5. 量级对照块：只给在场的人 + 成对比较；**没有量级数据 ⇒ 提示词逐字节不变**；
6. 路线/量级由 AI 生成时**只建议不落库**；
7. 「处境」由规则推导（不问模型）；
8. 量级与体系类型**正交**（档位不当量纲用）。
