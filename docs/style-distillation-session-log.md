# 文风蒸馏工作记录（v3 → v7）

> 记录本轮在 `feat/style-distillation` 分支上的蒸馏迭代：做了什么、为什么、结果如何。
> 分档对比见 `style-distillation-tiers.md`；原始计划见 `style-distillation-plan.md`。
> 测试模型：智谱 glm-4-flash（免费档）。语料：豪门宠婚（603章/174万字）、大奉打更人（833章/510万字）。

## 一句话总结

叙事档案从「11 维度浅层提炼」迭代到「14 维度 + 角色名语料自证归一」，
v7 在语料 1 上 266 条规则、18 个角色全部规范全名；跨语料（大奉）压测出 3 个已知局限。

## 能力演进主线

| 版本 | 做了什么 | 关键结果 |
|---|---|---|
| v3 | 蒸馏维度从 7 扩到 11（+角色声音/文笔量化/剧情编排/伏笔/文风漂移） | 88 条规则，角色声音含伪角色 |
| v4 | 角色声音扩到 20 角色 + 关系动态 + 代表台词 | 角色声音维度成型 |
| v5 | 五重提升：节拍序列/高频场景模板/潜台词模式 + 针对性角色检索 | 14 维度，但角色名截断、部分信息「无」 |
| v6 | 采样按百分比 + 场景均衡 + 对话优先；节拍多块提取 | 覆盖面可控，但暴露占位符/伪角色/名字截断三类缺陷 |
| v6.x | 连续修 v6 质量缺陷（见下） | 角色声音从混乱到干净 |
| v7 | 角色名按语料自证的词频关系归一 | 语料 1 上 19 个规范角色名、12 条别名映射、零占位符零伪角色 |

v6.x 的修复链（每个都是真实蒸馏暴露的真问题，不是预设）：
1. 角色覆盖不足——配角在单章出现次数不达阈值被跳过，出现阈值 ≥3→≥2
2. 角色声音混合提取——推理模型逐个提取 20 角色太慢（47 分钟未完成），改主要角色逐个 + 配角分批（8+3 次调用）
3. 过滤动词伪角色——GLM 把「相信/喜欢/冷声」当角色名
4. 重写子串合并逻辑——「小落/宫爵」没合并到全名
5. 角色声音 prompt 占位符——system prompt 示例里的「角色A/B」被 GLM 照抄成输出
6. 角色 key 模糊匹配——LLM 用简称「宫爵」做 key，精确匹配失败
7. 「具体角色名」占位符——改 prompt 示例又引入新占位符
8. 文风漂移 LLM 输出容错——key 名不稳定（漂移总结/整体趋势/总结）

## v7 核心工作：角色名语料自证归一

### 问题

图谱（LLM 逐块抽取）的 character 节点很脏——语料 1 的 513 个里混着：
- 高频虚词：时间/任何/相信/简直/充满/公司…
- 分词截断：同一角色被切成「安小落/小落/安小」「南宫爵/宫爵/南宫」

把图谱当权威规范名永远合不拢——「小落」本身就是图谱节点，精确命中后原样返回。

### 修法：用语料词频的包含关系自证，不依赖词表

两个判据（`app/style/narrative.py`）：

1. **包含判据**（`_resolve_name_artifacts`）：对 A ⊂ B 的两名
   - A 独立出现 ≤15% → A 是截断，归一到 B：宫爵(9984)≈南宫爵(9982) → 合并
   - B 频次 ≤15%×A → B 是「名字+相邻字」的过度切分，归回 A：夏诺柔(41)⊂夏诺(2354)
     （这条同时挡住「夏诺柔声」这类假名）

2. **后缀判据**（`_extend_name_candidates`）：N 的高频后继字构成全名 N+c
   - 莫泽 1800 次里 1781 次是「莫泽修」，独立 1.1% → 莫泽 → 莫泽修
   - 后继字符集排除功能字/标点（_NAME_CONT_STOP），否则「安小落」+「的」会被当新名字
   - 实测分离度：真截断 ≤1.1%，真名 ≥67%（完全分离，无误判）

配套：候选池改为「会说话的角色 ∪ 高提及角色」；`_is_fake_character` 统一伪角色判定；
MAX_VOICE_CHARACTERS 20→30（名额不再浪费在伪角色上）；NARRATIVE_VERSION 6→7 让旧缓存失效。

### 语料 1 实测（豪门宠婚）

- 规范角色名 19 个，全部是真角色：安小落/南宫爵/夏诺/莫泽修/何萱萱/蒋曼曼/莫雨蝶/
  钟姨/冷月/文静/南尊义/韩明秋/夏浅/唐甜甜/郑楚桥/南总/林玲/莫母/秦岚
- 别名映射 12 条：小落→安小落、宫爵→南宫爵、莫泽→莫泽修、何萱→何萱萱、
  蒋曼→蒋曼曼、莫雨→莫雨蝶、南尊→南尊义、唐甜→唐甜甜、郑楚→郑楚桥、
  安小→安小落、南宫→南宫爵、夏诺柔→夏诺
- 角色声音 18 个，零占位符零伪角色

## 跨语料压测：大奉打更人暴露的已知局限

用大奉（图谱 2644 角色节点，比语料 1 大 5 倍）压测 v7，725 条规则/22 角色，主要角色全对，
但暴露 3 个大奉专属局限（非语料 1 回归）：

1. **同一人多种切分未合并**：金莲道长(1349)/金莲道(1361)/莲道长(1472) 互不为子串，
   包含判据合并不了；后缀判据被「道长」停用挡住。角色声音里「金莲道」「莲道长」分裂，台词张冠李戴。
2. **称谓混入**：魏渊/魏公（官称）各占一条，台词重复。
3. **角色名池膨胀到 421 个**：大奉图谱 speaking 标志几乎全 true，
   候选池「会说话 ∪ 高提及」几乎不过滤，混进大量虚词（武夫/云州/江湖/公主/公子…）。
   语料 1 的 speaking 区分度高（39/513），大奉失去区分度。

修法方向（未实现）：称谓后缀词表 + 言说动词邻接率二次过滤 + 称谓前缀映射表。

## 工程要点 / 踩坑记录

- **DB 字段名坑**：distill 接口返回里维度分布在 `dimensions`，落库到 `projects.style_narrative`
  后叫 `rules`。扫历史 DB 时读错字段会得到全 0。
- **推理模型慢**：MiniMax/nemotron/glm-4.7-flash 对角色声音（7 维度分析）逐个提取极慢，
  47 分钟未完成 20 角色。改混合提取（主要逐个+配角分批）后 glm-4-flash ~21 分钟跑完 90 章。
- **GLM 照抄 prompt**：任何写进 system prompt 示例的占位符（角色A/具体角色名）都会被 GLM 当输出。
  改示例只能缓解，根治靠后处理过滤 + 归一化。
- **服务被杀丢结果**：蒸馏 29 分钟处进程被 kill，连接中断、未落库。长任务要防中途被杀，
  图谱已落库的可直接重跑蒸馏（不用重建 KG）。
- **合成测试语料要仿真实结构**：名字后必须接标点/「的」（不能当交接字符）、
  名字要嵌在另一名字内、名字后要接言说词，否则扩展判据会造出假名字。
