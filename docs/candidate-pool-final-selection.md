# 候选池的末端择优：让「池选中 == 落库」

> 状态：已实现（2026-10-28）。
> 相关：`backend/app/generation/engine.py`（`_run_pool_selection` / `_run_text_chain` /
> `_judge_final_text`）、`backend/app/generation/candidate.py`（打分器）、
> `ENGINEERING.md`「候选池的择优结论，在流水线末端还成立吗」一节。

## 一句话

候选池以前挑的是「候选原稿」，落库的是「那份原稿被后面几道工序改过之后的东西」——
**两者从来不是同一份**。现在改成：**每份候选走完整条链之后，再用同一把尺量成品，
落库第一份合格的**（拒绝采样跑在整条链上）。

## 问题：口径差是结构性的

落库前有 7 道会改文本的工序：

| 工序 | 改不改文本 | 改什么 |
|---|---|---|
| 场景契约审计修复 | 会（局部） | 局部补写 |
| AI 味重写 | 会（全文） | 全文重写 |
| 段内自我重复清理 | 会（删段） | 字数 |
| 文风改写 | 会（全文） | 句长（候选池根本不打这一项） |
| 形态校正（机械合并 + 引导语补写） | 会（改段边界 / 新增叙述） | 形态 ⇒ 拉回档案带内 |
| beat 插入 | 会（加叙述） | 形态（只降不升） |
| 照搬门禁重写 | 会（全文） | 形态 —— **这一步在形态校正之后** |

择优发生在第 1 步、落库在最后一步 ⇒ 中间隔着这些工序。
实测（2026-10-27 两轮真跑）：**池交出 2733 字 → 落库 2558 字**；
另一轮落库形态 **41%**，而带上沿 **33.5%** ⇒ 出带。

修法 A（2026-10-27 做的）只闭合了「段长闸门」那一道：
闸门挪进池内（打分之前），落库前再用同一把尺复判一次，**失效只留痕、不阻断**。
⇒ 「择优的结论失效了」从此看得见，但**看得见 ≠ 修得掉**。

## 三条路与选择

| 方案 | 做什么 | 代价 | 判断 |
|---|---|---|---|
| A | 闸门挪进池内 + 末端留痕（已做） | 零 | **不够**：看得见 ≠ 修得掉 |
| B | 把整条链跑 N 遍，落库前择优 | N × 链 | 贵，但**按需**就不贵 |
| C | 池只判形态，不碰落库 | 零 | 没解决「落库 ≠ 选中」 |

**选 B，但做成「按需的 B」**：不是先把 N 份都跑一遍链，而是
**采一份 → 跑一条链 → 量一次成品 → 合格就停；不合格才采下一份**。
⇒ 常态成本 = **1 次采样 + 1 条链**（与从前「合格即停」时一样），
最坏 N 条链。

## 设计

### 1. 采样与走链**交替**进行

```
for i in 1..N:
    候选 ← 采样（1 次模型调用）
    候选 ← 段长闸门（会整段重写 ⇒ 必须在打分与走链之前）
    成品 ← 走完整条链（场景审计 → AI 味重写 → 去重 → 文风改写
                       → 形态校正 → beat 插入 → 照搬门禁）
    判定 ← 用同一把尺量「成品」
    合格 ⇒ 落库它，停
都不合格 ⇒ 落库「离目标最近」的那份，并如实标注偏离（下限兜底）
```

**为什么闸门在池内**：闸门在字数不够时是**整段重写**。放在打分之后，
被认可的稿子会被当场换掉，而新稿从没被量过。

**为什么按需**：链很贵（一条链 ≈ 10~30 次模型调用）。先把 N 份都跑链，
等于为「可能用不上的候选」先付一遍链的钱。

### 2. 末端那把尺：只判形态

- **尺** = `stylometry.band_check()` 的「纯台词段占比」（与机械校正闸门、
  池的先验分**同一把尺**，不引入新判官）。
- **只判形态，不判字数**：长度由**段长闸门**负责（池内每份候选都过一遍）；
  而落库前的**文风改写**会压缩 15%~25% ⇒ 链后的文本常落在目标的 60%~80%，
  正好压在池的守恒下限附近 ⇒ 拿它裁决链后的文本会**系统性误杀**。
  字数只**如实报出**（`length_ratio`），不参与裁决。

### 3. 链必须能被重复跑

所以把链抽成 `_run_text_chain()`：只做文本变换 + 只读数据库，不落库、不写库
（唯一例外是照搬门禁的后台索引预热，幂等）。同步路径与流式路径共用这一份实现
⇒ 两条路径的池口径**必然一致**。

### 4. 顺带修好的两件事

- **流式路径吐出来的字 == 落库的那份**（池路径改成「先择优、再吐字」）。
  以前吐的是链之前的稿子，链跑完就与界面显示的对不上。
- **默认路径逐字节不变**：`pool_size = 1` 时不进池（不采样、不闸门、不判定），
  连尺子都不拿出来量（有测试钉住）。

## 代价

| | 采样调用 | 链 | 说明 |
|---|---|---|---|
| 池关（默认） | 1 | 1 | 与从前完全一致 |
| 池开 · 第一份合格 | 1 | 1 | 常态 |
| 池开 · 都不合格 | N | N | 最坏情况 |

对比从前（2026-10-27 的口径）：从前的池是「先采 N 份、挑一份、跑一条链」，
且**合格即停**发生在采样阶段（用的是链前的形态预览）⇒ 常见情况 1 份采样 + 1 条链，
但**落库的那份不一定合格**。现在常态成本相同，换来「落库的一定是尺子判过的」。

## 边界（不声称的事）

- **池默认关**（`STYLE_CANDIDATE_POOL=1`）：这条路的收益是「开了池时结论诚实」，
  不是「让默认路径更好」。
- **末端只判形态**：链后的字数若低于闸门下限，会如实报在 `length_ratio` /
  `length_report` 里，但**不参与裁决**（理由见上）。
- **都不合格时仍会落库**：落「离目标最近」的那份，并标注偏离——
  拒绝采样的原则：预算不确定，但保证最低质量。
