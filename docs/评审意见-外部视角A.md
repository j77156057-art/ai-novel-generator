# 评审意见 · 外部视角 A：长篇生成「记忆与注入体系」

> 材料核对：简报对代码描述属实——`prompts.py` 中风格确实仅来自下拉标签 + RAG 原文（`_style_block` 只打印 `{类型/风格平台}`）；`extractor.py` docstring 确写「LLM 抽取后置」、规则基线为占位质量。本评审为对抗性、非附和。

## 贯穿全表的判断

你的痛点（不遗忘、像人写）主要不是「记忆结构不够」造成的，而是三个被你在方案里排在中后段的便宜事造成的：① 段级 60 字摘要链本身就是遗忘机制（有损压缩随 30 段累积）；② 实体消解/别名表缺失（就是你看到的 宁折/宁折枝、晏无/晏无咎）；③ 风格没走可计算的文体统计。四层方案的重心压在「往记忆里加更多结构」上，方向有偏。

## 逐条评审

| 编号 | 结论 | 理由/证据 | 优先级 | 对你原方案的修正 |
|---|---|---|---|---|
| Q1 | 排序部分错。L0+L3 最先做的前提是「抽取质量已达标」，但你自己证明它没达标（山门/左手误判成角色、4 条「坑」全是台词碎片）。坏地基上铺 30+ 实体只会等比放大垃圾 | L0 瓶颈是 ingestion 不是 schema；低成本模型很少「凭空握一把不存在的剑」，更常见的是忘名字（摘要链能带）和文风崩（目标 4，被你排到最后） | 必做(修正) | 真正的「线 0」应是 实体消解/别名表 + 分层摘要，比扩实体类型更早止血；L2 不该排在线 2 之后，离线可并行、性价比最高 |
| Q2 | 关键遗漏：别名/称谓归一表（那个 bug 的正解）、金手指/系统（系统文头号一致性对象）、境界有序阶梯（检测跳级/倒退的前提）。节奏类（爽点节拍/打脸/换地图）不该进 KG | KG 存可校验的实体状态；节奏是调度信号，用一个小的数值/日程状态即可，进图只增维护成本又没人遍历 | 必做 | 把 L0 拆两块：状态实体表（可校验）+ 节奏控制器（几行状态，非图谱）。金手指、境界阶梯从 P2 提到必做；信息不对称表降 P2 |
| Q3 | GraphRAG/MemGPT 都过重。性价比最高 = 分层摘要树（段→卷/arc→全书）+ 一张带别名的扁平事实表（不是图）。MemGPT 的「分页上下文」理念可借，但其 agent 自编辑记忆要多次 LLM 调用，与「点一次一段、首字延迟低、成本敏感」冲突 | 你不需要多跳图遍历，你需要「本场 ~20 条相关事实」——这是过滤/检索问题；分层摘要才是治「第 30 段遗忘」的便宜主力 | 必做(架构) | 别建图谱遍历设施；SQLite 加一张 `facts(type,key,props,aliases,updated_at)` 表 + 卷级摘要列即可落地 |
| Q4 | 「生成后检错→自动重写」是成本陷阱，别默认开。改写让同一段最多 2×~4× token；造错的弱模型往往检测不出自己的错 | 一致性最好在生成前约束（只注入高置信事实）+ 生成后跑不需要 LLM 的规则校验（死人说话/未知武器名/境界越序/别名分裂）→ 标红给用户看，不自动重写 | P1 | 把 L3 从「自动重写环」改成「零成本规则哨兵 + 命中才触发一次采样重生成」。真正省钱的校验在入库时（让事实可信），不在输出后 |
| Q5 | L2 蒸馏主体不该用 LLM。句长分布/标点频率/对话:旁白比/段落均句数/单字动词vs四字成语占比——是可计算的文体统计，对已有 chunk 跑 Python profiler，产出天然可量化验证的档案。LLM 只补统计抓不到的（比喻类型、视角习惯、断章钩子），且必须带原文 span 举例 | 这就是你没想出的「可计算指标」：拿生成段特征向量 vs 语料特征向量算距离（stylometry），无需人工即质量分；人工盲评降级为周期性校准 | 必做 | 新增离线 `stylometry.py`（纯统计）产出 L2 档案主体；蒸馏 prompt 改成「每维度给 {模式, 计数, 例证span含偏移}」，禁形容词式总结 |
| Q6 | 分层裁决，不一刀切「最新为准」。优先级：plot_bible/用户手改(作者意图) > 高置信抽取 > 低置信抽取。正文状态大体「最新为准」（写到即成 canon），但前提是修好别名，否则会在同一人两个别名间「最新为准」冲掉真值 | 死人说话/境界倒退/物品同时归两人属硬矛盾→阻断+标人工；单纯状态推进(受伤→痊愈)非矛盾→自动应用 | 必做 | 加「非矛盾更新自动应用 / 硬矛盾阻断人工」两档触发条件；别名词表未就绪前禁用自动裁决 |
| Q7 | 30+ 项确属过度设计。MVP 撑 30 段最小集：① 别名/实体归一 ② 角色表(一行当前状态)+死亡名单 ③ 境界阶梯+谁在哪 ④ 物品/功法含持有者(尤其金手指) ⑤ 伏笔台账(埋于第几段/回收状态) ⑥ 卷级分层摘要 ⑦ stylometry 风格档案 | 其余每项都带来维护/额外 LLM 调用成本，单机便宜模型付不起：信息不对称表、承诺/人情、悬念三级阶梯、情绪曲线、感官侧重、势力演化图、冲突升级阶段 | 砍 | 上面 7 项 = 必做；其余全标 P2/P3 或直接砍。别把 L1/L2 当清单逐条实现 |
| Q8 | 注入总量硬顶 ~1200–1800 token（约 1000–1200 字），给输出 3000 字(≈4500 token)留足窗口；每块设硬上限并按相关度截断，否则一定溢出。占比：分层前情/摘要 300–400（最大头）> RAG 300–400（砍到 2–3 段或更短窗，4×1200 字是隐形预算杀手）> L0 事实 200–300 > 风格 150–250（放静态 system 吃缓存）> L1 100–150 | 已把 system 保持静态做缓存——对；但 L0/L1 是动态的，若误放 system 会击穿缓存。RAG 原文收益最不稳、占预算最大，最该先砍 | P1 | 别只定「强/中/远」原则，要给每层一个 token 天花板 + 相关度打分截断，把最大预算给分层摘要而非 RAG 原文 |

## 两条你没问但影响很大

目标 4（像人写）被你系统性低估：它排在 L2 之后，却恰恰是用户一眼能感知、且你明说「基本未达成」的。它的主解（stylometry 档案，Q5）是离线、近零在线成本、天然可量化验证的——延迟它 = 延迟用户最爽的收益。建议 L2 里「统计那半」和实体消解一起进 MVP。

摘要链是「遗忘」的成因，不是解药：60 字/段的有损压缩串 30 段，信息丢失复利式累积。方案里把「分层摘要」轻描淡写带过，它其实比整个 KG 更能直接兑现目标 3（不遗忘）。段级细节 + 卷级压缩 + 一句话全书梗概，这套三级摘要成本几乎为零。

## 最危险的一个判断

你在用「往记忆里加更多结构（四层、30+ 实体类型、图谱、校验重写环）」，去对抗一个本质上由检索质量、token 预算、和入库抽取/别名质量决定的问题。

危险在于：它把你引向「建大教堂」——投入大量工程扩图谱 schema 和自动重写环，而地基（规则抽取 + 无别名归一）是你自己实证证明已经塌的；同时把真正止血的两件便宜事（分层摘要、可计算的文体蒸馏）排在后面。对单机、低成本、单模型约束而言，加结构的边际收益远低于修抽取和改预算分配。最坏情况下四层全做完，用户感受到的仍是「文风崩 + 关键设定记混」——因为那两件事不在这四层的重心里。
