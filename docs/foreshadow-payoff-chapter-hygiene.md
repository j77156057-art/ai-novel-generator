# 伏笔「计划回收章」脏数据清理（2026-10-29）

## 一、问题

`kg_foreshadows.planned_payoff_chapter` 里存着一批**编造的回收章号**，它们会：

1. **造出假告警** —— judge 的 `check_foreshadow_expiry` 按
   「`planned_payoff_chapter < current_chapter` ⇒ 伏笔超期」判。
   `pf=0`（第 0 章不存在）比任何 current_chapter 都小 ⇒
   **实测 83 条假告警**：「计划第 0 章回收，已超期 9 章仍未揭晓」。
2. **进界面误导人** —— KG 工作台显示「埋@3 → 计划 50」，
   而这个 50 在正文里**一个字都找不到**。
3. **进提示词当假约束** —— 这一条在 `e8c90bd` 已处理（伏笔块只列名字），
   但排序仍按 `plausible_payoff_chapter` 走，脏值会把行排到前面。

## 二、取证（本地冒烟库，真机量出来）

### 2.1 脏值分布

140 条伏笔，`planned_payoff_chapter` 分布：

| 值 | 条数 | 判 |
|---|---|---|
| `NULL` | 29 | 正常（没写） |
| `0` | 84 | **脏** —— 第 0 章不存在 |
| `50` | 22 | **脏** —— 无正文证据；其中 18 条恰好等于抽取提示 JSON 示例的字面值 50（模型照抄） |
| `30` | 1 | **脏** —— 无正文证据 |
| `12` | 1 | **脏** —— 无正文证据 |
| `1`（`planted=1`） | 2 | 合法（同章回收，`paid_off`） |
| `4`（`planted=4`） | 1 | 合法（同章回收，`paid_off`） |

⇒ **108 条要清，32 条保留**。

### 2.2 段号 = 书内章号

`generations.chapter_range` = 「第 N 章」，**一段一章** ⇒
**段号 = 书内章号**（不是两套编号）。
实测 `planted_chapter` 取值域 = `{1,2,3,4,9}`，全在已写段数 `[1,9]` 内
⇒ `planted_chapter` 与 `planned_payoff_chapter` 用**同一个单位**，可以直接比。

### 2.3 危害量化

按 `check_foreshadow_expiry` 现有逻辑复算：

| 项目 | current_chapter | 有 pf 的 active | **触发假超期告警** |
|---|---|---|---|
| 1 | 9 | 92 | **72** |
| 2 | 2 | 15 | **11** |
| 5 | 6 | 0 | 0 |
| | | | **合计 83 条假告警** |

## 三、判据：证据，不是数值上界

写进 `app/kg/foreshadow_quality.py` + 新的 `app/kg/chapter_evidence.py`。

### 3.1 ⚠️ 为什么**否掉**「回收章 ≤ 已写章数」这条上界

最初的设计是加一条上界：`planned_payoff_chapter ≤ 已写到的章`。
**量过之后否掉了**。

`planned_payoff_chapter` 是「**计划**回收章」——作者对**将来**的规划。
「埋@3 → 计划第 60 章」是**合法且有用**的路线图信息（长篇里伏笔几十章后
才收是常态）。用「已写章数」当上界会把这条功能直接杀掉：
用户才写 9 章就想规划第 60 章回收，也会被判成非法。

⇒ 改用**正文证据**判：这个章号得在**正文里真的出现过**。

### 3.2 正文证据（`app/kg/chapter_evidence.py`）

正文证据长这样（**阳性对照**：参考书语料 10122 块里 151 处命中）：

```
（第一章。）        （第二章。）        白马出凉州第一百三十章八叉
```

⇒ 认「**章**」「**节**」，阿拉伯数字（`第 12 章`）与中文数字（`第十二章`）都认。

⚠️ **一个坑**：生成正文里有「停过两回，**第一回**是傍晚，**第二回**是换防以后」。
这里的「回」是「次数」，**不是章节**。若把「回」也当章号证据，
「第二回」会被当成「第 2 章」——凭空给一个不存在的回收章号背书。
⇒ **只认「章」「节」，不认「回」。**

**阳性对照自证**（尺必须先用阳性对照证明自己能用）：

| 语料 | 段/块数 | 「第 N 章」命中 |
|---|---|---|
| 生成正文（用户自己写的 19 段） | 19 | **0** |
| 参考书语料 | 10122 | 151 |

匹配器**能**命中真章号（151 处）⇒ 生成正文的 0 命中是**真阴性**，
不是匹配器坏了。⇒ 所有脏值（`0`/`50`/`30`/`12`）在正文里都没有任何证据。

### 3.3 三级判据

1. **章号 ≥ 1** —— 第 0 章不存在；
2. **回收章晚于埋下章** —— 同一章回收等于没埋；
3. **正文证据** —— 这个章号在正文里真的出现过。

说不通 ⇒ **置空（当作未知）**，不猜一个数补上。

### 3.4 状态敏感性：已收尾的行只判「章号 ≥ 1」

`closed` = `paid_off`（已回收）/ `dropped`（已丢弃）——
回收章记的是**当时的计划**，是**历史记录**：

| 状态 | 语义 | 处理 |
|---|---|---|
| `paid_off` | 已回收 ⇒ `pf == planted`（同章埋了又收）**合法** | 保留（实测 #91 `pf=1/planted=1`、#43 `pf=4/planted=4`） |
| `dropped` | 已废弃、**从未回收** ⇒ 没有「同章回收」这层语义 | `pf=0` 是纯脏值 ⇒ 清 |

⚠️ 这条区分是**真机跑出来的**：第一版规则写成「已回收/已丢弃都不清」，
结果库里剩下 1 条 `pf=0` —— id=46 是 `dropped`（已丢弃）状态。
`dropped` 与 `paid_off` 语义不同，不能一锅端。

⇒ `closed` 行**只判「章号 ≥ 1」**（`0` 不是章号），不拿现在的正文/埋下章
去重新裁决历史。

## 四、清理范围（分层，避免误伤）

| 层 | 做什么 | 为什么 |
|---|---|---|
| **落库层** | 新抽出的值过关才写 | 源头拦住，不再产生脏值 |
| **读取层** | 送模型 / 切片 / judge 告警前，对老数据再过一遍判据 | 老数据立刻不再进提示词，**不必等清理** |
| **存量清理** | 启动时一次性把存量脏值置空 | 账本不再带脏值；界面不再显示假计划 |

**清理只动 `kg_foreshadows`（机器抽取的），不碰剧情圣经里用户手写的伏笔** ——
`kg_foreshadows` 的唯一写入点是 `batch_worker`（全仓 `KgForeshadow(` 仅一处），
用户写的伏笔在 `plot_bible.foreshadowing` 里，是另一条路（且是权威）。

## 五、决策：自动清 vs 人点按钮

**决定：自动清（启动时）+ 记条数。**

依据：
- 判据是**确定性**的（数值不变式 + 正文证据），不是模型判断 ⇒ 零误伤风险；
- 置空的方向是「不知道」而不是「猜一个数」⇒ 不可逆损失为零；
- 老数据在清理前也已经被读取层挡住（送模型不再带脏值）⇒ 清理只影响界面/诊断，
  不影响生成质量，**不需要人守着点按钮**；
- 代价：清理前界面会短暂显示假计划 ⇒ 清理完即恢复。

按既有纪律，清理要**留痕**：记条数到日志，不静默改账。
清理**幂等**（跑第二遍不改任何东西）—— 启动时每次都跑。

## 六、验收项

1. `pf=0` 的行**不再触发** judge 超期告警（修前 83 条假告警）；
2. 送模型的伏笔清单里不再有脏 `planned_payoff_chapter`；
3. 存量清理后：脏值 108 → 0，合法值 32 条**一条不动**；
4. `paid_off` 的同章回收（`pf == planted`）**一条都不许清**；
   `dropped` 的 `pf=0` **要清**（两者语义不同）；
5. 剧情圣经里用户手写的伏笔**一个字都不许动**；
6. 计划回收章**可以指向尚未写到的将来章**（路线图功能不能被杀掉）；
7. 清理**幂等**（跑第二遍不改任何东西）、**只置空不删行**（140 → 140 行）。

## 七、真机验证（发布版冒烟库真实数据）

```
清理前（140 条）：pf=0:84  pf=50:22  pf=30:1  pf=12:1  pf=1:2  pf=4:1  pf=None:29
清理统计：{projects:3, total:111, cleaned:108, kept:3}
清理后（140 条）：pf=1:2  pf=4:1  pf=None:137
```

| 断言 | 结果 |
|---|---|
| 清理 108 条脏值 | OK |
| 保留的 3 条有值行全是 `paid_off` 同章回收 | OK |
| `paid_off` 行被清条数 = 0 | OK |
| `dropped` 的 `pf=0` 被清 | OK（1 条） |
| 幂等（第二遍 cleaned=0） | OK |
| 行数不变（140 → 140，只置空不删行） | OK |

**假告警基线复算**（旧判据 `pf < current_chapter`）：

| | 项目 1 | 项目 2 | 项目 5 | 合计 |
|---|---|---|---|---|
| 旧判据会报的假告警 | 72 | 11 | 0 | **83** |
| 新判据（修复后，**未清理**的库上） | 0 | 0 | 0 | **0** |

读取层在**未清理**的库上就已挡住脏值（切片里有回收章值的条数 = 0）⇒
**老数据不必等清理就不带脏值进提示词/告警**。
