# 助手聊天附件

## 输入与展示

在现有聊天输入框加入「添加文件」按钮，接受 `.txt`、`.md`；同一输入区支持拖拽文件和剪贴板文件粘贴。普通文字粘贴维持浏览器默认行为；文件与文字混合粘贴时保留文字及当前选区位置。其他格式以失败标签清楚提示，不能静默忽略。

文件标签展示名称和上传中、已就绪、失败状态；未发送附件可以移除或重试。发送过程中冻结附件编辑。失败/上传中的附件都会阻止发送，用户必须重试成功或移除。无文字但有就绪附件时，默认提问「请检查附件文本」，仅检查，不自动执行入库。提示用户上传不会自动入库。

消息沿用当前页面本地历史，用户气泡记录附件名称及发送中/已发送/发送失败状态；不引入独立聊天历史服务。

## 请求与隔离

- `POST /api/assistant/attachments`：multipart `project_id` + `file`，返回 `attachment_id, filename, size, encoding, status, preview`。
- `GET /api/assistant/attachments/{id}?project_id=…`：查询元信息。
- 现有 `POST /api/assistant/qa` 新增可选 `attachment_ids`；无附件沿用旧请求。只发送 ID，不读取整书或把文件正文塞进 query。
- 格式校验在客户端先行，大小/解码等由服务端验证并展示可读错误。
- 附件状态绑定项目和一次页面作用域。项目切换同步清空草稿/消息，并使旧上传与旧问答结果失效；A→B→A 仍不能接纳旧上传结果。
- 同一作用域内以名称、大小、修改时间去重；移除/重试生成独立请求对象，迟到响应不能复活旧标签。移除只移除草稿，不调用服务端删除。
- 问答失败保留附件供重发；问答成功后移除已发送草稿，历史仍保存名称。

## 验收

使用 Node 自带 test runner 运行 TypeScript 逻辑单测：发送体只包含 ID；空文本附件默认检查；上传失败与 pending 阻断；重复文件不重复上传；移除后不复活；项目切换与 A→B→A 迟到响应不污染草稿；重试成功后可发送。运行现有 `vue-tsc --noEmit && vite build`。不声称已完成浏览器交互或真实后端联调，除非实际执行并记录。
