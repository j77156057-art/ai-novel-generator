# 角色卡与「不千篇一律」的声纹（2026-10-29）

## 一、用户要什么

原话：

> 「新加入的角色性格行为怎么弄，还有一些路人甲角色，用户一个个写是不是有点麻烦……
>  加入准备加入新角色，AI 自动添加性格、行为、关系、口头禅这类，
>  用户可以自己修改，也可以 AI 自己生成，**但注意，生成的不要千篇一律，
>  得有各自的性格，不能出现几个人说话方式差不多的情况**。
>  另外我还发现，似乎没有记录角色使用的武器、使用的功法、有什么能力这一类型的
>  有关角色的记录，要不要做一个**角色卡**……蒸馏的时候也可以做出来，
>  正好用来完善角色对话、续写这类问题，然后模型生成文本的时候可以抽调出这类信息
>  注入提示词里面」

拆成三件事：

1. **角色卡**（身份 / 武器 / 功法 / 能力 / 声纹 / 关系），能自动生成、也能人改；
2. **批量新建路人角色**，AI 一次补齐属性，不用一个个写；
3. **不能千篇一律** —— 几个人说话方式必须分得出来。

## 二、取证：问题是真的，而且比想的严重

### 2.1 「说话方式差不多」实测成立

拿发布版冒烟库的 19 段真实正文，按角色统计台词的字符特征
（平均长度、感叹号/问号/省略号/破折号/逗号密度），算两两欧氏距离：

| 项目 | 有 persona | 角色数 | 风格向量平均距离 | 最近一对 |
|---|---|---|---|---|
| 5 | **有** | 5 | 0.230 | **0.037** |
| 1 | 无 | 8 | 0.399 | 0.138 |
| 2 | 无 | 6 | 0.439 | 0.163 |

**写了 persona 的项目反而更像**。project 5 的五个角色平均台词长度：
顾星河 7.5 / 伊芙琳 7.0 / 陆沉舟 8.3 / 白烬 7.8 / 守烛人 8.6 字 ——
全挤在 7~8 字。

⇒ **只写「沉稳寡言」这类形容词没用**：模型照样让每个人都写短句。
必须写**可执行、可比对的锚点**。

### 2.2 台词归属被污染（顺带查出来的更严重问题）

原来从正文反推 persona 用的是「名字周围 180 字窗口」⇒ 窗口里必然混进别人的台词。

肉眼看真实台词时直接看到：

```
「沉日者。」「你迟了。」     ← 这两句同时被算进 白烬 和 沉日者
「我从未参与那一战。」        ← 同时被算进 顾星河 和 伊芙琳
「两个都要。」「别碰那张图。」 ← 同时被算进 陆沉舟 和 守烛人
```

原因：这些行里出现了**两个**角色名（如「白烬抬头。「沉日者。」」），
而判据只看「名字在不在这一行」。

后果：白烬的 persona 把沉日者的台词记成了自己的口头禅 ⇒
**上游数据就是混的，下游怎么调都救不回来**。

### 2.3 角色属性确实缺武器/功法/能力

`kg_entities.attrs` 里 38 个 `character`：

| 键 | 覆盖 |
|---|---|
| `arc` | 38/38 |
| `current_goal` | 38/38 |
| `secrets` | 34/38 |
| **武器 / 功法 / 能力** | **0/38** |

`kg_character_state` 只有 6 类（location / injury / goal / mood / inventory / alive）——
那是**会变的状态**，不是**不变的档案**。确实缺一层「这个角色是谁」。

## 三、设计

### 3.1 角色卡四组字段

| 组 | 字段 | 回答什么问题 |
|---|---|---|
| **身份** | 性别 / 年龄 / 外貌 / 身份职业 / 出身背景 | 他多大岁数、长什么样、干什么的、从哪来 |
| **能力** | 武器 / 功法 / 能力 / **能力上限** | 打斗怎么写、他能解决什么、他**做不到**什么 |
| **声纹** | 自称 / 称呼他人 / 句长 / 句末 / 口头禅 / 禁用词 / 语气底色 | 他开口是什么腔调 |
| **关系** | 对每个人的称呼 / 态度 / 位置 / 边界 | 他与人怎么互动 |

**「能力上限」是刻意加的**：写「他很厉害」会让模型越写越强；
写「他不会水、一个人挡不住带刀的汉子」才锁得住。

### 3.2 声纹为什么必须是锚点

| 写法 | 能不能比对 | 后果 |
|---|---|---|
| 「沉稳寡言」 | ✗ | 五个人都会写成一样（实测正是如此） |
| 「句长=极短，句末=直陈收尾，自称=老身」 | ✓ | 能检出撞车，能要求改 |

句长档位（**闭集**，不给自由发挥）：

| 档位 | 字数 |
|---|---|
| 极短 | 1~4 |
| 短 | 5~8 |
| 中 | 9~16 |
| 长 | 17+ |

档位是**互不重叠**的（有测试钉住）——否则「换个档」等于没换。

### 3.3 「不千篇一律」靠三层，不靠一句提示词

1. **只产出锚点**：schema 强制「句长从这几档里选」「句末从这几档里选」；
2. **成批生成 + 互相避让**：一次生成整批，把**已生成的声纹**喂给模型，
   明确要求「与下面每一个都至少差两项」；
3. **生成后检测 + 撞了重写**：`voice_collisions` 判「相同锚点 ≥3 项」，
   撞了就把冲突贴回去让它改，最多 2 轮。

第 3 层是兜底：模型没听招呼时代码还能兜住。

### 3.4 判「撞车」的口径

| 锚点 | 相同算不算撞 |
|---|---|
| 自称 | 算（但**都自称「我」不算** —— 中文里绝大多数人自称我，没有区分度） |
| 句长档位 | 算 |
| 句末习惯 | 算 |
| 语气底色 | 算 |

**≥3 项相同 ⇒ 判撞车**。2 项相同不算（实测 B 组有 2 项相同的对，
但角色依然一眼能分出来）。

### 3.5 人写优先（与 persona 同一条纪律）

- 用户保存的卡标 `来源=user`，任何自动流程**不覆盖**；
- AI 补全只在**空缺**处填，用户写过的字段一个字不动；
- AI 生成结果**不落库**，要不要采纳由人点「保存 / 采纳」。

### 3.6 从正文抽卡：名称必须有出处

`extract_card` 抄同一套哲学（证据优先）但独立实现，不动
`style/character_profile.py` 那条有 6 字段 + claims 证据门的流水线：

- 武器 / 功法 / 能力的**名称必须逐字出现在正文里**，查不到就删掉这一条；
- 口头禅必须是正文里真说过的原话；
- 身份类字段（性别/年龄）不做逐字校验（正文常写「她」「十九岁」，逐字匹配会把对的删光）。

### 3.7 注入提示词

角色卡随角色约束块一起进 system 提示，形态：

```
  · 沈砚（守城士兵；动机：…）｜ 说话：… ｜ 会：…
  ↳ 性别男 ｜ 年龄：十九 ｜ 外貌：左手虎口有旧疤 ｜ 身份职业：守城士兵
     ｜ 武器：断刀（刀身有暗红纹路，不能见水） ｜ 功法：换气
     ｜ 做不到：不会水；记不住八个字以上的官话 ｜ 说话：自称「我」，句长极短，…
```

多角色同场时，`render_cast` 会额外加一句「句长、句末与称呼必须**彼此不同**」。

**没有卡时输出与改动前逐字节相同**（老项目不受影响）。

## 四、真机验证（openai/go 通道，真实模型）

### 4.1 通道（这一步踩了很久，记下来）

用户给的 key 是 opencode Go 订阅。实测：

| 端点 / 方式 | 结果 |
|---|---|
| `https://opencode.ai/zen/v1`（按量付费） | 429 `FreeUsageLimitError` / 402 `Insufficient account funds` |
| `opencode run -m opencode-go/<model>`（CLI） | 通，但本机 `~/.local/share/opencode/opencode.db` 是旧 schema（有 `session_v2` 没 `session` 表）⇒ 报 `Database is not empty and has no session table` |
| **`https://opencode.ai/zen/go/v1` + `x-opencode-session`** | **200，可用** ✅ |

⚠️ 少 `x-opencode-session` 会 400 `MissingSessionID`。
⚠️ 这些是**思考型**模型：`max_tokens` 太小会被 reasoning 吃光，
`content` 为空且 `finish_reason=length` ⇒ 必须给足（实测 4000 够）。

### 4.2 A/B 对照（同一模型 deepseek-v4.1-flash，4 个新角色）

| | A. 逐角色单独生成 | B. 整批 + 互相避让 |
|---|---|---|
| 拿到的卡 | 4 | 4 |
| 调用次数 | 6（含重试） | 3（含重试） |
| 两两相同锚点 | 最多 2 项 | **全部 0 项** |
| 句长铺开 | 2 档（3 人挤「极短」） | **4 档全铺开** |
| 自称分布 | 我 / 老身 / 本职 / 六（哑六） | 我 / 老身 / **下官** / 六 |

B 组六对角色**没有任何相同锚点**，句长四个档位各占一个。
⇒ 「一次整批 + 互相避让」确实把差距拉开了。

生成质量抽样（B 组，真实模型输出）：

```
祁婆婆：自称=老身 句长=极短 句末=常以命令收尾
        语气=居高临下，像在吩咐自家人干活
        口头禅=「海上的事，我说了算。」「记在簿上。」
        武器=断指橹柄
        做不到=不识字，账目全靠别人代笔，因此被人做过手脚 /
               右腿有旧伤，上不了灯塔的螺旋梯 /
               在官面上不会说软话，一进港务司就谈崩

白鹭：  自称=下官 句长=长 句末=常用「呢」「吧」
        语气=客气到发冷的官腔，每句话都像在念条款
        口头禅=「章程上不是这么写的。」「这不合程序。」
        武器=司印
        做不到=不敢违逆上司，命令下来再不合理也照办 /
               一撒谎就咳，瞒不过追问三句以上的人
```

「能力上限」写出来的是**可写的剧情障碍**（被人做过手脚、上不了螺旋梯、
一撒谎就咳），不是空泛的「怕水」。

## 五、真机跑出来的两个 bug（都靠真实模型才暴露）

### 5.1 `normalize_card` 只认平铺、不认分组 ⇒ 全丢

模型按我们给格式返回 `{"身份": {...}, "声纹": {...}}`，
而函数读的是平铺的 `raw["性别"]` / `raw["自称"]` ⇒ **整张卡变成 `{}`**。
假 provider 返回完全合法的 JSON，解析出来仍然是 0 张卡。

⇒ 先摊平分组再走同一套逻辑。

**修的时候又踩一次**：「能力」既是分组名又是字段名
（`{"能力": ["听声辨位"]}` 是平铺写法）。
摊平后如果跳过所有分组名，这个字段就被整块删掉。
⇒ 只有「`能力` 的值是 dict」时才当分组跳过。

### 5.2 思考型模型偶尔不吐 JSON，直接回一句寒暄

同一个 prompt，这一次返回 4 个角色的合法 JSON，下一次返回：

```
Hi! It looks like your message came through empty — I don't see a question...
```

⇒ 解析不出角色**必须重试**（加了 `PARSE_RETRY=2`），
不能把「这一次没吐 JSON」当成「功能不可用」。

### 一条方法论

**「代码跑通」和「模型真的能用」是两件事。**
上面两个 bug 用假 provider 都测不出来（假 provider 返回的 JSON 是我手写的、
格式恰好是平铺的；而且它永远会回 JSON）——
只有接真实模型、并且真实模型**按提示词格式返回**才暴露。

## 六、验收项

1. 一行出现 ≥2 个角色名 ⇒ 不算任何人的台词（归属不污染）；
2. 角色卡四组字段齐全，且「能力上限」必须能写出来；
3. 声纹撞车（≥3 项相同）能检出；**都自称「我」不算撞**；
4. 批量生成时避开已有角色，撞了会重写；
5. 用户写的字段不被 AI 覆盖；
6. 武器/功法/能力的名称查不到正文 ⇒ 删掉（不凭空造）；
7. 句长档位互不重叠；
8. 没有卡时提示词与改动前逐字节相同。
