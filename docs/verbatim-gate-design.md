# 正文级照搬门禁：生成正文 vs 参考语料

> 状态：2026-10-26 实现中。本文先定口径，再落代码。
> 相关：`ENGINEERING.md`「原创性：蒸馏之后的正文到底抄没抄」一节（本文的数据来源）

## 一、要解决的问题

项目里**已经有**照搬检测，但它只管一半：

| 已有机制 | 位置 | 管什么 |
|---|---|---|
| `plot_structure.copy_check` | `backend/app/generation/plot_structure.py` | **规划节点** vs 参考规则（12 字窗口），命中 → `CopyViolation` → 回灌自改 → 改不掉就拒绝保存 |
| 水印检测 | `backend/app/agents/ingest_clean.py` | **语料清洗**时剔盗版站 SEO 串 |

**没有**的是：**生成出来的正文** vs **参考语料原文**。

这不是理论风险 —— 项目自己踩过：

> v2.272 五章实测证据：5 章全在重写王府迎接道人那一段，第 4/5 段前 3 句几乎逐字相同。
> （`backend/app/style/narrative.py` 里的注释）

也就是说：**模型会把语料里的整段原话复读进正文**，而系统照收不误。已有机制一个都拦不住它
（规划节点是干净的，正文才复读）。

## 二、判据

**与参考语料共享一段连续 ≥25 字的逐字片段 = 照搬。**

### 为什么是 25 字（实测标定，不是拍的）

2026-10-26 在验收库的真实语料（5,323 段 / 498 万字）上实测「最长公共子串」：

| 对象 | 与语料的最长公共串 | 那一段是什么 |
|---|---|---|
| 真实生产产物（自创故事，13,722 字） | 9 字 | `。”“还有呢？”“` —— 纯标点 + 套话 |
| 同书续写（10,289 字） | 10 字 | 一个人名 + 一个动作 |
| 本轮实测 25 篇（83,390 字） | 11 字 | `“天地玄黄，宇宙洪荒”` ——《千字文》开篇 |
| **基准：与语料毫无关系的真书（987,101 字）** | **15 字** | 老子的话 |

**跟语料毫无关系的另一本书，和语料的最长重合（15 字）反而比我们生成的正文更长（9~11 字）。**
这就是「中文共用地毯」的实测上限：**≤15 字**。

⇒ 25 字 = 共用地毯上限的 1.7 倍，且高于所有实测样本 ⇒ **判得死**，够得上 error 级。
⇒ 12~24 字只**告警**不拦截（误报会堵死真活）。

### 尺的三处坑（写代码前先记下来）

1. **两侧必须先归一化空白**（`re.sub(r"\s+", "", t)`）。
   语料是清洗过的（去空行、去站点广告），生成文本有自己的换行缩进；
   不归一化会**系统性漏报**（实测：连「语料自己跟自己」都测不出重合）。
2. **n-gram 只能定位候选，不能当结论**。
   连续的 12-gram 全部命中，可能来自语料里**不同位置**的片段（误拼接）。
   实测：同一部书的另一份来源 vs 语料，12-gram 命中 99.5%，但整段在语料里找不到
   （两份来源是同章不同版本，段落顺序与内容有出入）。
   ⇒ 必须**逐字向两侧延伸**，只认真正连续的那一段。
3. **报「0」之前要把 n-gram 下限降下来再量一遍**。
   只用 12-gram 索引时量出来全是 0 —— 那不是「一个字都不重合」，是「最长也不到 12 字」。
   两个口径别混。

## 三、算法：为什么不能直接上 DP

语料 498 万字 × 正文 3000 字 ⇒ DP 要填 150 亿格，跑不动。

### 纯 Python 方案（项目**刻意不引入 numpy**，见 `backend/requirements.txt` 的说明）

**建索引（离线，一次）**

1. 语料归一化 → 一个长字符串。
2. 逐位置取 12 字窗口，算 `zlib.crc32`，与位置打包成一个 64 位整数
   `(hash << 32) | position`，塞进 `array('Q')`。
3. 整个数组排序 ⇒ 二分查找可用。

- 命中判定用 **CRC32 + 字符串复核**：CRC32 只有 32 位，理论上有碰撞，
  所以查到候选位置后**逐字比对**才算数 —— 碰撞只会多查一次，不会误判。
- `zlib.crc32` 与 `bisect` 都是 C 实现，单次探测 ~3µs。

**扫描（一段正文一次）**

对正文的每个位置 i：

1. 取 `text[i:i+25]`，算 CRC32，二分找候选语料位置；
2. 命中就**逐字向两侧延伸**（向前回到共同开头、向后延到共同结尾）
   ⇒ 得到真正连续的那一段（锚点式最长公共串，规避误拼接）；
3. 命中的区间整体跳过，避免同一段被反复报。

- 3000 字正文 ⇒ 约 3000 次探测 ⇒ **~10ms**。
- 一次**都不**调用 LLM。

### 索引缓存

- 建索引要扫全语料（498 万字 ⇒ 几十秒），**不能每段生成都做**。
- 缓存键 = **语料指纹** = `(novel_ids, chunk 条数, text 总长度, 最大 chunk id)` 的 sha1。
  指纹只依赖 SQLite 的聚合结果（`count/sum(length)/max(id)`），**不用把 498 万字读出来**。
- 两级缓存：
  1. **进程内**（按指纹，LRU 保留 4 份）—— 同一进程内多段生成只建一次；
  2. **落盘**（`.cache/verbatim/<fingerprint>.vbi`）—— 重启后直接读，不用重建。
- 落盘格式：自定义二进制（magic + 头 + 语料 UTF-8 + 索引表），不用 pickle。

### 实测（2026-10-26，真实语料 5,323 段 / 498 万字，纯 Python）

| 动作 | 耗时 |
|------|------|
| 建索引（498 万字 → 4,987,054 个 12-gram） | **9.4 秒** |
| 扫一段 3000 字正文 | **10 ms** |

⇒ 建索引放**后台线程**（入库后触发）就够；扫描每段生成都做也没压力。

## 四、接入点

`backend/app/generation/engine.py` 的 `generate_next_segment()`：

```
…生成 → 段长闸门 → 场景审计 → AI 味重写 → 去重 → 文风改写 → 形态校正 → beat 插入
                                                                    ↓
                                                          ★ 照搬门禁（新增）
                                                                    ↓
                                                             _commit_segment
```

放在**所有正文改写之后、落库之前** —— 落库的是最终文本，门禁必须量最终文本。

## 五、命中之后怎么办：回灌自改，改不掉就不落库

与项目既有约定一致（`plot_structure.CopyViolation` 的口径）：

1. **回灌**：把命中的片段（最多 5 段，每段带上下文）连同原文交给模型，
   要求它**用自己的措辞重写**这些地方。
2. **重扫**：改完再扫一遍。
3. **仍命中** ⇒ **不落库**，抛 `VerbatimViolation`（可重试失败，`code='possible_copy'`），
   由路由层转成 409 + 人话提示，让用户直接重试。

**为什么不直接报错让用户重做**：同样的原文喂回去，模型大概率改不掉同样的地方；
把命中的片段指出来让它自己改，一次改对的概率高得多。

## 六、误报策略与降级（宁可漏判，不堵死真活）

| 情况 | 行为 |
|---|---|
| 项目没有参考语料 | 放行（没有可比的东西） |
| 语料为空 / 索引构建失败 | 放行 + 在诊断里标注「照搬检测未执行」 |
| 命中 12~24 字 | 只告警，不拦 |
| 命中 ≥25 字 | 回灌自改 → 仍命中则不落库 |

**降级一律放行**：门禁是加分项，不是主链路。索引坏了不能连正文都写不出来。

|---|---|---|
| `style_verbatim_gate` | `True` | 门禁总开关 |

## 八、验收项

1. **尺必须先自证**（阳性对照）：
   - 语料自己的一段 vs 语料 ⇒ 必须命中，且长度 = 整段；
   - 改写过的同义文本（换了措辞）⇒ **不得**命中。
2. 阈值边界：24 字不拦、25 字拦。
3. 无语料 / 索引不可用 ⇒ 放行，不抛异常。
4. 命中 → 回灌 → 改干净 ⇒ 正文正常落库。
5. 命中 → 回灌 → 改不掉 ⇒ **不落库**，抛 `VerbatimViolation`，错误码 `possible_copy`。
6. 索引缓存：指纹不变时第二次不重建；语料变了指纹要变。
7. 全量 `python -m pytest tests/` 保持 0 failed。

### 真跑结果（2026-10-26，真实语料 5,323 段 / 498 万字）

| 对象 | 字数 | 命中（≥25 字） | 扫描耗时 |
|------|------|----------------|----------|
| 真实生产产物（自创故事，5 段） | 13,722 | **0** | 9~12 ms/段 |
| 同书续写（4 段） | 10,289 | **0** | 7~13 ms/段 |
| 本轮实测生成的 25 篇 | 83,390 | **0** | 7~40 ms/篇 |
| **阳性对照：往正文里注入 200 字原文** | 3,663 | **1 处（186 字连续）** | 11 ms |
| **阳性对照：只注入 24 字** | 3,501 | **0** | 14 ms |

即：**真产物全部判干净、故意注入的原文必被抓住、阈值边界准**。

## 九、不在本次范围内

- 不检测「换词不换句」的语义抄袭（要 embedding + 近邻检索，成本高、误判高）。
- 不检测**项目自己的前文**与新段之间的重复（那是 `generation/dedup.py` 的活）。
- 不检测角色名/地名泄漏（专名泄漏是另一类问题，需要白名单，见 `generation/guard.py`）。
