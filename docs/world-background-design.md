# 世界背景与硬规则（背景组）——设计

> 目标：让「这个世界是什么样」成为**一等公民**：作者能写、模型能看到、跨段不漂移。
> 现状是半块：`premise` 是可选且在时间线模式下整块不输出，`plot_bible` 的
> synopsis/direction 讲的是「故事往哪走」不是「世界长什么样」，
> `kg_entities(kind=worldrule)` 只能从**已写正文**反推（开书前为空）。
> ⇒ 结果是模型每段自己现编一套世界观，前后不一致。

---

## 1. 数据形状

`plot_bible` 新增一个顶层键：

```json
"background": {
  "一句话世界": "灵气在三十年前枯竭，修行靠残存矿脉活着。",
  "硬规则": ["灵力只在夜间可用", "修行者死后不留遗体"],
  "势力与地点": ["矿盟——三家联合垄断残存矿脉", "旧城——矿脉枯竭后的废墟城"]
}
```

**为什么子键用中文**：这些是**作者手写**的内容（不是模型 schema 的机器字段）。
`plot_bible` 里已有的作者手写块（`persona` 的「说话方式」「性格底线」、
角色卡的「身份」「能力」「声纹」）一律中文键，JSON 编辑器里作者能直接看懂。
顶层键仍用英文（`synopsis` / `direction` / `power_system` 同族）。

**归一化**（`app/generation/background.py::normalize_background`）：

- 一句话世界：`str`，去空白，≤ 300 字；不是字符串 → 该字段丢弃。
- 硬规则 / 势力与地点：`list[str]`，逐条去空白、去空串；≤ 20 条 / ≤ 30 条，每条 ≤ 200 字。
- 形状不对（字符串当数组、dict 当数组）→ 丢弃该字段，**不抛**。
- 别名容错（模型输出不稳）：`世界/世界观/背景` → 一句话世界；`规则/世界规则/限制` → 硬规则；
  `势力/地点/势力地点` → 势力与地点。

---

## 2. 提示词接线

`build_user_prompt` 里新增一块，**放在「剧情圣经·动态指引」之前**：

```
【世界背景（作者设定，全书一致，不得与之矛盾）】
一句话世界：灵气在三十年前枯竭，修行靠残存矿脉活着。
硬规则：灵力只在夜间可用；修行者死后不留遗体。
势力与地点：矿盟——三家联合垄断残存矿脉；旧城——矿脉枯竭后的废墟城
```

三条规则：

1. **时间线模式也注入**。这是与 `plot_bible` 其余部分最大的不同：
   `synopsis`/`direction` 携带整条故事走向 ⇒ 时间线模式必须剔（否则第一段就奔结局）；
   而「世界是什么样」**不含走向**，剔掉它只会让模型自己现编 ⇒ 保留。
2. **没有背景组就不出这一块**（连标题都不出）。空块是负面暗示，
   与 rag 空块整块不输出是同一条纪律。
3. **旧项目逐字节不变**。`background` 缺失 ⇒ 提示词与改动前完全一致
   （`tests/test_prompt_override_wiring.py` 的 golden SHA 守着这条）。

## 3. premise 的剔除规则改法

**问题**：`premise` 是用户写的「小说大概内容」，自由文本，**世界设定与剧情走向混在一起**。
时间线模式现在把它整块剔掉 ⇒ 世界设定跟着一起没了。

**做法**：不在提示词层做文本切分（脆弱、静默丢内容），而是**换承载**：

- 「合成剧情圣经」时，模型额外产出 `background`（从 `premise` + 类型 + 风格里抽世界设定），
  随圣经落库。
- 时间线模式下：注入 `background`（世界），**不注入** `synopsis`/`direction`/`premise`（走向）。
- 非时间线模式下：`background` 与 `premise` 都注入（premise 继续当基调锚点）。

⇒ 净效果就是「**只剔走向部分，背景/世界设定要保留**」，而且是在**合成时**分流一次，
不是在每次生成时重新猜文本。

**兜底**：`premise` 存在但 `background` 缺失（老项目、或模型没给）时，
背景面板的「AI 帮我补全」从 `premise` 抽一份，作者确认后保存即可。

## 4. 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/projects/{id}/background` | 保存作者编辑的背景组（写 `plot_bible.background`） |
| `POST` | `/api/projects/{id}/background/generate` | AI 补全背景组，**只返回不落库** |

- 保存走「合并进现有 bible 再整体写回」，与角色卡 / 角色个性同一条路
  （`flag_modified` 标脏，2026-10-28 踩过的坑）。
- AI 补全**不落库**：与体系、角色卡一致 —— AI 的东西要人点「采纳」。
- 闸门：一句话世界非空 **且** 硬规则 ≥ 1 条，否则回 `ok: false` + 人能读懂的原因。
- 渠道失败按 `_MODEL_FAILURE_HINTS` 映射（429→限流、401/403→鉴权、timeout→超时）。

## 5. 前端

剧情圣经卡片里加三行展示（世界 / 硬规则 / 势力与地点），
并在同卡片下挂一个「世界背景与硬规则」面板：

- 三个可编辑项：一句话世界（长文本）、硬规则（可增删的行）、势力与地点（可增删的行）。
- 按钮：「AI 帮我补全」（填入表单，不落库）、「保存」、「取消」。
- 文案面向小白：不用 `plot_bible` / `background` 这类内部词。

---

## 6. 已知边界

- **与 KG 的 worldrule 可能分叉**：KG 的 `kind=worldrule` 是从**已写正文**反推的
  （事实层），背景组是**作者设定**（意图层）。本轮不合并两者；
  出现矛盾时以背景组为准（作者意图 > 反推事实）。
- **`build_bible` 的响应模型是白名单**：`PlotBibleOut` 走 pydantic，
  **未声明的字段会被 `model_dump()` 静默丢弃** ⇒ `background` 必须显式加进
  `PlotBibleOut`，否则模型给了也存不下来。这条由守卫测试盯着。
- 背景组**不做**「自动从正文反推补全」——那是 KG 的活。

## 7. 实测效果

用 opencode Go 的**免费模型**（`deepseek-v4.1-flash`）做 A/B ——
便宜、可反复重跑，够回答「提示词指令有没有被听见」，
**不代表成稿质量**。

**① 背景块会被听见并影响正文**（同一提示词其余逐字节相同，各跑 3 次）

| | 设定要素出现 | 说明 |
|---|---|---|
| 无背景块 | **0/3** | 模型每次现编一个世界（写的是油、铜壶、剪子，零设定要素） |
| 有背景块 | **3/3** | 灵石 / 永夜 / 灯塔 都进了正文 |

**② 显式禁止能压住背景里的错误信息**（n=8/组，背景里故意写错「货币是金币」）

| | 出现「金币」 | |
|---|---|---|
| 有禁止规则 | **0/8**（命中 0 处） | |
| 去掉禁止（阳性对照） | **4/8**（命中 5 处） | 尺打响了，0 才有意义 |

⚠️ 这条**试了三轮才对**，前两轮的尺都没打响（详见 `ENGINEERING.md`）：
违规点要选模型「本来就会写」的那个**确切字符串**，
而不是选「故事上必然碰到」的那个东西 —— 选「灯塔」这个概念必然碰到，
但模型写的是「塔」，尺还是打不响。
**没响的尺 ⇒ 那轮实验不能出结论**（既不能说有效，也不能说无效）。

## 8. 验收

- 提示词：背景块出现在「剧情圣经·动态指引」**之前**；时间线模式**也**出现；
  没有背景组时提示词逐字节不变。
- 数据：`PlotBibleOut` 含 `background`（守卫测试）；归一化对脏形状不抛。
- 接口：保存即落库；AI 补全**不**落库；闸门拦空结果。
- 前端：类型、三行展示、编辑面板。
