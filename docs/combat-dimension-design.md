# 战斗描写维度

## 缺口

实测当前 570 条蒸馏规则里，只有 **3 条**真正讲「战斗怎么写」：

> 战斗采用招式解释、双方试探、暂停判断、再起杀招的层层递进，避免一次性宣泄
> 战斗场景不预设全貌，而按距离变化逐层显露对手、兵器与杀招
> 刺杀的快节奏被一段极长的内心追忆打断，用延时回忆将节奏从物理时间拉回心理时间

其余 52 条「战斗相关」规则（占 9.6%）只是**提到**兵器或打斗情节，讲的不是写法。

## 为什么要单独一维

同一场打斗，五种写法读者感受完全不同：

| 写法 | 特征 |
|---|---|
| 一招一式拆解 | 报招式名、拆招、防守反击，节奏慢但精确 |
| 蒙太奇快切 | 动作碎片、短句并置、视角跳切，节奏极快 |
| 环境破坏 | 借地形与器物损毁表现力量，不细写招式 |
| 旁观者侧写 | 写旁观者的震惊反应，正面战斗一笔带过 |
| 心理博弈 | 打之前的判断、试探、气势压制占大头 |

这些差异**句长、句号密度、对白比例都测不出来**——它们都是「打斗」，统计特征相似，
但读起来完全是两个作者。

缺这一维，生成战斗段落时只能靠「场景构建」顺带写一句，写出来是通用网文打斗。

## 实测验证（4 章真实战斗片段，MiniMax-M3）

选中战斗词最密集的 4 章（第 990/881/777/641 章），各截 2500 字，真实调用：

```
总规则 31 条，中位长度 61 字
人名/地名残留 1 条（且在「证据：」里，渲染时会被剥掉）
招式名残留 0 条
单次耗时 6-12s
```

抽样质量（北荒刀歌，作者署名已隐去）：

> 打斗前后用大段设定讲解和人物对话铺陈，气运、朝局、人物前史占据七成篇幅，
> 真正交锋只用极短段落收束

> 交锋动作高度凝练，靠单一动作的夸张量级推进而非逐招拆解
> （证据：踏出寸余、横移十数步、一砸倒地）

> 作者用旁观者甚至小辈的反应来侧写主角的气势，自己不直接评价，
> 力量由旁观者的错愕、欢喜、惭愧反推

> 真正动手只占极小篇幅，绝大部分段落被对峙、言语交锋、心理推演和人物关系交代占满

**这正好抓住了北荒刀歌的战斗风格**：不逐招拆解，重蓄势与旁观者侧写，
动手极短但后果夸张。换成另一本书（比如逐招拆解的武侠），抽出来的会是完全不同的规则。

## 实现

`_build_combat_prompt`（`app/style/narrative.py`），八个问题：

1. 拆解粒度（逐招 / 快切 / 只写结果）
2. 节奏（一次交锋几句、长短句交替、中途是否停顿）
3. 视角（贴主角 / 切对手 / 旁观者侧写）
4. 力量如何表现（招式效果 / 环境损毁 / 对手反应 / 器物状态）
5. 语言特征（长短句 / 拟声词 / 术语 / 古语）
6. 开打前怎么蓄势
7. 怎么收尾（干净利落 / 力竭 / 第三方打断）
8. 战斗中还投喂什么信息

约束与另外三个剧情型维度一致：**只写手法结构，不写具体内容**——不写人名、
地名、门派名、招式名，不复述这场战斗发生了什么，每条必须可迁移。

## 接线

| 位置 | 改动 |
|---|---|
| `NARRATIVE_DIMENSIONS` | 新增「战斗描写」 |
| `DIM_LABELS` | `"战斗描写": "打斗"` → 渲染成 `打斗——…` 一行 |
| `_FAST_TIER_DROP_DIMENSIONS` | 加入（每 chunk 多一次调用，属增量能力） |
| 采样器 | 新增 `kind="combat"` 一路 prompt |
| 解析分支 | 与语序编排同构：证据验证 + 逐字复制检测 |
| `_COMBAT_NOISE_PREFIX_RE` | 剥掉模型照抄的「规则描述：」前缀，但保留「拆解粒度：」这类分类标签 |

## 测试

- 明确禁止写招式名与复述剧情
