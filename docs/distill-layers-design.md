# 蒸馏产物 × 三种用途 × 模型分档（设计）

> 状态：待审｜依据：M3 全量蒸馏实测 + 现有 14 维度审计

## 0. 先说结论：现有架构有两个结构性缺口

### 缺口一：产物是「一本书一份档案」，但三种用途要的东西不同

现在 `projects.style_narrative` 存一份 `rules` 字典（14 个维度），三种模式
都从这一份里挑：

| 用途 | 需要什么 | 现状 |
|---|---|---|
| 原创 | 作者的写法（手法、语序、句法）| 从同一份挑 METHOD_DIMS |
| 续写 | 世界观 + 人物 + 时间线 + 手法 | 从同一份挑，靠 RAG 补实体 |
| 角色聊天 | 单个角色的性格/经历/口头禅/关系 | 从同一份挑 `角色声音词典` |

**问题：续写需要的「世界观 / 人物关系 / 时间线」不在这份档案里**，它们靠
生成时 RAG 检索原文 + 图谱节点临时拼。这导致续写的正确性取决于检索质量，
而不是蒸馏产物——蒸馏只贡献了文风。

### 缺口二：角色聊天只拿到一条「声音词典」，拿不到「这个人会做什么」

`角色声音词典` 现在长这样：

```
隋珠公主：自称「本宫」，语气骄横尖刻，受辱时以反问、威胁反击（证据：本宫的女子）
```

只有**说话方式**，没有：
- 这个人经历过什么（决定他会怎么反应）
- 他和对话者的关系（决定称呼和态度）
- 他的性格底线（决定什么话他不会说）

角色聊天要防「说出不符合身份的话」，光有声音词典不够。

## 一、蒸馏产物的正确结构：四层，按用途分区

不要一份 14 维平铺的 `rules`。按「这份产物回答什么问题」分四层：

```
┌─ L1 文风层（原创用）─────────────────────────────┐
│ 手法 12 维：人物描写/对白风格/段落编排/场景构建/    │
│ 情绪表达/节奏控制/世界观呈现/剧情编排模式/伏笔与    │
│ 悬念设计/节拍序列/高频场景模板/潜台词模式           │
│ + 反向禁忌 4 类                                    │
│ + 语序编排（新增，见下）                            │
│ 特征：抽象、可迁移、零专名                          │
└────────────────────────────────────────────────┘
┌─ L2 人物层（续写 + 角色聊天用）───────────────────┐
│ 每个主要角色一条：                                  │
│   说话方式（自称/口头禅/句长/语气）                  │
│   行为倾向（遇到 X 会怎么做）                       │
│   性格底线（不会做什么）                            │
│   关系网（对每个人的称呼与态度）                     │
│   关键经历（决定他现在的状态）                       │
│ 特征：含专名，只在「写这本书」时可见                 │
└────────────────────────────────────────────────┘
┌─ L3 世界层（续写用）──────────────────────────────┐
│ 力量体系 / 势力格局 / 地理 / 时代背景               │
│ 特征：含专名，续写可见，原创不可见                   │
└────────────────────────────────────────────────┘
┌─ L4 时间线层（续写用）────────────────────────────┐
│ 已发生事件的有序摘要（第 N 章发生了什么）            │
│ 特征：含专名，续写可见                              │
└────────────────────────────────────────────────┘
```

**关键设计判断：L1 与 L2/L3/L4 必须物理分开存。**

理由：L1 是「怎么写得像作者」，L2-L4 是「这本书是什么」。前者对任何一本新书
都有效，后者只对这本书有效。混在一个 `rules` 字典里，原创模式就得靠
`_prompt_form` 逐条剥离——而剥离必然漏（已实测：791 条场景模板剥完仍带剧情）。

分开存之后，原创模式**根本不读 L2-L4**，不需要剥离。

## 二、L1 要补的维度：语序编排

用户提到「作者习惯的写字顺序、语序的编排」。现有 14 维里没有这个。

现有维度讲的是「句子怎么写」（句长、节奏、段长），没讲「信息按什么顺序给」：

- 先写环境还是先写人物动作？
- 对话前垫动作还是对话后补动作？
- 一个场景里，先交代空间、还是先给出人物、还是先抛一句对白？
- 段落内部：先结论后细节，还是先细节后结论？

这是**比句长更本质的文风特征**，且强模型能学到（弱模型未必）。

新增维度 `语序编排`，蒸馏 prompt 要问的是：

```
1. 场景开场：先给空间/先给人/先给声音/先给对白？
2. 对话与动作的相对位置：动作在前铺垫、在后补充、还是穿插？
3. 段内信息顺序：从宏观到细节，还是从细节拉远？
4. 场景切换方式：空行硬切/过渡句/人物位移带出？
5. 时间推进：顺叙为主/插叙/预叙（先给结果再回溯）？
```

## 三、模型分档：蒸馏侧也要分，但和生成档位不同轴

### 为什么蒸馏必须分档

实测差异（同一批 chunk，同一 prompt）：

| 模型 | 规则数/调用 | 中位长 | **过短率** | 耗时 |
|---|---|---|---|---|
| 智谱 glm-4-flash | 10.8 | 17 字 | **29%** | 92s |
| MiniMax-M3 | 17.7 | 29 字 | **0%** | 156s |

过短率 29% 意味着弱模型有 1/3 产出是「文笔细腻」这类空话。

**但这不是「弱模型不可用」，是「弱模型能做的维度更少」。**

实测还发现：弱模型在**抽象归纳**上明显弱于强模型（把 231 字剧情压成 10 字
骨架这件事，M3 改完 prompt 就做到了，智谱做不到）。而弱模型在**清单式抽取**
（列出口头禅、列出场景类型）上差距不大。

所以分档不是「用不用弱模型」，而是**「哪些维度交给哪种模型」**：

### 三档定义

| 档位 | 模型 | 抽哪些维度 | 预期产出 | 耗时（990 章 30%）|
|---|---|---|---|---|
| **quick** | 弱模型（glm-4-flash）| 只抽 L1 的「清单型」维度：对白风格 / 段落编排 / 反向禁忌 / 人物声音（说话方式部分）| 骨架可用，无深度 | ~26 min |
| **standard** | 强模型（M3）| L1 全 13 维 + L2 人物层 | 完整 | ~13 min |
| **deep** | 强模型 + 两轮 | L1 + L2 + L3 + L4，且 L1 跑两轮取交集（稳定性）| 最完整 | ~30 min |

**注意 quick 档的耗时反而比 standard 长**——弱模型单请求慢且并发上限低（2 vs 15）。
所以 quick 档的价值不是快，是**免费**。

### 档位与维度的映射要可测

不能凭感觉说「弱模型做不了抽象归纳」。要有判据：

```
某维度在 quick 档的产出，若「过短率 > 20%」或「平均长度 < 20 字」，
则该维度自动升级到 standard 档（跳过弱模型）。
```

这条规则让分档能自我修正，而不是写死一张表。

## 四、三种用途各自的产物消费方式

| | 原创 | 续写 | 角色聊天 |
|---|---|---|---|
| L1 文风 | ✅ 全用 | ✅ 全用 | ❌（角色不写小说）|
| L2 人物 | ❌ | ✅ 全用 | ⚠️ 只取被扮演者 + 对话对象的关系 |
| L3 世界 | ❌ | ✅ | ❌（角色不知道设定文档）|
| L4 时间线 | ❌ | ✅ | ⚠️ 只取该角色的经历 |
| 反向禁忌 | ✅ | ✅ | ⚠️ 只取「禁用解释性对白」 |

**这张表就是 `profiles.py` 该长成的样子**——现在是 `narrative_dims` 一个元组，
要改成按层声明。

## 五、落地顺序（每步可独立验证）

### 第 1 步：拆分产物结构（不动蒸馏，只改存储与消费）

- `style_narrative` 从 `{rules: {14维}}` 改成 `{L1: {...}, L2: [...], L3: {...}, L4: [...]}`
- 兼容层：读旧格式时把 `rules` 当 L1，L2-L4 为空
- `describe_narrative` 只读 L1；新增 `describe_characters` 读 L2
- 验证：旧档案能正常生成，原创模式 prompt 里零 L2-L4 内容

### 第 2 步：新增 `语序编排` 维度

- 加进 `NARRATIVE_DIMENSIONS` + `METHOD_DIMS` + 蒸馏 prompt
- 验证：抽出的规则是否描述顺序而非长度（人工读 10 条）

### 第 3 步：L2 人物层蒸馏

- 新增 prompt：按角色抽「行为倾向 / 性格底线 / 关系网 / 关键经历」
- 数据来源：图谱的角色节点 + 该角色出现过的 chunk
- 验证：拿 3 个角色，人工判断「这些描述能否防止他说出不符合身份的话」

### 第 4 步：模型分档

- `narrative_tier` 从 `full/balanced/fast`（按采样量分）改成
  `quick/standard/deep`（按模型+维度分）
- 加「过短率自动升级」规则
- 验证：quick 档跑一次，看哪些维度被自动升级

### 第 5 步：L3/L4

- L3 世界观：从图谱的 place/faction 节点 + 蒸馏
- L4 时间线：已有 `plot_timeline` 表，复用
- 验证：续写时不再依赖 RAG 检索原文来获得世界观

## 六、不做什么

- **不做「一次蒸馏出全部四层」**：L2 需要按角色逐个抽（一本书几十个主要角色），
  L1 是按 chunk 抽。混在一起会让单次调用负载过重（已有实测：14 维塞一个
  prompt 会截断）。
- **不做「弱模型跑 L2」**：人物行为倾向需要推理，弱模型会产出「他是个好人」
  这类废话。
- **不改现有 `narrative_tier` 的语义而不做迁移**：已存的档案带 `tier: full`，
  新档位名不同，要有映射表。
