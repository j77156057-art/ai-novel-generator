# 三功能拆分设计（原创 / 续写 / 角色聊天）

> 状态：**设计待审**｜作者：本会话实证驱动｜日期：2026-10-20

## 0. 这份设计要解决的问题

v2.274 五章实测暴露的根因不是 prompt 措辞，而是**同一份参考语料在生成 prompt 里扮演了互相冲突的角色**：

```
user prompt 构成（实 measurement）
  【检索上下文】4839 字  70.4%   ← 北荒刀歌原句，按「剧情相关」检索而来
  【风格样例】  1144 字  16.6%   ← 北荒刀歌原句，按采样而来
  【前情提要】   255 字   3.8%   ← 真正决定「写到哪了」
  【大纲】       276 字   4.0%
  【续写指令】   158 字   2.3%
```

后果（都是实测，不是推测）：

| 现象 | 实测证据 |
|---|---|
| 世界观被替换 | 大纲写「北漠」，正文写「北莽」16 次、「北荒」13 次 |
| 跨段重写同一场景 | 段 1/3/4/5 全部从「风沙刮过横水城城墙 + 沈砚蹲在沈铁山身后抱饭罐」开始 |
| 角色被替换 | 段 2 起凭空出现「青鲤帮」「萧烈」「阿三」，大纲里没有 |
| 摘要与正文脱节 | 段 1 摘要「得老者传授断刀武功」，正文写的是父亲咽气 |

**根因一句话：检索上下文用「本书剧情」去检索「参考书剧情」，语义上必然失败，命中的是无关章节（第 167、512 章），唯一效果是把参考书的世界观和人物灌进 prompt。**

用户提出的方案是把功能拆开，让语料在不同功能里承担不同职责。本设计把它落成可实现的规格。

---

## 1. 核心原则：语料是「作者的方法」，不是「别人的故事」

同一份参考语料，在三个功能里的可见范围必须不同：

| | 原创小说 | 续写 | 角色聊天 |
|---|---|---|---|
| **目标** | 写一个全新的故事 | 接作者的原文往下写 | 扮演某个角色对话 |
| **能看作者的什么** | 文风、写法、剧情安排、人物动机、转折设计 | 全部 + 作者没填的坑 + 角色性格 | 单个角色的性格、口头禅、经历 |
| **能否看到原文正文** | **不能**（只有抽象的方法） | 能（前后文） | 只能看该角色的台词片段 |
| **能否看到参考角色名** | **不能** | 能（本来就是续写它的故事） | 只能看被扮演的那一个 |
| **能否看到参考地名/门派** | **不能** | 能 | 不能 |
| **人名/地名处理** | 全部替换为占位符 | 原样保留 | 原样保留（但仅限该角色） |

这就是设计的分界线：**原创 = 方法可见、实体不可见；续写 = 全可见但锚定原文；角色聊天 = 单实体可见、其余不可见。**

## 2. 功能一：原创小说

### 2.1 输入

- 用户自己的 premise / outline / plot_bible（必需，已有 `_require_story_seed` 校验）
- 参考语料的**蒸馏产物**（只有方法层，不含原文）

### 2.2 prompt 里放什么、不放什么

| 蒸馏维度 | 处理 | 理由 |
|---|---|---|
| 人物描写手法 | ✅ 保留（抽象规则） | 教「怎么写人」 |
| 对白风格 | ✅ 保留（抽象规则） | 教「怎么写对话」 |
| 段落编排 | ✅ 保留 | 教「怎么切段」 |
| 场景构建 | ✅ 保留 | 教「怎么铺环境」 |
| 情绪表达 | ✅ 保留 | 教「怎么承载情绪」 |
| 节奏控制 | ✅ 保留 | 教「怎么推节奏」 |
| 世界观呈现 | ✅ 保留 | 教「怎么透露设定」 |
| 剧情编排模式 | ✅ 保留 | 教「怎么安排剧情」 |
| 伏笔与悬念设计 | ✅ 保留 | 教「怎么埋伏笔」 |
| 节拍序列 | ⚠️ 只留标签（铺垫→升温→爆发） | 内容含具体剧情，已在 v2.273 处理 |
| 高频场景模板 | ⚠️ 只留动作链 | 同上 |
| 潜台词模式 | ⚠️ 只留类型名 | 同上 |
| 文笔量化审计 | ❌ 排除 | 分块统计互相矛盾（53.0/44.0/50.2） |
| 文风漂移分析 | ❌ 排除 | 讲作者前后期变化，单次生成无可执行含义 |
| 角色声音词典 | ❌ **排除** | **这是「参考书角色怎么说话」，原创里必须换成用户自己的角色** |

**新增：角色塑造模板（替代角色声音词典）**

用户要的是「给一个人物塑造的大纲模板」，不是参考书的具体角色。做法：从 71 条角色声音**归纳出方法论**，丢弃所有角色名与台词。

```
【人物塑造模板（写作方法，不含任何参考书角色）】
一、自我介绍方式：分三类——用本名/用身份自称（如「本官」）/用诨号。
   选一类贯穿全书，不要混用。
二、口头禅：每个主要角色 1 条，且只在情绪波动时说，不要每句都带。
三、句长特征：给每个角色定一个基线（短句型/长句型/混合型），
   紧张时偏离基线。
四、语气基调：冷淡/热络/傲慢/谦卑，选一个主基调 + 一个破防时的反差。
五、关系态度：对上级/平辈/晚辈三种态度要能区分开。
六、代表台词：不提供，由用户按自己角色填。
```

这份模板是**从参考语料归纳的方法论**，不含任何专名、台词、剧情，可以安全进原创 prompt。

### 2.3 检索上下文怎么处理

**原创功能彻底移除【检索上下文】和【风格样例】两块的原文注入。**

理由：
1. `风格样例` 和 `检索上下文` 在做同一件事（提供北荒刀歌原句），重复
2. 两者加起来占 prompt 87%，把「写到哪了」（3.8%）压到不可见
3. 原文自带世界观与人物，模型无法区分「学写法」与「抄设定」

**替代方案：风格用「结构指纹 + 少量脱敏样例」**

- 统计指纹（L1 `PROXY_FEATURES`）：句长分布、对白占比、标点密度、段长分布——纯数字，已在 system prompt 里，保留
- 脱敏样例：从参考语料采样 2 段，但**把专名替换为占位符**（`【人名1】`、`【地名1】`、`【门派1】`），只保留句法结构、节奏、标点习惯

这样模型学到的是「长句怎么断」「对白怎么夹动作」，而不是「北荒王府在清凉山」。

### 2.4 验收标准

| 指标 | 阈值 | 测法 |
|---|---|---|
| 参考语料专名泄漏 | **0** | 用参考书图谱的全部角色/地名做黑名单，扫生成正文 |
| 前情提要占比 | ≥ 10% | 统计 user prompt 各块字数占比 |
| 世界观一致性 | 100% | 用户大纲里的地名/国名必须出现，且不出现参考书的 |
| 新角色占比 | 100% | 生成正文里的人物必须全部来自用户 plot_bible |
| 段长达标率 | ≥ 80% | `len(text) >= 0.8 * generation_length` |
| 跨段场景重复 | 0 | 相邻段落的场景关键词集合不得相同 |

## 3. 功能二：续写

### 3.1 输入

- 参考语料**原文**（这次可以给、也应该给）
- 用户指定的续写位置：`novel_id` + `chapter_no`（可以是「接第 N 章之后」或「重写第 N 章」）
- 蒸馏产物（全部维度，包括角色声音词典——因为这次写的就是原书角色）

### 3.2 两种模式

| 模式 | 说明 | prompt 差异 |
|---|---|---|
| **接续**（默认） | 从 `chapter_no` 之后往下写 | 给前 N 章正文（截断）+ 全部未填伏笔 |
| **重写**（用户指定章节） | 重写第 N 章，要「不脱离实际、不脱离原本文风、不脱离角色设计」 | 给第 N 章原文 + 前后各 1 章上下文 + 该章涉及的角色声音 |

### 3.3 「作者没填的坑」怎么用

这是续写功能独有的价值，但当前 `plothole` 抽取是坏的——实测 10 条全是问句碎片：

```
咋办？ / 是沈铁山？ / 你留得住吗？ / 外面……发生了什么？ / 到底什么关系？
```

**修法：伏笔必须同时满足三条**

1. 有悬念语义：包含「为什么/究竟/到底/未曾/不明/疑」等，或问句 + 主语是具体人物/物件
2. 有指代对象：不能只有语气词（排除「咋办？」「是吗？」）
3. 跨章存在：在第 X 章提出，到第 X+N 章仍未回答（原文里后续章节没有对应答案）

第 3 条是关键——**「作者没填的坑」的定义就是「后续章节没有回收」**，这需要正向全文检索验证，不能只看单章。

### 3.4 续写的锚定约束（防止「脱离实际」）

| 约束 | 实现 |
|---|---|
| 不脱离文风 | 全维度蒸馏产物进 prompt（含文笔量化审计，因为这次数字与原文一致） |
| 不脱离角色设计 | 角色声音词典全量注入 + 角色当前状态（`kg_character_state`） |
| 不脱离既有事实 | `kg_slice`（已发生事件）+ 该章之前的所有伏笔状态 |
| 不脱离世界设定 | 参考书图谱里的地名/门派/势力作为「既有设定」注入（这次允许） |

### 3.5 验收标准

| 指标 | 阈值 |
|---|---|
| 角色名一致性 | 生成正文里出现的人物，必须全部在该书图谱里 |
| 世界观一致性 | 不得出现图谱外的地名/门派 |
| 伏笔呼应率 | 至少呼应 1 条已埋未收的伏笔（不是兑现，是提及） |
| 文风偏离 | 句长/对白占比与原文偏差 ≤ 30% |

## 4. 功能三：角色聊天

### 4.1 输入

- 单个角色：`character_name`
- 该角色的：声音词典条目 + 图谱事实（经历的事件、关系）+ 原文台词片段（仅该角色说的）

### 4.2 隔离要求（「不能串台」）

这是与其他两个功能最大的不同：**必须只看见一个角色**。

| 内容 | 是否可见 |
|---|---|
| 被扮演角色的台词原文 | ✅ 最多 N 条 |
| 被扮演角色的经历（`kg_events` 里 subject 或 object 是他） | ✅ |
| 被扮演角色的关系（`kg_edges` 里一端是他） | ✅ |
| **其他角色的台词** | ❌ |
| **其他角色的性格描述** | ❌ |
| **剧情梗概 / 章节摘要** | ❌ |
| **世界观设定文档** | ❌（角色不该知道自己是小说人物） |

「串台」的两个典型表现：
1. 说出别的角色的口头禅 → 因为角色声音词典是全量注入的
2. 说出剧情走向/未来事件 → 因为前情提要和摘要被注入了

**修法：角色聊天的上下文构造函数独立，不复用 `build_context`。**

### 4.3 系统提示结构

```
你是《{novel_title}》里的{character_name}。以下是你的设定：

【你是谁】
{该角色在原文里的身份、经历摘要（从 kg_events 聚合）}

【你说话的方式】
自称：{从声音词典}
口头禅：{...}
句长：{...}
语气：{...}
（示例台词 2-3 条，用来锁定语感）

【你和他人的关系】
{从 kg_edges 取，只保留一句话描述}

规则：
- 只用第一人称
- 不知道的事就说不知道，不要编造
- 不要提到「小说」「作者」「读者」「章节」这些词
- 不要替别人说话
```

### 4.4 验收标准

| 指标 | 阈值 |
|---|---|
| 口头禅归属正确率 | 100%（不得出现其他角色的口头禅） |
| 剧情泄漏 | 0（不得说出该角色在原文时间点之后才知道的事） |
| 自称一致性 | 100% |
| 句长偏离 | ≤ 30% |

## 5. 代码落点

### 5.1 现状问题

```
build_context()              ← 三个功能共用，无法区分职责
  ├─ hybrid_search(k=4)      ← 用本书剧情检索参考书剧情，语义上不成立
  ├─ sample_style_exemplars  ← 与检索上下文重复
  └─ merged_constraint_items ← 角色/伏笔合并
build_system_prompt()        ← 只有一套，不管什么功能
  └─ describe_narrative()    ← 全维度注入，不分场景
```

### 5.2 改造方案

```
新增 app/generation/profiles.py
  ContextProfile = Literal["original", "continuation", "roleplay"]

  def build_context(db, project, profile: ContextProfile, **kw) -> dict
  def build_system_prompt(project, profile: ContextProfile, **kw) -> str

三个 profile 的差异集中在一张表里：

PROFILE_RULES = {
    "original": {
        "rag": False,                    # 不注入原文检索
        "style_exemplars": "redacted",   # 脱敏样例（专名→占位符）
        "narrative_dims": ALL_METHOD_DIMS,      # 含人物塑造模板，不含角色声音词典
        "characters_from": "plot_bible",        # 角色只来自用户
        "world_from": "plot_bible",
    },
    "continuation": {
        "rag": True,                     # 注入原文，锚定上下文
        "style_exemplars": "raw",        # 原文样例
        "narrative_dims": ALL_DIMS,      # 全维度
        "characters_from": "kg_novel",   # 角色来自参考书图谱
        "world_from": "kg_novel",
        # 情节可调，但这三样冻结（用户决策 2）：关系 / 世界观 / 既有事实
        "frozen_facts": ["relations", "world", "events_before_N"],
    },
    "roleplay": {
        "rag": False,
        "style_exemplars": "single_character_lines",  # 只给该角色台词
        "narrative_dims": ["角色声音词典"],           # 只这一维
        "characters_from": "single",
        "world_from": None,
    },
}
```

### 5.3 新增脱敏模块

```
app/style/redact.py
  def redact_entities(text, names: set[str], places: set[str]) -> str

      人名 → 【人名N】（同一人始终同一编号）

```

## 6. 实施顺序（每步可独立验收）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0-A** | `profiles.py` 骨架 + `original` profile 移除 rag/原文样例 | 五章实测：专名泄漏 0、前情提要占比 ≥10% |
| **P0-B** | 人物塑造模板（从 71 条角色声音归纳） | 原创 prompt 里 0 个参考角色名，但仍有 6 类塑造方法 |

| **P2-A** | `roleplay` profile + 路由 | 口头禅归属 100%、剧情泄漏 0 |
| **P2-B** | 重写指定章节模式 | 重写第 N 章：文风偏差 ≤30%、角色不换人 |

## 7. 明确不做的事

- **不给参考语料做「角色重命名」式的仿写**——那是另一个产品形态（同人改写），用户要的是原创
- **不保证原创小说与参考语料「完全不像」**——文风本来就是要像的，要求的是「实体不可见」
- **不让角色聊天访问剧情梗概**——这正是串台的主因
- **不在原创里保留文笔量化审计的多块数字**——它们互相矛盾，只会让模型摇摆

## 8. 已确认的三个决策（2026-10-20）

1. **原创功能保留脱敏样例** —— 保留句法结构、专名替成占位符（`【人名1】`/`【地名1】`/`【门派1】`）。
   理由：所有风格信号若只靠统计数字（`句长 60.3±20.8` 这类），实测对模型几乎无约束力
   （指令 60.3，实际生成 18.0，偏差 −64%）。必须有可读的样例承载「长句怎么断」。

2. **续写「重写第 N 章」的情节允许调整** —— 但三条硬边界不可动：
   - **人物关系**：不得改变已确立的亲属/敌友/师徒关系
   - **世界观**：不得引入原书图谱外的国名、地名、门派、势力
   - **既有事实**：不得推翻前 N-1 章已发生的事件（死亡、获得物件、身份揭露等）

   实现上：`continuation` profile 的 `plot_bible` 由「原文事实抽取」注入，
   含 `kg_events`（已发生）+ `kg_relations`（关系）+ `kg_nodes` 地名门派，
   并在 prompt 里明确标注「以下为不可更改的既有事实」。
   重写时可自由改动的是：场景内的动作顺序、对白内容、描写取舍、节奏切分。

3. **角色聊天第一期只做单角色** —— 多角色需要处理「A 看不到 B 的内心」这种会话级信息隔离，
   复杂度成倍上升，不做进第一期。接口预留 `character_name: str`（而非 list），
   将来扩展为多角色时改为 `character_names: list[str]` + 每人独立上下文。
