# 角色对话的三处毛病：角色清单混进不是人的 · 切换角色还在一个框 · 问性格答跑偏

> 2026-10-28。用户在使用《北荒刀歌》（xz.txt，990 章）项目时提的三个问题：
> ① 项目角色里混进很多不是人的（水下/水门/别让/清楚…）；
> ② 切换角色以后还是在这个对话框；
> ③ 问「老夫子性格怎么样」，答得不好，还多回答了赵长安。
>
> 本地那次冒烟运行的库里留有用户那次会话的原文（`roleplay_messages` #1–#8），
> 本文所有数字都来自它，不是估的（那个库是运行产物，不随仓库分发）。

## 1. 问题①：角色清单混进不是人的

### 1.1 根因不是「判断失误」，是**取错了数据源**

清单端点 `routers/roleplay.py::list_characters` 的「这个项目里的角色」取自
`get_reminders(db, project.id, source="generated")` 的 `character_constraints`，
而那是从 **`kg_nodes`（source=generated, type=character）** 读出来的。

实测 p1：

| 来源 | 条数 | 内容 |
|---|---|---|
| `kg_nodes`(generated, character) | 32 | 沈砚 / 沈铁山 / 周郎 **+ 水下/水门/水中/水面/边缘/颜色/后面/怀里/左手/车上/别回/别碰/别让/任凭/清楚/冷声/苍白/焦黑/乌木/乌篷/后来/沈砚握/东门临…** |
| `kg_entities`(kind=character) | 19 实体 + 28 别名 | 沈砚 / 沈铁山 / 周郎中 / 老卒 / 守门人 / 船夫 / 柳惊寒 / 瘸腿男人 / 神秘女子 … **全是人** |

⇒ 噪声**全部**来自 `kg_nodes` 那一层：它是**抽取器的原始产物**（模型把「水下」「边缘」
这类**非人称谓**也建成了 character 节点，mentions 高达 47 次）。
而 `kg_entities` 是**归一化后的实体表**（canonical_name + aliases + 合并），
里面 19 个实体**个个是人**。

**同一份数据，两个视图。** 清单端点挑了脏的那个。

### 1.2 参考组（声音词典）也有噪声，但形态不同

p5《长夜司》的 52 条声音词典条目里，24 条不是人：
能力 / 危险 / 相应 / 白银 / 封印 / 成员 / 相当 / 简单 / 怀疑 / 成功 / 利用 /
曾经 / 解决 / 程度 / 单词 / 阴影 / 房屋 / 古老 / 唐泰 / 马车 / 霍然 / 查拉 …

看它们的 rule 原文就知道是什么了：

```
相当： 自称「我」 口头禅「相当、不简单」 句长长短句 语气谨慎、评价式、低声判断
       …代表台词：「这大男孩处理事情的手段相当成熟相当谨慎，比许多二十」
```

⇒ 蒸馏时，**作者对读者说话**的那几段（"面对读者时语气亲切随和""求月票""请假"）
被当成了某个角色的说话样本，**角色名是抽错的**（把台词里的「相当」当成了人名）。

### 1.3 试过的判据（都不够好，如实记下）

| 判据 | 在 p5 参考组上的表现 |
|---|---|
| 名字紧贴说话动词（gap0） | 噪声命中 21/25 —— 「简单道：」「霍然」都中招 |
| 行首 + 引号对白 | 噪声命中 25/25 —— 「白银道：」也算 |
| KG 参考图命中 | 噪声全部命中（KG 图本身也脏） |
| 作者语汇（读者/月票/请假…） | 只剔掉 9 条（漏 15 条） |
| 「代表台词说话人 == 条目名」 | 噪声判对 20/24，但**真人被漏 11 个**（亚当/戴里/鲍勃…） |

⇒ **纯机械判据无法可靠区分**「人名」与「抽错的词」，而且误伤代价大
（把真人从清单里删掉，用户就选不到他了）。

### 1.4 修法（两条，方向不同）

**A. 项目组：换数据源 —— 改用 `kg_entities`**（治本，且零误伤）

- 19 个实体 + 28 个别名，**个个是人**（含别名「沈砚的父亲」「戴斗笠的船夫」）。
- 用户看到的不再是 `kg_nodes` 的抽取碎片。

**B. 参考组：降噪 + 折叠**（治标，保守）

- 用「作者语汇」判据先剔掉一批（9 条）——**只剔确定的**，宁可留噪声也不误伤真人。
- 参考组本来就是**折叠的**（"展开参考书里的角色（N）"），且带搜索框。
- 再加一句：清单里显示**条数**，让用户知道折叠区有多大。

**明确不做**：不引入「人名合法性」的启发式白名单/黑名单 —— 实测误伤率太高，
且会把「上一轮刚做完的人写个性」这类能力卡死。

### 1.5 界面上怎么表现

- 「这个项目里的角色」只放**确认是人**的（`kg_entities` 的 canonical + 别名）。
- 别名**不单独占一个按钮**（否则「沈砚的父亲」「他爹」会各占一格），
  折叠成「沈砚（又名 小子 / 沈守将 / 沈将军）」的样子。
- 参考组维持折叠 + 搜索。

## 2. 问题②：切换角色以后还是在这个对话框

### 2.1 根因：前端 `messages` 是一维数组

`frontend/src/components/RoleplayPanel.vue`：

```ts
const messages = ref<RoleplayMessage[]>([]);   // 一维，所有角色混在一起
```

- `send()` 把新消息 `push` 到**同一个数组**；
- 点别的角色只改 `character` 这个 ref，**不清空、不分组**；
- 于是「问沈砚 → 切到白狐儿脸 → 问」三段问答在界面上连成一段。

用户说「切换角色以后还是在这个对话框」——**他看到的就是这个**。

### 2.2 修法

- 消息**按角色分组**渲染：每个角色一段对话，标题写清「和 XX 的对话」。
- 切换角色时，**自动滚到/展开该角色那一段**（而不是留在别的角色的段落里）。
- 后端 `GET /roleplay/messages` 已经支持 `character` 参数 ⇒ 前端**按角色分别拉**，
  一次拉全部（`character` 不传）后在前端分组即可，不用多次请求。

## 3. 问题③：问「你的性格怎么样」，答跑偏还多提赵长安

### 3.1 现象（库里 #8 原样）

```
问：你的性格怎么样
答：老夫子么，读书人的脾气，未必好，却也不是一味蛮横。……
    至于赵长安那厮……老夫子看不惯，却也认得他的本事。……
```

三个症状：**第三人称自称**（"老夫子么"）、**像人物小传**、**多聊了赵长安**。

### 3.2 根因（逐条实测）

**(a) 证据块里没有「老夫子」的第一人称材料 —— 全是别人在谈论他。**

`gather_evidence` 给 #8 的 6 段证据，标注是这样的：

| 段 | 标注 | 实际内容 |
|---|---|---|
| 1 | 他亲历 | 苏禾视角，**老夫子只在别人台词里被提到** |
| 2 | 他亲历 | 苏禾视角，老夫子开口说「要搬家了，往南走」 |
| 3 | 他在场听到 | 铁匠铺，老夫子训苏禾 |
| 4 | 他在场听到 | **另一个老头**（程白霜/薛宋官），跟老夫子无关 |
| 5 | 他在场听到 | 「赵老夫子跟某个白衣男达成盟约」 |
| 6 | 他亲历 | 老夫子与赵长安对话 |

⇒ 「亲历」判据（`_speaker_lines`：名字紧贴说话动词 / 行首带引号）本身**没错** ——
第 1 段里老夫子确实开了口。但**整段 952 字里老夫子只占两三句**，
其余全是苏禾在说话、旁白在描述。模型看到的是「别人在讲老夫子」的文本，
于是**用第三人称谈论他**。

**(b) 角色档案缺席 —— `profile_block` 长度 0。**

实测：`style_narrative["characters"]` 在 p1 里**一条都没有**（蒸馏时没产出这一层），
所以 `_character_profile_block` 返回空串。模型手里只有：
- 一句「你现在扮演《北漠断刀》里的老夫子」
- 一段声音描述（自称/语气/句长）
- 6 段别人在谈论他的原文

**没有任何「他是什么样的人」的档案。** 模型只能自己总结 ——
总结出来的当然是「老夫子么，读书人的脾气……」这种**第三人称人物小传**。

**(c) 提示词没禁「总结自己」。**

`SYSTEM_TEMPLATE` 规矩 4 写的是「不要总结自己的性格」——但用户问的**正是**「你的性格怎么样」。
模型被这条规矩一压，就走了「用第三人称点评一下」的路子（既回答了问题，又没「总结自己的性格」，
还在规则 2「不要第三人称转述」的边缘）。

**(d) 「多回答赵长安」是证据 6 带来的**：那段里赵长安在跟老夫子说话，
模型顺着复述了「至于赵长安那厮……」。

### 3.3 修法

**(a) 证据块说清它的性质 + 列出「他亲口说过的话」。**

先说一个**走不通的路**：原本打算把证据**裁剪**成「他自己开过口的行」。
但「谁在说」这个判据（名字紧贴说话动词 / 行首）在真实文本上试了**九版**，每版都被新反例推翻：

| 反例 | 为什么难判 |
|---|---|
| 「苏禾斜眼看了…横眉竖眼的老夫子，无奈道：」 | 「老夫子」在句中是**宾语**，说话的是苏禾 |
| 「老夫子怒极，颤声道：」 | 逗号是**并列谓语**，说话的是老夫子 |
| 「老夫子一拍桌子，道：」 | 逗号是**插入语**，说话的是老夫子 |
| 「赵长安…赵北山小心翼翼赔笑道：」 | 行以赵长安开头，说话的是赵北山 |
| 「头上粘上几根马草的老周挠挠头道：」 | 「的」是**定语**，老周是说话人 |

而且版本之间真人命中量在 **563~4766 行**之间大幅摆动 ⇒ 对写法太敏感，不是可靠判据。
⇒ 放弃裁剪，改成：

1. 证据**整段保留**（裁剪会把他人的台词混进来，实测更糟）；
2. 证据块开头**说清它的性质**：「这是**书里的片段**，不是你的传记。
   大多数里面是**别人在说话**、关于你的话；只有引号里**属于你的那几句**才是你亲口说的」；
3. 「他亲历」的段落**额外列出他名字所在行的引号**（判据只有「名字与引号同行」
   这一层机械规则，**不需要判断谁在说**）。

实测（#8）：6 段共 6297 字 → 挑出 17 句他名字所在行的引号，老夫子的原话就在里面
（「卖技艺给贩夫走卒，成何体统！」「我西蜀三百万户，谁不是做了二十年的丧家之犬？！」…）。

**(b) 提示词改两处。**
- 规矩 4 从「**不要总结自己的性格**」改成
  「**用第一人称「我」自称，不要在回答里点评自己**（不写「老夫子么」这种人物小传）。
  对方问你是什么样的人 ⇒ **用你亲口说过的话**回答，一两句即可；实在说不上来就说「这个我说不好」」。
  —— 旧那条把「问性格」这个问题变成了死路，模型只好绕道第三人称。
- 规矩 5 补一句「**不要替别的人说话，也不要顺带评价别的人**」（用户反馈里多回答了赵长安）。

**(c) 来源标注加第三档「只是被提到」。**
原来只有「亲历 / 在场听到」两档 ⇒ 「文里写到他」与「他在场」混在一起。
现在三档：亲历 / 在场听到 / **只是被提到**（不代表他在场，也不代表他知道）。

### 3.4 真跑结果（真实通道 MiniMax-M3，同一个问题）

| | 修前（#8） | 修后（#9） |
|---|---|---|
| 开头 | 「**老夫子么**，读书人的脾气，未必好…」 | 「**我嘛**，脾气古板了些。爱拿圣贤道理劝人…」 |
| 提到别的角色 | 赵长安、苏禾 | 无 |
| 长度 | 175 字 | 73 字 |

## 4. 验收项

1. 角色清单端点返回的「项目组」**没有一个不是人的**（对照 `kg_entities` 名单）。
   —— 实测 p1：修前 32 条（30 条是「水下/水门/边缘」这种），修后 19 条，个个是人。
2. 「沈砚的父亲」「他爹」这类别名**不单独占一格**（折叠显示）。
   —— 实测：「沈砚＝小子」「沈铁山＝沈守将 / 沈将军 / 沈砚的父亲」。
3. 切到另一个角色后，问答**分属不同段落**，界面上能一眼看出在跟谁说话
   （输入框占位符会变成「问「XX」一件事…」）。
4. 问「你的性格怎么样」，回答是**第一人称短答**，不含「XX么」「XX是…」这种第三人称点评。
5. 回答里**不出现**用户没问到的角色名。
6. 证据块**说清它是片段不是传记**，并列出「你亲口说过的话」。
7. 全量 `python -m pytest tests/` 0 failed；前端 `npm test` + `npm run build` 通过。
8. 真跑一次：问「老夫子性格怎么样」，肉眼判「像不像老夫子在说话」。

## 4.5 顺带查出的第四个问题：「故事进行到第几章」**根本没接上**（剧透）

用户项目 #1 填了「第 1 章」，实测问「老夫子性格怎么样」，证据来自
**第 290 / 293 / 294 / 791 / 981 章** —— 角色知道了用户还没读到的剧情。

**根因**：`gather_evidence` 直接调 `retrieve_for_character`（只查参考书、**没有章节上限**）；
项目里的 `reference_cutoffs` 只被**续写路径**用，角色对话这条路径没接。
界面上还写着「没有边界就等于整本不可见」，实际是**整本都给**。

**修法**：

1. `retrieve_for_character(..., max_chapter=N)`：只检索第 N 章及以前；
2. `gather_evidence` 按项目的 `reference_cutoffs` 取上限，**没有边界的书整本挡掉**；
3. `character_timeline`（生平时间线）同样受约束 —— 越界的事件同样是剧透；
4. **证据分流**：改走 `retrieve_for_character_auto`（参考书角色 / 原创角色分流），
   边界**只**加在参考书那一侧 —— 原创角色（沈砚）的证据来自**用户自己写的正文**，
   不该被参考书的边界挡住；
5. **零证据时不调模型**（服务端兜底）—— 实测边界=第 1 章时模型仍答出
   「他曾在我门下听学…」，那是它**训练里的世界知识**，不是书里的证据。

**真跑结果**：

| 边界 | 证据 | 回答 |
|---|---|---|
| 第 300 章 | 6 段（第 290~295 章） | 「认得。靖北世子赵长安，我自是认得。」 |
| 第 1 章 | **0 段** | 「……这我倒说不上来。」+ 提示往后调边界 |

---

## 5. 边界（明确不做）

- 不做「人名合法性白名单」—— 实测误伤真人的代价大于留噪声。
- 不重写已有 KG 数据（`kg_nodes` 的碎片**留着**，只是不再拿它当清单）。
- 不改蒸馏判据（那会动到全部 16 个维度）。
- **不判断「谁在说」**（九版都失败，见 §3.3a）—— 说话人判据只保留原版，
  继续只用于**来源标注**，不再承担裁剪职责。
