# 验收指标

> **这份文档解决什么**：把「不崩 / 不漂移 / 不遗忘 / 像人写」四个目标，翻译成**可机检的指标 + 有出处的阈值 + 失败后做什么**，并给出一条能重复跑出来的命令。
>
> **这份文档不解决什么**：它不能替你判断文笔好坏。凡是机器测不了的，这里一律标「未测 / 需人工」，并给出可操作的盲评流程 —— **不编数字**。

跑法（离线、无网络、约 10 秒）：

```bash
cd backend
python verify_acceptance.py --segments 30      # 验收窗口
python verify_acceptance.py --segments 80      # 饱和验证（漂移判定需要更长窗口才有意义）
```

**真模型跑**（2026-10-30 新增，补「文笔 / 漂移」这两轴的机器侧证据 + 盲评材料）：

```bash
cd backend
python verify_acceptance_real.py --segments 30 --out out/acceptance
```

⇒ 真模型跑的结果与边界见 **`docs/real-model-acceptance.md`**（含抓到的三个真 bug 与修法）。

## 1. 四轴与它们的可判定性

| 轴 | 含义 | 谁来判 | 指标 |
|---|---|---|---|
| **不崩** | 人物/物品/境界/时间不矛盾 | 机器 | 规则哨兵错误级告警数（`verify_sentinel.py`，96 断言） |
| **不遗忘** | 第 N 段仍记得第 1 段埋的事 | 机器 | 前情覆盖留洞数 / 峰值漂移 / 账本事实是否仍在注入里 |
| **不漂移** | 不跑题、不丢主线、支线有收束 | **人**（机器只能证注入侧没退化） | 注入覆盖率（机器）+ 盲评判据（人） |
| **像人写** | 有参考作者文风，不是 AI 腔 | **人** + 机器辅助 | 三个可计算特征对照人类基线 + A/B 盲评 |

**为什么「不漂移 / 像人写」不能交给机器**：这两件事的判据是「读起来像不像」，而离线路径的正文是固定模板 —— 在模板上测文笔等于测模板。机器能做的是**排除法**：证明「注入侧没退化」（前情没留洞、约束还在），以及给出**可对照的量化特征**。剩下的必须由人看。

## 2. 指标定义

### 2.1 重复率（段间）

相邻两段正文的 **3-gram Jaccard 相似度**：`|A ∩ B| / |A ∪ B|`，先剥掉空白与换行。

越接近 0 越好。取 3-gram 而不是整句，是因为中文网文允许套语复用（「他笑了笑」），但**成段的字面重复**是明确的退化信号。

### 2.2 比喻密度（每百字）

`像…`（后接 1–12 字且不在标点处断）/ `如同` / `宛如` / `仿佛` / `彷佛` 的出现次数 ÷ 正文字数 × 100。

AI 腔最稳的硬特征之一：真人写得再花，也不会每百字挂一个比喻。

### 2.3 句长变异系数

按 `。！？…` 切句（长度 ≥ 4 的句），算句长的 `pstdev / mean`。句数 < 5 时返回 `None` 不参与判定（不硬算噪音）。

**方向是「越大越像人」**——AI 腔的句子长度往往过于整齐。

### 2.4 前情注入：覆盖与预算

来自 `build_context()` 的 `prior_report`：

- `uncovered`：**必须恒为空**。非空 = 某几段的剧情永远不会进入后续上下文，模型不会报错，只会悄悄忘掉。
- `chars` / `budget_chars`：预算是**软目标**，不是硬上界（见 §3.4）。
- `over_budget`：超预算必须如实上报 —— 信号说谎比超支本身更糟。

### 2.5 账本事实留存

末段注入的约束里是否仍含种子的角色/伏笔。**注意**：`plot_bible` 里的事实是静态注入，永远在；真正被压的是 `get_reminders()` 那条**账本 → 注入**的链（见 §6）。

### 2.6 规则哨兵

见 `verify_sentinel.py` 的模块 docstring：五条规则、四条已实现、`item_owner_conflict` 与 `alias_split` 默认沉默且**在前端显式标出**。

## 3. 阈值从哪来

**不拍脑袋**：先在**真实网文**上跑同一套算法，取人类分布的分位数当阈值。

### 3.1 基线实测

语料：真实网文 / 每段 3000 字，切法与 `verify_sentinel.py` H 段一致 —— 两处口径必须一致，否则「基线」和「被测对象」不是一回事。

| 指标 | 中位 | 分位 | n |
|---|---|---|---|
| 相邻段 3-gram Jaccard | 0.0336 | p90 = **0.0577** | 384 |
| 比喻密度 / 百字 | 0.0733 | p90 = **0.2248** | 387 |
| 句长变异系数 | 0.6327 | p10 = **0.5352** | 387 |

> ⚠️ **这张表是「某一批语料」的数，不是常数。**
> 基线换一批，阈值必须重算 —— 实测同一批产出对**五个**不同基线：
> 比喻 p90 从 0.115 变到 0.407，「句长偏齐」的结论**被推翻**（23/30 → 3/30 → 0/30）。
> ⇒ 跑之前先确认 `ACCEPTANCE_CORPUS` 指向哪本书，并**在多个语料上复现结论**。
> 详细对照见 `docs/real-model-acceptance.md` §3.2.1。

### 3.2 阈值

| 指标 | 阈值 | 来源 | 方向 |
|---|---|---|---|
| 重复率 | ≤ 0.0577 | 人类 p90 | 越小越好 |
| 比喻密度 | ≤ 0.2248 | 人类 p90 | 越小越好 |
| 句长 CV | ≥ 0.5352 | 人类 p10 | 越大越好 |

取 p90 而不是中位，是刻意放宽：这是**报警线**不是**优秀线** —— 真人自己也有 10% 的段落比这更"重复"，阈值卡到中位会让正常产出天天报警，最后没人看。

### 3.3 基线本身的自检

`verify_acceptance.py` 的 A2 断言「真人相邻段重复率中位 < 0.05」。这不是循环论证：如果切分口径写错（比如把整本当一个段），这个数会趋近 1，断言立刻红。

### 3.4 前情预算是软目标（本轮实测澄清）

`compose_prior` 的代码注释写得很明确：**「覆盖优先于预算，照留并标记」**。

丢一段就会在上下文里留一个永久的洞，所以它宁可超出预算并置 `over_budget=True`。

实测（80 段，预算 600）：

```
逐 8 段窗口峰值：637 → 857 → 986 → 986 → 986 → ... → 986
段  1- 8   +37     段 17-24  +386     段 33-80  +386（恒定）
段  9-16   +257    段 25-32  +386
```

**结论分两半，都得说清：**

- **不漂移**：峰值在第 17 段饱和在 986，此后 60 多段一动不动 → `engine.build_context` 那句「比例固定，不随段数漂移」**成立**。
- **稳定超支 1.64×**：这是「不留洞」的既定代价。它被 `over_budget` 如实上报，前端有超标记与问题项，**不是静默的**。

> **这里有一条被实测推翻的假设，留在文档里当路标**：验收脚本初版写的是「前情注入从不超预算」，实测红了。当时第一反应是「发现了漂移」，于是把窗口从 30 段拉到 80 段 —— 结果峰值是**饱和**的，漂移不存在。真正的问题不是漂移，是**我那条断言要求了一个系统刻意不提供的保证**。断言已改为守两个真契约：`B3a` 峰值不漂移、`B3c` 超支信号必须诚实。
>
> 教训：**「红了」不等于「有 bug」，先确认断言本身是不是在要求一件没人承诺过的事。**

## 5. 人工盲评流程（机器测不了的两轴）

**目的**：判断「像不像人写」与「有没有跑题」，且**不让评者知道哪段是谁写的**。

### 5.0 盲评包必须先过自检（否则不算盲评）

盲评包不是「把两段文字摆出来」就成立。**判据在生成时就自动跑**，
不合格的包会被标成「不是盲评包」，且 `verify_blind_eval.py` **拒绝出统计结论**
（退出码 2）。六道闸门：

| 闸门 | 为什么必须有 | 怎么查 |
|---|---|---|
| **两侧同等脱敏** | 人类侧若取自一部知名作品，人物名一出来就等于举牌 | 两侧专名都换成**等长占位符**（`＃＃`），且用**同一套**流程：召回 → LLM 判定 → 残片剔除 → 替换 |
| **取样口径对称** | 我们原来取「段首 400 字」、人类取「随机 400 字」，引号密度差 2.3 倍 —— **取样位置本身就是泄露线索** | 两侧都随机取 |
| **版式归一** | 盗版站文本每段带四个空格缩进、章节标题单独一行（「第74章 报复」会被拼进 400 字窗口中间），我们这侧两样都没有 ⇒ **也是非对称特征** | 两侧都过同一个 `normalize_for_blind`：去缩进、去章节标记行、统一段落分隔 |
| **题材/年代一致** | 一侧古风武侠、一侧现代都市，评者不看内容就能分出哪边是哪边 | 年代标记词**份额 + 命中数**判据，**整包级别**（逐 400 字样本只检出 2/6） |
| **脱敏痕迹对称** | 两侧占位符密度差一大截，数一数井号就知道哪边是出版物 | 占位符密度（每百字井号数）两侧对比 |
| **题面级专名复查** | 逐词判定**会漏** —— 实测一次判定批次撞上 `max_tokens` 被截断，整批 100 个候选被记成「不是专名」，真名原样留在题面里 | 脱敏后把**成段题面**再交给模型「只报还是专名的词」，挑到的补遮后重查（≤3 轮）；清不干净 ⇒ 整包作废、题面不发 |

六条实测结论，**别凭直觉改回去**：

1. **滑窗猜人名是错的** —— 会把「王爷公子」这类词当成名字。
2. **只靠频次阈值也不行** —— KG 抽取器会把三字名截断（「赵长安」→「赵长」），且噪声与真名频次重叠。
   现在的做法是**两套召回合并**（整本高频 PMI + 片段级形状候选）再交给 LLM 判定。
3. **年代判据不能用绝对密度阈值** —— 实测我们侧现代密度 0.0438、阈值 0.05 就**漏检**了一次。
   现在用「份额 + 命中数下限」，并且在**全文**上再判一遍。
4. **盗版水印要按整行剥** —— 行内正则会把正文里的「最新章节」也吃掉（实测削掉 7% 正文）；
   只删「整行都是样板」的行（实测只删 30 行、-0.02%）。
5. **判定失败不能当成「不是专名」** —— 「没判出来」和「判出来不是」必须能分开：
   脱敏链路把前者当**整包作废**（fail closed），判定缓存**不带版本号就整份作废**。
6. **脱敏判定批次要小（30）** —— 逐词判定的回包是「每个词一个 JSON 对象」，
   批次越大回包越长，越容易被 `max_tokens` 拦腰截断；而截断 = 整批判定消失。

### 5.1 取样

- 从同一项目取 **N 段**（默认 6，可用 `--snips` 调）：默认口径是首 2 段（第 1、3 段）、
  中 2 段（第 15、16 段）、尾 2 段（第 29、30 段）。
  *为什么跨位置*：漂移与文风退化都发生在长跑里，只测开头等于没测。
  *题数 > 6 时*改成在整条长跑上**均匀铺开**（首尾必留）——
  否则十几道题都落在同一段区间里，评者其实在评同一批文本，样本量是假的。
- 每段截 **400 字**（超长会让人疲劳，判定质量下降）。
- 对照样本：从**同题材**参考语料里随机取 400 字人类片段 N 条。
- **多本混采时轮转取书**（不是随机抽）：N 题从 2 本书里取，各 N/2 题。
  随机抽可能 5 题来自同一本 —— 评者认出那一本，就等于认出了大半。

人类侧语料与**基线语料可以不是同一批**：
基线要「一份能代表当代网文的语料」，盲评人类侧要「同题材 + 混采几本」，诉求不同。
用 `--human-corpus <目录>`（或环境变量 `BLIND_HUMAN_CORPUS`）单独指定，
给目录 = 多本混采；缺省才用基线语料。
每题的人类侧出处记在密封文件里（`items[].human_source`），不进题面。

### 5.2 随机化（关键）

每一对（本项目产出 / 人类片段）用**抛硬币**决定谁当 A、谁当 B。映射写入单独的密封文件：

```
sample_id, slot_A, slot_B      # 例如 s01, human, ours
```

评者**只看 A/B**，不看密封文件。这样连我们自己也无法无意识引导。

### 5.3 判据（每题二选一，不许"差不多"）

1. 哪一段**更像人写的**？
2. 哪一段的**主线更清楚**？
3. 哪一段**有 AI 腔**？
4. 你猜**哪一段是 AI 写的**？（这题用于交叉检验前 3 题的自洽性）

### 5.4 通过线（可算，不靠感觉）

- 判定数 `n = 评者人数 × 题数`，**n ≥ 18 才有统计力量**。两条等效的路：
  - **多请人**：≥3 人 × 6 题（默认口径）—— 判断之间真正独立，p 值最可信；
  - **多出题**：1~2 人 × 18 题（`--snips 18`）—— 省事，但**同一个人的多次判断不独立**
    （口味是相关的），符号检验会把 p 值算得偏乐观 ⇒ 结论只能说「倾向」。
- 记「AI 段被判为更像人写」的成功次数 `k`。
- **二项检验**：n=18 时，`k ≥ 6` 即不能拒绝「评者只是随机猜」（p ≥ 0.048）；`k ≤ 5` 则 p < 0.05，判定**可被识别为 AI → FAIL**。
- 人数不够时脚本会明确打「这个检验没有足够力量」⇒ 只能当**观察**，不能当结论。
- 漂移题：**≥2 人标出同一段号** → 该段进人工复核，不直接判失败。

### 5.6 人类侧语料的要求（会决定这个包有没有意义）

人类侧**必须与我们的产出同题材、同年代**，而且**最好是没多少人读过的作品**：

- 取名篇（如一部畅销武侠）做人类侧，评者可能**凭印象认出文风**——
  脱敏只能挡住名字，挡不住「这段我读过」。
- 取跨代语料，量的其实是**年代差**，不是文风差 ⇒ 工具会直接判「不是盲评包」。
- 取我们自己写的 demo（模型生成的样例）当人类侧 ⇒ 那不是人类侧，是**左右手互搏**。

**怎么才算「准备好了」**（实测过）：用**现代都市题材**的真人网文做人类侧，
四道闸门就能全过（实测两本都 `blind=true`）：

- 题材/年代一致 ⇒ 两侧都是「现代」，不再是两个世界；
- **盗版站水印按整行剥**（不是行内正则 —— 会吃掉正文，实测削掉 7%）；
- **版式也要归一**（去段首缩进、去章节标记行）：盗版站文本每段带四个空格缩进、
  章节标题单独一行，我们这侧两样都没有 ⇒ 那也是「非对称特征」。

版权正文只在本机投放，**不进仓库**。

## 6. 扩展性：账本增长 → 提示词膨胀（本轮实测）

**这一节是「不遗忘」真实的失败面，量出来的，不是推的。**

`get_reminders()` 按项目 + 类型**全量**取角色与未填坑，没有 LIMIT / 排序 / 相关度过滤。

### 6.1 真实语料上的累积速率

《夜巡录》381,884 字 / 128 段，逐段跑抽取并累计去重角色名：

```
第  20 段 →  25 个      第  80 段 →  86 个
第  40 段 →  45 个      第 100 段 → 104 个
第  60 段 →  68 个      第 120 段 → 123 个
```

≈ **1.02 个/段**，线性累积。

### 6.2 灌进提示词后的实测斜率

| 账本角色数 | system 提示字数 |
|---|---|
| 10 | 728 |
| 30 | 962 |
| 60 | 1,310 |
| 100 | 1,770 |

实测 **11.6 字/角色**。外推：写到第 300 段时账本角色约 307 个，**仅角色清单就约 3,560 字** —— 每一段都重复一遍。

### 6.3 为什么这条必须修

1. **它绕过了前情那套预算裁剪** —— 角色清单不在 `prior_blocks` 里，预算管不到它。
2. **每段都把这些角色声明为「本段锁定约束」** —— 100 个角色全"锁定"，等于没有约束。
3. **名字表是脏的** —— 抽取侧会把 `冷笑` / `连忙` 这类动词短语当角色名（`verify_sentinel.py` H 段已披露），所以实际注入的清单比 123 更长，而其中一部分根本不是人。

### 6.4 修复（已落地）：硬封顶 + 相关度排序

**处置**：`get_reminders()` 增加 `top_k` 封顶（默认 `REMINDER_TOP_K = 50`），按相关度排序后截断；生成路径用默认封顶，人工查阅的 API（`GET /projects/{id}/reminders`）传 `top_k=None` 保持完整。

- **角色**：按 `最后出场段号` 降序、`提及数` 降序 —— 把当前活跃阵容顶上来，长尾旧角色自然落出清单。
- **未填坑**：按 `开坑段号` 降序 —— 最近开的悬疑优先提醒。

阈值不拍脑袋：§6.2 实测清单**内**斜率 11.6 字/角色，封顶 50 ⇒ 角色清单贡献 **≤ ~580 字**，约等于一个前情预算块（600），且随账本规模**饱和**而非增长。

**修复后实测**（`_probe_reminders_bound.py`，同 §6.2 探针项目；`reminders 角色` 列即实际下发的实体数）：

| 账本角色数 | reminders 角色 | system 提示字数 |
|---|---|---|
| 5   | 5   | 682   |
| 20  | 20  | 892   |
| 50  | 50  | 1,312 |
| 100 | 50  | 1,312（封顶，较未修 1,770 收敛）|
| 200 | 50  | 1,312（增量 0，饱和）|

`verify_acceptance.py` C 段（真实语料）交叉验证：封顶前斜率仍 11.7 字/角色（清单内线性，本就不是 bug），封顶后增量 **+0 字**；`C2a` 断言实体数 ≤ 50、`C2b` 断言超 K 后增量 ≤5 字，均 PASS。

## 7. 失败处理矩阵

| 轴 | 触发条件 | 处理 |
|---|---|---|
| 不崩 | 哨兵 `err > 0` | 先看 `evidence` 里的前段原文：是模型真矛盾还是抽取误报。**误报改规则并加进 `verify_sentinel` 的负例**；真矛盾才回退该段重写 |
| 不崩 | 人判断为误报 | 按「少报优于误报」收紧规则；**每一类误报都要落成一条断言**，否则下次还会回来 |
| 不遗忘 | 前情覆盖留洞 | **停发**。先修 `compose_prior` 的覆盖证明 —— 留洞 = 某些剧情永远不进上下文，写下去必然自相矛盾 |
| 不遗忘 | 峰值开始漂移（B3a 红） | 查 `spine_covers` 是否失效（L3 没形成 → 所有卷都被"照留并标记"）。**不得靠截断正文解决**（截断 = 新的洞） |

| 不漂移 | 主线相关度下降（盲评） | 先查大纲注入是否被前情挤掉；再查 RAG 检索是否退化成同质召回 |
| 像人写 | AI 味指标越界 | 对照人类基线**定位是哪个特征越界**（比喻/句长/升华结尾），改提示词约束后再测。**不做无对照的「感觉更好」** |
