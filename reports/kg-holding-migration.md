## 2. 方向约定

**统一写成「持有者 → 物品」，只此一种，全表不混用。**

- 表字段是 `owner_*` + `item_name`，方向本身就是「谁持有物」；按「物品 → 持有者」写会让`owner_id` 落在物品上、和 `item_id` 打架。
- v3 索引里 `owns` 有 11 条把物品放在 `from`、持有者放在 `to`（`item_is_from`），这是显示层方向反转，不是语义反转。统计时统一取「item 端 = 物品，另一端 = 持有者」。这 11 条在判定表里按归一后的方向展示；其中最终判为转持有的 3 条，`reason_code` 记 `dir_normalized`，其余 8 条先命中别的错因（批次、构成物等），不重复标。
- `belongs_to` 原始方向是「物品 → 归属方」，与 `owns` 相反；判定表里同样翻成「持有者 → 物品」。

## 3. 分组判据

判据只问三个问题，按顺序问，命中即停。它只看**名字形态 + 同章回指**，不看情节好坏，所以能落到每一条上，不需要事后挑。

**Q1 它是「一个个体」还是「一类/一批/一份」？**

能不能在跨章时用「这/那/它」回指同一个东西。不能的进 **B 组**：

| 子类 | 判据 | 本轮名单 |
|---|---|---|
| 物资批次 | 名字带数量/量词，或整批转让 | 税银、银票、碎银、假银、假银子、黄金、黄金千两、一百两银子的彩礼、五百匹丝织品、五口棺材、绸缎、桐油、滚石 |

**Q2 它是实体物，还是人 / 机构 / 场所 / 工程 / 阵法 / 类别名？**

不是实体物的进 **C 组**：银锣、金锣（官职/腰牌）、朱成铸（人名）、地宗（宗门）、火药厂（作坊）、永镇山河庙（建筑）、化生井（井）、大黄山硝石矿（矿脉）、桑泊封印 / 桑泊封印阵法 / 封印阵法（阵法）、八卦阵（阵法）、很重要的物品（占位指代）、周旻遗留密码（信息）、法器（类别名）。

**Q3 剩下的进 A 组**：具名、可单独转手、正文有连续持有叙事的单体（宝物、兵器、书信、身份物、坐骑、佩饰）。

三问都过才是 A 组。这样「税银 15 万两」在 Q1 就被拦住，「鸡精/香菇/老母鸡」在 Q1（消耗品）与第 5 节第 4 条（持有者是物品）被拦住，都不会进持有史。

## 6. 多持有者物品与连续段

- **跨章转手**：同一件东西换了人，且中间没有同章冲突 → 直接建段，前段 `valid_to` = 后段 `valid_from`。

## 9. `located_at` 42 条：哪些像「存放地当持有」，为什么不算

## 13. 分组判据（可复算版）

### 13.1 先说清楚：这不是打分，是闭集名单 + 两条结构检查

没有分数、没有权重、没有阈值。每条边只跑下面 4 步，命中即停，因此任何人拿同样的 269 条边跑一遍都会得到同样的 A/B/C。

```
for edge in 269_edges:
    name = 归一后的物品名
    if 命中 C 名单:                      group = C
    elif 命中 B 名单:                    group = B
    elif 名字是单数但正文说“总共 N 份”:   group = B   # 唯一需要读正文的一步
    else:                                group = A
```

### 13.2 用的信号（6 个布尔判断，全部落在名字上）

| 信号 | 怎么判 | 命中后 |
|---|---|---|
| S1 数量/量词 | 名字里出现「数字 + 量词」（15万两、五百匹、五口、一百两） | B 物资批次 |
| S2 消耗性 | 名字属调料/药材/毒药/矿石/火药类，正文有「抹/服/吃/用掉」 | B 消耗品 |
| S3 可回指 | 跨章能用「这/那/它/此物」指同一件 | A（必要条件） |
| S4 专属定语/序号 | 名字含「X的Y」「第二本」「半块」「黑金」「镇国」 | A（充分条件） |
| S5 非实体 | 官职、宗门、作坊、建筑、井、矿脉、阵法、占位指代、类别名 | C |
| S6 复数无序号 | 名字是单数，但正文说「总共九块」「三支」「几块」 | B 整类多实例 |

S1/S2/S5/S6 是名单匹配（闭集），S3/S4 是名字形态判断。**没有「数量超过 N 就归 B」这种阈值**——「15 万两」和「半块」都是看有没有量词/定语，不看数值大小。

**没有阈值。** 唯一带「数」的信号是 S1/S6，判的也是「有没有数量词/复数陈述」这个是否问题，不做比例或基数比较。这样做的代价是：名单没覆盖到的新名字会默认落 A（见 13.5）。

### 13.5 必须人工兜底的两个口子

A 组是默认桶，所以**漏判方向只有一个：该进 B 的进了 A**，后果是时间线被无意义段塞满。需要人工看的只有两处：

1. **单数名字其实是多份（S6）**。机器只能靠正文一句「总共九块」发现，名字本身看不出来。本轮命中 16 条（地书碎片 9 / 金步摇 4 / 玉佩 3）。
2. **裸类名 vs 具名件（S4）**。`册子` vs `第二本蓝皮书`、`卷宗` vs `周旻的账簿`，只差一个定语，但一个是批次一个是唯一物。本轮通用文书 13 条属于这一类。

兜底做法：跑完后人工扫一遍 A 组物品名，凡「看起来像批次」的抽查一句正文；新出现的名字在下一轮直接补进 B/C 名单，不进代码逻辑。

## 15. 灌库之后：五组样例能不能成线

先给结论：**112 条覆盖 50 个物品名，但只有 6 件真的有换手线，其余 44 件是单段。** 五组重点样例里 2 组灌完是空的、1 组只有封印态、2 组完整。

### 15.1 整体形态

| 项 | 数 | 说明 |
|---|---:|---|
| 转持有边 | 112 | — |
| 去重后物品（原始写法） | 50 | — |
| 有 ≥2 个不同持有者 | 8 | 军弩、半块玉佩、地书、屏蔽气息的法器、灵龙、玉石小镜、银枪、风水盘 |

### 15.2 五组逐组预判

| 组 | 灌完的样子 | 能不能用 |
|---|---|---|
| 地书 | `own`：地宗[73,74) → 天地会[74,∞)；`custody`：金莲师兄[73,74) → 许七安[74,∞) | **双线都立得住**，是唯一能演示 own/custody 分离的样例。前提是 ch74#7（权属转移）与 ch74#11（许七安接手）两条事件都在 |

| 封印物 | `own`：`sealed`[115,∞)，owner 为空 | 只有一段封印态。**不会出现 sealed→held**：没有解封事件，也没有任何一条 held 边 |
| 神剑 | **0 行** | 3 条 `owns` 全存疑、0 条转持有。不是「断在中间」，是**整条线不存在**；表里查不到「谁持有神剑」，只有 `located_at` 的 4 条（供奉地）留在关系表。另有 ch95/99/122/165 四章抽取里有 `神剑` 却没有边，是否抽漏未核 |
| 地书碎片 | **0 行** | 9 条全判错（九片分持）。连带 `三号碎片` 的 2 条存疑也没转，**整个碎片体系在表里是空的** |

### 15.3 直接回答那三个问题

1. **地书 own/custody 双线**：都能立，且互不覆盖。这是本轮唯一证明「own 是权属、custody 是在谁手上」的样例，建议作为灌库后的第一条验收用例。
2. **神剑会不会 `sealed→held→held` 断在中间**：不会，因为`sealed` 那条属于 `封印物`（ch115），不属于神剑。神剑没有任何 held 段，所以不存在「断」——是**整件物品在持有表里缺席**。`封印物` 也不会从 sealed 变 held（没有解封事件）。要修只能补神剑的持有动作句，3 条里至少成立 1 条。
3. **地书碎片会不会空**：会，完全空。而且不是「地书空了」——地书（整本）仍有 own/custody 双线；空的是**碎片节点**。要让碎片有行，必须先有副本维度（片号），否则 9 条永远转不进。

**判断**：如果验收标准是「五组都能看到线」，现在灌进去只能过 2 组（地书、玉石小镜），封印物算半组，神剑与地书碎片为空。**先补神剑 1 条持有句 + 碎片副本维度，再灌**，否则验收会在第 3、5 组直接失败。
