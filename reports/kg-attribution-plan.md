# 主宾绑定修复方案（R0–R9 已落地，306 章实测通过）

- 触发依据：918 章全量审计 61 条 mixed 人物关系，24 对 37 错（39.3% [28.1, 51.9]）；
  错误分类里「并列串位 5 + 挂错对象 25」= 30/37 = 81.1%。
- **状态**：R0–R9 已实现于 `backend/app/kg/generated_extract.py`，306 章对照实测
  precision 100%、recall 90.9%（见 §九）；四类硬拒有单测锁行为
  （`backend/tests/test_kg_attribution_gate.py`）。全量 918 章 61 → 20 行，未逐条复核。
- 下方 §一–§八 是落地前的推演，保留以便对照；实测以 §九 为准。
- 现状机制：canon 边 (a,b,rel) 是唯一候选来源，抽取器只做验证——
  [generated_extract.py](backend/app/kg/generated_extract.py#L340-L444)
  取同时含 a、b 的段落，交给
  [`_edge_trigger`](backend/app/kg/generated_extract.py#L279-L336)；
  方向由 canon 边固定，触发词只做支撑。真正的绑定在
  [`_pair_trigger`](backend/app/kg/generated_extract.py#L249-L263)：
  「a 在前、b 在后、相距 ≤24 字，触发词落在 a..b 之间或 b 之后 12 字内」。这个窗口不区分
  谁修饰谁，所以「同僚/并肩/联手/授业/教导/当差」会绑到相邻的第三人。

## 一、先把错误分成两层

| 层 | 定义 | 例子 | 句法规则能不能修 |
|---|---|---|---|
| A·canon 边错 | 这条 (a,b,rel) 本身端点或方向就不对 | ch304 许新年→许七安 `subordinate`；ch776 许七安→神殊 `mentor` | 只能**拒**，不能改；要恢复得回头审 canon 边 |
| B·句内绑定错 | canon 边可能为真，但这句话的触发词修饰的不是 a/b | ch103 朱广孝→李玉春 `同僚`；ch619 元景帝→怀庆 `教导` | 可以**拒**；若 (主语,宾语) 另有其人，可落 candidate 供人工改边 |

审计判据是「原句是否支撑这条有向关系」，所以两层在这里都算错。方案的第一步不是「修关系」，
而是**让输出只保留原句真正断言的那一对**；B 层丢掉的正确关系另走候选复核，不在抽取器里猜。

## 二、规则

### R0 解析单位：句 → 小句

按 `。！？；` 切句，再按 `，、` 切小句；引号（`“”「」『』`）单独一层，记录开闭位置。
所有规则只在**触发词所在小句**内取论元，跨小句必须有显式回指（「他/她/其」且能解）。

### R1 触发词定位

只在 `REL_TRIGGERS[rel]` 命中的小句里做归因；一句多个触发词时逐个候选，取端点能对上的那个。
触发词不在小句里、只在段尾 12 字内飘着 → 不认（现状 `b 之后 12 字` 这一条要取消）。

### R2 主语：按触发词类型分开定，不用一条规则包打

**动词类触发**（教导/授业/指点/联手/并肩/当差/投靠/麾下/下属/是X的人）：

1. 同小句内、触发词左侧最近的名词短语（专名优先，代词次之）；
2. 同小句没有，才回退到上一小句的句首主语；
3. 回退时若中间夹着另一个专名，**以那个专名为准，不再回退**（防止跨人绑定）；
4. 并列主语 `A 和/与 B + 相互性触发词`（联手/并肩/同僚/故交/好友/盟友）→ 语义上是 A-B 两条有向边；
   落库仍按现有 `SYMMETRIC_RELS` 存一条无序边（`direction_basis=symmetric`），
   查询层需要双向时再展开。存两条会让计数器、去重、极性审计重复计，不建议。
5. 并列主语 + 单向触发词（教导/授业/指点/麾下/下属/投靠）→ 只取句法主语（第一个并列项或「的」前项），
   不把 B 也当主语。

**名词类触发**（同僚/老师/下属/故交/好友/盟友/师父/弟子）：

1. `A 是 B 的 Y` → 主体 A，Y 的持有者 B；`B 的 Y 是 A` → 主体 A，持有者 B；
2. `A 和 B 是 Y` / `A、B、C 等 Y` → 名单内两两展开（对称关系）；
3. `A 和 B 的 Y` → Y 只属于 B（「的」左结合），A 不是 Y；
4. `他这位 Y` / `这位 Y` + 外部专名 → 绑定那个专名，不展开前面的并列；
5. 裸 `Y 们` / `诸位 Y` / 无指代的 `Y` → 只有能回指到唯一专名时才用，否则 candidate。

> 直接回答：不是「一律取左边最近专名」，也不是「一律取句首主语」。
> 动词类先取同小句左侧最近 NP，取不到才回退句首；名词类先看「是/的」结构，
> 左侧最近专名只在裸名词时兜底。两类混用是当前错误的主因之一。

### R3 宾语/对象：先看论元槽，再看距离

1. 介词框架优先：`对/向/给/为/与/和/跟/同 + NP` → 取介词宾语；
2. 否则取触发词右侧最近的名词短语，作为直接宾语；
3. 距离上限 8 字；超过 8 字或跨小句 → 不认；
4. 右侧是 `V 出/成 … 的 NP` → 取「的」后中心语（「教导出…许新年」）；
5. `被` 字句：`A 被 B V` → B 是施事、A 是受事；`把` 字句：`A 把 B V` → A 是施事、B 是受事；
6. `V 过 A，V 过 B、C` → 每个 V 各自绑定自己的宾语，A 不升格为主语。

> 直接回答：不是「右侧最近专名」一把梭。先看介词框架和「的」结构，再退回右侧直接宾语，
> 并且有 8 字上限。`联手/并肩` 这类相互性动词，`与/和` 的宾语是共同施事，不是受事。

### R4 端点硬校验（关键门）

算出 `(subject, object)` 后，必须与 canon 边 `(a, b)` 相等；对称关系允许 a/b 互换。
比较前先走 `normalize`（否则 legacy 的「长公主」与「怀庆」会被误判为不符）。
不相等 → **不产正式边**，落 `candidates`，`reason=endpoint_mismatch`，并附 `suggested_pair`。
这一条单独就能杀掉「挂错对象」25 条里的大部分，也是「精度只升不降」的来源。

### R5 否定/疑问/排除/假设

触发词所在小句出现以下任一项 → 拒（`reason=negated/question/hypothetical`）：

- 否定：`不/没/未/别/莫/岂/难道/并非/而不是/无法/未能`；
- 疑问：句末 `？/?`，或 `能…？/难道…？/岂…？` 反问；
- 排除：`除了…/除…外`（ch188「除了许七安…其余都是姜律中麾下」）；
- 假设：`如果/若是/要是/万一/假如/除非`；

**这四类一律硬拒（`HARD_REJECT_REASONS`），不进正式边、也不进 candidate。**
「拒绝」不等于「降级为候选」：候选只留给端点可疑、需要人工改边的情况；
语境本身不成立时，候选同样是噪声。

### R6 引语/转述

1. 引号内单独解析；`X 道/说/问/答/喊：“…”` → 引号内 `我=X`；
2. `你` = 上一处被称呼者或对话对象；`他/她` = 引号外最近同名/最近专名；
3. 三类代词只要有一个解不出 → 拒（`reason=unresolved_pronoun`），不猜；
4. `听说/据说/传言/声称/扬言/都说/传说/闻说/相传` → **硬拒**（`reason=reported`），
   不进正式边、也不进 candidate，除非同段叙述层另有断言。

> 直接回答：转述句（「他说 A 是 B 的老师」）不直接入正式边。说话人、受话人、第三人称
> 三者都解得出，才按引语内断言处理；解不出就落 candidate，不用「最近人名」硬顶。

### R7 并列名单串位

1. `V 过 A，V 过 B、C` → A 归第一个 V，B/C 归第二个 V，谁也不当谁的主语；
2. `A、B、C 等 Y` → Y 在名单内两两展开；
3. `A 和 B 的 Y` → 只 B 持有 Y；
4. `A 和 B 一起 V`（相互性 V）→ A-B 一对；单向 V → A 为主语、B 为伴随，不产 B→A。

### R8 方向校验（非对称关系）

`mentor/student/subordinate/superior/parent/child/family` 等：

- `A 是 B 的老师/师父/上级/下属/父亲` → 方向由句式定；
- `A 在 B 麾下/手下` → A subordinate B；
- 与 canon 边方向相反 → 拒（`reason=direction_conflict`），**不自动翻转**；翻转等于改 canon，
  需要单独审边，不能在抽取器里静默做。

### R9 兜底

代词、省略、跨段共指、名单里混入通名/头衔（银锣、白衣术士、道人）→ candidate，不产正式边。
所有被拒的行都保留 `reason` 与 `suggested_pair`，保证「不静默吞掉」。

## 三、每条规则会漏掉什么

| 规则 | 主要收益 | 代价/漏检 |
|---|---|---|
| R4 端点硬校验 | 杀掉挂错对象；精度单调不降 | canon 边端点本身错时也一并拒，召回下降；恢复需审边 |
| R5 否定/疑问 | 杀掉「能指点宋卿？」「并没有并肩」 | 四类硬拒不落 candidate，双重否定、反讽误杀后只能从 `rejected_edges` 找回 |
| R6 引语 | 杀掉转述换人 | 转述硬拒；说话人/代词解不出时，正确对话关系也会丢（ch127 依赖「许七安无奈道」） |
| R7 并列 | 修「教过元景帝，教过怀庆临安」 | `A 和 B，两位同僚` 这类同位语若判定错，会把正确对拆错；需要白名单测试锁行为 |
| R2 主语回退 | 保留跨小句的正确主语 | 跨小句回退最容易跨人；必须加「中间有别的专名就停」 |
| R3 8 字上限 | 防止跨小句乱绑 | 长定语（「A 的前任上级兼至交好友 B」这类长定语）会超限丢失 |
| R8 方向 | 修「监正老师」类反向 | 不翻转，所以只减不增；方向错的 canon 边仍留在库里 |
| R9 兜底 | 不猜、可复查 | candidate 表会变大，需要下游有消费方，否则等于没修 |

## 六、实施顺序与验收

1. **第一步（最小改动）**：R0/R1 小句化 + R5 否定/疑问 + R4 端点硬校验。
   先不动主语/宾语算法，只把「a、b 与触发词所在小句的主宾不一致」的行拒掉；
   这一步预计就能去掉大部分错误，且不新增边。
2. **第二步**：R2 主语 + R3 宾语（按触发词类型分支），补 R7 并列、R8 方向。
3. **第三步**：R6 引语/转述，把 candidate 的 `suggested_pair` 接出来，供人工改 canon 边。
4. **回归集**：61 条 mixed + 63 条 legacy 的金标准不删；每次改动同时跑 precision/recall/
   reason 分布，并与本文推演对照。306 基线只做历史对照，不再作为验收口径。
5. **测试用例**（每条锁一个行为）：
   - `宋廷风和朱广孝在一楼等着他这位同僚，见许七安下楼` → 宋→许保留，宋→朱拒；
   - `许七安和南宫倩柔是寻常的同僚关系` → 保留一对；
   - `太傅教过元景帝，教过怀庆临安` → 元→怀拒；
   - `能指点宋卿？` → 拒；
   - `怀庆和临安两位公主站在远处，并没有和许七安并肩` → 拒；
   - `许七安是魏渊的人` → 保留；`魏渊的下属是许七安` → 保留；
   - `许七安带着下属铜锣巡街` → 许→魏拒；
   - `许七安依旧在杨砚麾下` → 保留；
   - `监正老师` 类 → 方向与 canon 相反时拒，不翻转；
   - `许七安与同僚结伴…宋廷风跟过来` → candidate，不产正式边。

## 七、不做什么

- 不改 canon 边、不自动翻转方向、不新增 canon 之外的实体对；
- 不把 candidate 当正式边落库；
- 不为这 9 条错误写特例正则（否则只是把过拟合从窗口搬到规则）；
- 不引入 LLM 兜底（会破坏「零 LLM、可复算」的约束）。

## 八、一句话结论

现状错在「先有 canon 边，再在窗口里找触发词」，等于让触发词给一条已定的边背书；
应反过来：**先从触发词所在小句解出 (主语, 宾语)，再要求它与 canon 边相等，不等就拒。**
规则只做减法，所以不会新增错误边；代价是 24 条正确行里预计丢 3–5 条弱证据行。
**实测（§九）：306 章 precision 100%、recall 90.9%，9/9 错误救回、仅误伤 ch175 一条；
全量 918 章 61 → 20 行，逐条复核后 precision 80.0% [58.4, 91.9]、recall 66.7% [46.7, 82.0]，
4 条残余错边都在「关系名词·唯一指代」分支。**

## 十、4 条残余错边的分支追踪（只诊断，未改代码）

脚本：`experiments/2026-11-09-kg-shadow/probe_noun_branch.py`，把 §九 那 4 条的目标人物对

`holders` = 小句内触发词左侧的专名，`others` = 全句专名去掉 `holders`。

| 章 | 触发词所在小句 | `_APPELLATION` | `holders` | `others` | 实际走的分支 |
|---|---|---|---|---|---|
| ch66 | 「…许七安随着两位同僚」 | False | {许七安} | {李玉春} | 裸名词·唯一第三人 |
| ch68 | ch68 原句：吕青与两位同僚卸下包裹（叙述） | False | {吕青} | {许七安} | 裸名词·唯一第三人 |

四条**全部**走「裸名词·唯一第三人」这一支，没有一条进入同位语/并列分支——这才是根因：
`_APPELLATION` 用 `^` 锚在小句开头，而真实文本里「两位同僚」几乎从不落在小句首位
（ch66 前文另有一处第一人称群体称呼），于是所有带数量词的群体指代都漏到下一支。

### 10.1 两类成因（不是四种）

**成因一：群体指代被当成单人（ch66、ch68）**

- 「两位同僚」「三人」「众人」里有数量词，指的是**不具名的群体**，语义上根本不存在
  「唯一第三人」。
- 规则没有识别数量词，把句里唯一另一个具名角色当成了指代对象；而那个角色在句法上
  处于别的角色：ch66 的「李玉春」是「李玉春的办公室」的**领属定语**，ch68 的「许七安」
  是下一小句「分发给许七安三人」的**受事**。
- 所以这类错不是「指代解错」，而是**在不该启用唯一指代的地方启用了它**。

**成因二：`holders` 已有两人，仍走唯一指代（ch495、ch806）**

- ch495「X 是 Y 的好友」结构里，`holders` 同时含 X（梁有平，被描述者）与 Y（李妙真，
  关系持有者），真正的第二方是 X；规则却把句里剩下的唯一专名（杨川南，后一小句的揪人者）
  当第二方。
- ch806「A 和 B 是 Y」更是 `holders` 已经完整给出了关系双方（许七安、南宫倩柔），
  此时「第三个名字」只是跨小句的旁证人物。
- 共同缺陷：唯一第三人规则只用 `others == 1` 当先决条件，**没有约束 `holders` 的人数**，
  也没要求该第三人处于触发词右侧的谓语宾语位置。

### 10.2 规则方案（R10–R13，尚未实现）

在原 R7 之后插入四条，都是**减法**，不新增边：

- **R10 数量词先否决**：触发词前 6 字内出现 `两位|二位|三人|几人|数名|一群|一众|众人|
  等人|诸位|各位`，该名词短语判为群体，直接 `endpoint_mismatch`；不进入唯一指代。
- **R11 排除领属/受事位**：候选第三人若形如「X的…」（X 是被判专名）或出现在
  「分发给/交给/告诉 X」这类受事框架内，不算被指代对象。
- **R12 唯一指代收紧为三条件**：`holders` 恰 1 人 + `others` 恰 1 人 + 该第三人位于
  触发词右侧 6 字内的谓语名词位（「他的同僚」「老王的好友」）。任一不满足即拒。
  ch495（holders=2）、ch806（holders=2）由此直接出局。
- **R13 并列优先判定**：小句同时含「A 和/与 B」且后接「是…关系/同僚/好友/师徒」时，
  只按并列名单判，名单里没有 canon 端点就拒。ch806 会被这一条判成「许-南宫」而拒掉
  宋廷风的边。

**预期影响**：这 4 行全部转拒 → 输出 20 → 16 行，precision 16/16（Wilson [79.4, 100]），
recall 仍 16/24 = 66.7%。即「用 4 条覆盖换 80% → 100% 精度」，代价是丢掉 4 条本来也没说对的边。
真正的密度缺口靠 §3 那条线（生成层信号确认）补，不靠名词分支。
