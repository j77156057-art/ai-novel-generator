# 长文本摘要的证据强制与可自动判的验收

## 什么时候用

- 要把一整本书 / 一整批语料压成**结构化摘要**（时间线 / 角色 / 事件 / 摘要条目）并落库；
- 要让「摘要有没有把主线压丢」变成**能自动判**的问题，而不是靠人读一遍；
- 要决定「整本一次投喂」还是「切块抽 + 合并」；
- 要把摘要**接进上下文 / 检索 / 对话**，担心剧透与污染；
- 要做「同一份输入重复提交要不要重算」这类**幂等与花费**的判断。

## 先认清一件事：摘要最危险的失败模式不是「压得不够狠」

是**看起来很像摘要的编造**。

时间线读起来顺、角色读起来像那么回事、事件有因果 ——
但那些事在原文里根本不存在。摘要压缩了一本书，模型「顺手」补几个过渡事件太自然了。

⇒ 所以摘要的第一纪律不是「压得狠」，是**每一条都站得住**。

## 一、证据强制：站不住证据的条目**直接丢弃** —— 但先试着**修指针**

### 判据（可机检）

每条摘要必须挂证据：**位置（章号/偏移）+ 原文逐字片段**。校验顺序：

1. 引文**逐字**出现在它声称的那一章里 ⇒ 成立（允许尾部被模型截断 ⇒ 前缀命中即可，
   否则模型每改一个标点你就丢一条真条目）；
2. 引文**逐字在书里、只是挂错了章** ⇒ **在邻近章节里重新归属**（改章号，留条目）；
3. 引文在书里但**离得太远**（超出归属窗口）⇒ 丢弃，记 `quote_far`；
4. 引文**压根不是书里的话** ⇒ 丢弃，记 `quote_not_found`（这才是编造）；
5. 引文太短 ⇒ 只有**短到无法定位**才丢（门槛 3 字即可）。

### 为什么第 2 条是「重新归属」而不是「丢弃」（2026-11-02 真跑实测）

真跑时被丢的 34 条**逐条回查原文**后发现：**全部**是
「引文逐字就在书里，只是章号挂了」（偏移多为 ±1）。

⇒ **引文是证据，章号只是指针**。指针错了应该修指针；
把证据一起扔掉等于「因为目录页码错了，就说这本书没写过这段」。

⇒ 只有「书里压根没有这句话」才判编造。丢弃时**必须记原因**
（`quote_not_found` / `quote_far` / `quote_too_short` / `no_evidence` …）
—— 只报一个比例的话，人没法判断该怪模型还是在怪匹配规则，
而这两种处置完全相反。

### 引文长度门槛按「能不能定位」判，不按「多长」判

真跑丢的 31 条里 **25 条是「引文太短」误杀**，而那些短引文确实逐字出现在它声称的章里。
⇒ 证据的强度取决于**能不能定位到那一章**，不取决于引文多长。

配套：提示词要求**原样复制、8~25 字**（长引文错一个标点就废，短引文错的机会小得多）
⇒ 真跑丢弃率 33.3% → 13.9%。

### 为什么是「丢弃」而不是「标注存疑」

标着「存疑」的条目**照样会被模型读进上下文、照样被当成事实** ——
标注只是给人看的，模型不看。

⇒ 没证据的条目**不进摘要**。

### 成片缺失 ⇒ 整次失败

单条缺失正常（模型把引文写错了）；**成片**缺失说明模型在编，
这时摘要的其它部分也不能信 ⇒ 缺失率超阈值整次判失败。

## 二、验收怎么定（都要能自动判）

| 项 | 判据 | 坑 |
|---|---|---|
| **压缩比** | `输出字数 ≤ max(输入/目标比, 最小体量)` | **必须有下限**：一千字的书压成 100 字不是压缩，是**把内容删了**。10:1 是给几十万字的书定的目标 |
| **主线覆盖** | 候选事件与摘要的覆盖比例（候选 = 「涉及主要角色的事」） | 候选集的**定义**决定闸门有没有判别力：按「动作动词 + 长度」抽出来的是风景句与对话碎片，不是主线 |
| **角色覆盖** | 高频角色名出现在**渲染文本**里的比例 | 要扫**渲染文本**而不是结构化条目 —— 只出现在「关系」里的人（relations 是 list 不是 str）在结构化条目里扫不到 |
| **证据留存** | 保留条数 / 总条数（并按原因分开记） | 成片缺失 ⇒ 模型在编 ⇒ 整次失败 |

### 角色候选**不要用 PMI 高频词**

真跑实测：PMI 取出来的是「主角的姓、主角的名、什么、自己、没有、怎么、知道、起来」——
**碎片 + 虚词**。拿这 20 个当分母，一个写得很好的摘要也会被判不达标（实测 0.65）
⇒ 闸门没有判别力。

⇒ 复用仓库既有的判据（**不另写一套**）：人名抽取信号（名字 + 说话动词 / 句首主语位）
→ 形态过滤 → **语料自证的碎片归一**（两字碎片只被某个全名支撑 ⇒ 归一或丢弃）
→ **碎片补全**（向前补尾字，失败再向后补首字）→ 伪角色清洗（虚词黑名单）。
全程纯统计、零模型调用。

### 候选集是**启发式**的，不是真值

「主线覆盖」的分母只能从原文启发式抽 ⇒ 它的用途是**当闸门**
（摘要把主线压丢了要能被挡住），**不是当标准答案**。
⇒ 文档里要写清这个局限，别假装它是真值。

### 检查项要**三态**：`通过 / 不通过 / 不适用`

`ok = null` 表示「这一项没有候选、根本没跑」——
**不算通过**（界面上单列一行「不适用」，别混进通过里）。
把「没跑」显示成「通过」是最容易骗过自己的那种 bug。

## 三、闸门必须有**判别力**（阳性对照）

一个永远 FAIL 的闸门等于没有闸门；一个永远 PASS 的闸门更糟。

⇒ 每条「达标型」判据都要配一条**反向用例**：

- 压缩比：把摘要条目复制到撑破上限 ⇒ `compression.ok` 必须变 False；
- 覆盖：故意漏掉角色的摘要 ⇒ 覆盖必须掉到阈值以下；
- 证据：整份编造的摘要 ⇒ 必须被清空。

**验证脚本第一次跑就抓出三个真问题**（都是判据定义错，不是阈值松紧）：

1. 压缩比在小书上不可达 ⇒ 加**下限**；
2. 主线覆盖对改写太苛刻 ⇒ 改用**词组重合**；
3. 角色覆盖漏了关系里的人 ⇒ 改扫**渲染文本**。

⇒ 这三条都不是「把阈值调松」解决的。**闸门红了先改判据的定义，再谈阈值。**

### 阈值要按**真书的实测分布**重校准（先改定义，再定数）

判据定义改对之后，在真书上跑几次，把好摘要与阳性对照的分布量出来再定阈值：

- 阈值取在好摘要分布的**下沿之下**（否则一半正常产物会被误杀）；
- 同时必须**离阳性对照足够远**（否则闸门没判别力）；
- 校准完把阳性对照钉进验证脚本，别让它以后悄悄失效。

⚠️ 在几百字的合成语料上定的阈值，搬到真书上**必然**要重校 —— 这是同一条经验：
**尺子必须跟着被量的对象换**。

## 四、整本一次投喂 vs 切块抽

**要「全」的产物用大块；要「精」的产物用小块** —— 两者对上下文的需求相反。

- **摘要**（写了什么）要**全** ⇒ 整本一次投喂：模型自己看全局，
  才答得出「第 3 章和第 500 章的关系变化」这种跨章问题（切块做不到）；
- **规则**（怎么写）要**精** ⇒ 小块：块大了每维候选池变小（实测 20 万字/块 ⇒ 每维候选 8 条，
  下游要选 5 条 ⇒ 多样性归零）。

### 档位自动选择的判据：**跟随渠道声明的上下文上限**

`书的大小 ≤ 渠道声明的单次上限` ∧ `渠道声明过上限` ⇒ 整本；否则切块。

⚠️ **渠道没声明就当它吃不下**。理由：假设错了的后果是
「请求发出去了、回来被截断、我们以为压缩成功了」。

⚠️ **别写死一个门槛数字**。写死的门槛在真书上可能**永远不可达**
（真书的最小体量往往比「几百字的合成语料」大一个量级），
于是这条路径等于不存在，而它是摘要相对切块抽的全部意义。

⇒ 能力声明写在 **provider 层**（`max_context_chars`），不是散在调用点；
另加一道与渠道无关的**绝对天花板**兜住渠道误配。
「能收下」与「该用满」是两个值，别混（后者是产出质量问题，不是上下文问题）。

### 切块档的合并要**确定性**

合并**不调模型**：只做拼接、去重、排序。
合并本身是一次「无中生有」的机会 —— 模型改写条目时会丢证据或造新条目。

### 切块档的条目上限要按**块**算

按整本书算 ⇒ 每个 5 万字的块都被要求给 200 条时间线，
而块里根本没有那么多内容 ⇒ 模型硬凑（编）或撞输出预算（截断）。
⇒ 合并之后再按整本裁。

## 五、摘要接进上下文的三条纪律

1. **只在「参考书就是用户正在读/续的那本」的路径下注入**。
   摘要里是**剧情**，塞进「参考书只是写法参考」的路径 ⇒ 模型会照着参考书的剧情写。
   （与「证据引文里的专名泄漏导致复读参考小说」是同一类事故。）
2. **可见边界必须 respected（fail closed）**：没设边界 = 整本不可见；
   挂不上位置的条目**也不放行**（放行等于「一个不知道来自哪一章的内容进了上下文」）。
3. **有界**：摘要可能几万字，进提示词必须有预算；截断了多少要**如实说**。

⚠️ 注意 **fail closed 的口径要按用途分**：
防剧透的链路（角色聊天）没边界就整本挡掉；
**学写法**的链路（蒸馏）没边界就整本照蒸 —— 搬错口径会让老项目直接空掉。

## 六、同一个坑的第 N 次出现：**换了输入却拿到旧结果**

摘要的失效键要带**语料正文哈希**（重新导入/清洗规则升级后正文变了 ⇒ 旧摘要失效）。
这与「档位 / 块大小 / 提炼版本进指纹」是**同一类坑**：
换了输入、产出必然变，而缓存键没变 ⇒ 界面显示「秒级完成」，用户拿到旧结果。

⇒ 凡是「用户能改的输入」，都要问一句：**它进指纹了吗？**
（摘要这里：**档位**与**压缩比目标**都是用户能改的 ⇒ 必须进复用键，
否则「改了参数再跑」会被静默复用成旧产物，而界面上看不出任何异常。）

## 七、幂等：**复用判定必须发生在花钱之前**

「先调模型抽一遍，再看要不要复用」这个顺序是**错的**：
于是任务状态里那句「命中已有摘要，未重新抽取」是**假的** ——
模型跑完了、额度花了，只是产物没保存。重复提交一次就白烧一次全本的额度。

⇒ 两步：

1. **先算「计划」**（纯本地计算，不调模型）：正文体量、有效档位、条目上限、压缩比目标；
2. 用 `(正文哈希, 产物版本, 有效档位, 压缩比目标)` 当**复用键**比对，命中就直接返回。

⚠️ 复用键少一项 = 一次静默的错误复用（用户改了参数却拿到旧结果）。
⚠️ 「最新那条」不等于「对得上那条」：同一本书被导入过两个版本时库里会有多条 active 行，
按 id 取最新会取错 ⇒ 按 `(书, 正文哈希, 产物版本, active)` 捞候选再逐条比对。

实测：同一本书同一参数，重算 81.4 秒 → 复用 2.0 秒，**零模型调用**。

## 八、这个 skill 覆盖不到的

- **切块档仍未真跑过**：真跑只覆盖了「整本一次投喂」这一档。
  切块抽 + 合并要一本书超过渠道上下文上限才能触发（百万字以上）。
- **摘要的条数由模型自己定**：同一本书、同一套参数，两次真跑给出 26 条与 113 条（都过闸门）。
  ⇒ 闸门管的是**质量**（覆盖率 / 证据），不是**体量**；
  把摘要塞进上下文时**不能假设长度稳定**。
- **语义级覆盖判定**：现在用词组重合，会漏判「换了同义词的重述」。
  想更准就得把模型请回闸门里 —— 那时闸门就有可能自己给自己放水。
- **真跑的副产物**：摘要产物里含**原文片段**，属于运行态，入库即泄露 ⇒ 必须在忽略规则里。
