# 长文本摘要的证据强制与可自动判的验收

## 什么时候用

- 要把一整本书 / 一整批语料压成**结构化摘要**（时间线 / 角色 / 事件 / 摘要条目）并落库；
- 要让「摘要有没有把主线压丢」变成**能自动判**的问题，而不是靠人读一遍；
- 要决定「整本一次投喂」还是「切块抽 + 合并」；
- 要把摘要**接进上下文 / 检索 / 对话**，担心剧透与污染。

## 先认清一件事：摘要最危险的失败模式不是「压得不够狠」

是**看起来很像摘要的编造**。

时间线读起来顺、角色读起来像那么回事、事件有因果 ——
但那些事在原文里根本不存在。摘要压缩了一本书，模型「顺手」补几个过渡事件太自然了。

⇒ 所以摘要的第一纪律不是「压得狠」，是**每一条都站得住**。

## 一、证据强制：没证据的条目**直接丢弃**

### 判据（可机检）

每条摘要必须挂证据：**章号/位置 + 原文逐字片段**。
校验：

1. 引文**逐字**出现在它声称的那一章里（允许尾部被模型截断 ⇒ 前缀命中即可，
   否则模型每改一个标点你就丢一条真条目）；
2. 引文挂在**错的**章上 ⇒ 同样丢弃（归属错了就是编）。

### 为什么是「丢弃」而不是「标注存疑」

标着「存疑」的条目**照样会被模型读进上下文、照样被当成事实** ——
标注只是给人看的，模型不看。

⇒ 没证据的条目**不进摘要**。

### 成片缺失 ⇒ 整次失败

单条缺失正常（模型把引文写错了）；**成片**缺失说明模型在编，
这时摘要的其它部分也不能信 ⇒ 缺失率超阈值（20%）整次判失败。

## 二、三项验收怎么定（都要能自动判）

| 项 | 判据 | 坑 |
|---|---|---|
| **压缩比** | `输出字数 ≤ max(输入/目标比, 最小体量)` | **必须有下限**：一千字的书压成 100 字不是压缩，是**把内容删了**。10:1 是给几十万字的书定的目标 |
| **主线覆盖** | 候选事件与摘要共享 **≥ 2 个「有区分度的 2-gram」** | 逐字比对**必漏判**（摘要是改写）；「角色名 + 动作动词」也太苛刻（改写后动词就换了）。2-gram 词组重合是折中 |
| **角色覆盖** | 高频角色名出现在**渲染文本**里的比例 | 要扫**渲染文本**而不是结构化条目 —— 只出现在「关系」里的人（relations 是 list 不是 str）在结构化条目里扫不到 |
| **证据缺失率** | 丢弃条数 / 总条数 | 成片缺失 ⇒ 模型在编 ⇒ 整次失败 |

### 候选集是**启发式**的，不是真值

「主线覆盖」的分母只能从原文启发式抽（像一件事的句子：动作动词 + 长度适中 + 每章至多一条），
按章**均匀**取样保证覆盖全书。

它的用途是**当闸门**（摘要把主线压丢了要能被挡住），**不是当标准答案**。
⇒ 文档里要写清这个局限，别假装它是真值。

### 有区分度怎么定

2-gram 在原文里到处都有的（df 超过句数的 10%）⇒ 套话，不算证据。

## 三、闸门必须有**判别力**（阳性对照）

一个永远 FAIL 的闸门等于没有闸门；一个永远 PASS 的闸门更糟。

⇒ 每条「达标型」判据都要配一条**反向用例**：

- 压缩比：把摘要条目复制到撑破上限 ⇒ `compression.ok` 必须变 False；
- 覆盖：故意漏掉角色的摘要 ⇒ 覆盖必须掉到阈值以下；
- 证据：整份编造的摘要 ⇒ 必须被清空。

**验证脚本第一次跑就抓出三个真问题**（都是判据定义错，不是阈值松紧）：

1. 压缩比在小书上不可达 ⇒ 加**下限**；
2. 主线覆盖对改写太苛刻 ⇒ 改用**词组重合**；
3. 角色覆盖漏了关系里的人 ⇒ 改扫**渲染文本**。

⇒ 这三条都不是「把阈值调松」解决的。**闸门红了先改判据的定义，再谈阈值。**

## 四、整本一次投喂 vs 切块抽

**要「全」的产物用大块；要「精」的产物用小块** —— 两者对上下文的需求相反。

- **摘要**（写了什么）要**全** ⇒ 整本一次投喂：模型自己看全局，
  才答得出「第 3 章和第 500 章的关系变化」这种跨章问题（切块做不到）；
- **规则**（怎么写）要**精** ⇒ 小块：块大了每维候选池变小（实测 20 万字/块 ⇒ 每维候选 8 条，
  下游要选 5 条 ⇒ 多样性归零）。

### 档位自动选择的判据

**书的大小 ≤ 门槛** ∧ **渠道声明过单次能读多少字** ⇒ 整本；否则切块。

⚠️ **渠道没声明就当它吃不下**。理由：假设错了的后果是
「请求发出去了、回来被截断、我们以为压缩成功了」。

⇒ 能力声明写在 **provider 层**（`max_context_chars`），不是散在调用点；
「能收下」与「该用满」是两个值，别混（后者是产出质量问题，不是上下文问题）。

### 切块档的合并要**确定性**

合并**不调模型**：只做拼接、去重、排序。
合并本身是一次「无中生有」的机会 —— 模型改写条目时会丢证据或造新条目。

## 五、摘要接进上下文的三条纪律

1. **只在「参考书就是用户正在读/续的那本」的路径下注入**。
   摘要里是**剧情**，塞进「参考书只是写法参考」的路径 ⇒ 模型会照着参考书的剧情写。
   （与「证据引文里的专名泄漏导致复读参考小说」是同一类事故。）
2. **可见边界必须 respected（fail closed）**：没设边界 = 整本不可见；
   挂不上位置的条目**也不放行**（放行等于「一个不知道来自哪一章的内容进了上下文」）。
3. **有界**：摘要可能几万字，进提示词必须有预算；截断了多少要**如实说**。

⚠️ 注意 **fail closed 的口径要按用途分**：
防剧透的链路（角色聊天）没边界就整本挡掉；
**学写法**的链路（蒸馏）没边界就整本照蒸 —— 搬错口径会让老项目直接空掉。

## 六、同一个坑的第 N 次出现：**换了输入却拿到旧结果**

摘要的失效键要带**语料正文哈希**（重新导入/清洗规则升级后正文变了 ⇒ 旧摘要失效）。
这与「档位 / 块大小 / 提炼版本进指纹」是**同一类坑**：
换了输入、产出必然变，而缓存键没变 ⇒ 界面显示「秒级完成」，用户拿到旧结果。

⇒ 凡是「用户能改的输入」，都要问一句：**它进指纹了吗？**

## 七、这个 skill 覆盖不到的

- **真跑**：本方法在离线测试与验证脚本上成立，**没有在真书上真跑过**。
  真跑前要先确认渠道的**输出预算**够不够 ——
  摘要的输出体量由**结构化条目数**决定，与上下文上限是两回事。
- **语义级覆盖判定**：现在用词组重合，会漏判「换了同义词的重述」。
  想更准就得把模型请回闸门里 —— 那时闸门就有可能自己给自己放水。
